## Day 1：Port、TCP 与 UDP

**新概念：** Port、TCP、UDP

**总时长：** 55 分钟

### 今日目标

- 理解 IP 地址定位到「设备」，端口定位到「设备上的服务」。
- 知道 TCP 和 UDP 的核心差别，以及各自适合什么场景。
- 能读懂 `IP:Port` 这样的写法。

### 学习（25 分钟）

上周你知道 IP 地址能定位一台设备。但一台 NAS 上同时跑着文件共享、影音服务、管理界面 —— **数据送到设备之后，怎么知道该交给哪个服务？**

答案是端口。

```text
IP 地址      →  送到哪台设备
端口（Port） →  送到设备上的哪个服务
```

地址写成 `IP:Port` 的形式：

```text
192.168.1.10:8096
     ↑         ↑
   设备地址   服务端口
```

用公寓楼类比：

```text
小区地址（IP）  →  定位到哪栋楼
房间号（Port）  →  定位到楼里的哪一户
```

然后区分两种传输方式：

```text
TCP  →  可靠，保证数据完整到达，用于网页、文件传输
UDP  →  快速，不保证送达，用于实时音视频、游戏
```

打个比方：TCP 像挂号信（要有签收确认），UDP 像喊话（说完就算，没听见就没了，但快）。

本周只需知道两者存在，以及「为什么有的应用选 TCP、有的选 UDP」。

- 回答：为什么光有 IP 地址不够，还需要端口？
- 回答：TCP 和 UDP 各自的取舍是什么？

## Day 2：NAT 与端口转发

**新概念：** NAT、Port Forwarding

**总时长：** 55 分钟

### 今日目标

- 理解 NAT 解决「多台设备共用一个公网地址」的问题。
- 画出公网请求被转发到内网 NAS 的完整路径。
- 知道端口转发的工作原理，以及它带来的安全风险。

### 学习（25 分钟）

**NAT（网络地址转换）** 解决上周留下的问题：家里十几台设备都只有私有地址，怎么共用路由器那一个公网地址上网？

```text
手机   192.168.1.11  ┐
电脑   192.168.1.12  ├──→ 路由器（NAT）──→ 公网地址 ──→ 互联网
NAS    192.168.1.10  ┘
```

路由器做的事情：

1. 内部设备要访问外网时，把「来源」改写成自己的公网地址。
2. 记住这条连接是哪台内部设备发起的。
3. 外部回应回来时，再按记录转交给正确的设备。

**关键点：NAT 让「内部主动出去」很顺畅，但「外部主动进来」默认不通。** 因为路由器不知道外部请求要找内部哪台设备 —— 这正是上周「出门访问不了」的机制层面的原因。

**端口转发（Port Forwarding）** 就是人为地开一个口子：

```text
外部访问 → 公网地址:某端口 → 转发给 → 192.168.1.10:服务端口
```

它让外部能进来，但代价是：**那个端口从此对全世界开放**。任何人在互联网上都能扫描到并尝试连接。

本周先把机制讲清，Day 4 再讨论它的取舍和替代方案。

- 回答：为什么默认情况下外部访问不进来？
- 回答：端口转发做的事情是什么？代价是什么？

## Day 3：DDNS 与防火墙

**新概念：** DDNS、Firewall

**总时长：** 55 分钟

### 今日目标

- 理解 DDNS 解决「公网地址会变」的问题。
- 理解防火墙解决「谁能进入」的问题。
- 分清这两个问题不能互相替代。

### 学习（25 分钟）

**DDNS（动态域名解析）**

上周知道公网地址可能变化。如果你想从外面访问家里，就需要一个不变的入口 —— DDNS 解决的就是这件事：

```text
IP 经常变  +  你记不住数字  →  用一个固定的域名指向它
```

做法是运行一个程序，检测到公网地址变化时，自动更新域名解析记录。这样你始终用同一个域名访问，不用管背后的地址是什么。

用类比：**DDNS 像是在你经常搬家的情况下，给你一个永久的邮箱地址** —— 别人只管往这个地址寄信，你在后台更新实际住址。

**防火墙（Firewall）**

防火墙解决的是另一个问题：**决定谁能进入、谁被拒绝。**

```text
DDNS   →  解决「地址会变」，让你找得到
防火墙  →  解决「谁能进入」，决定放不放行
```

**这两个问题最容易混淆**：DDNS 让外部找得到你家，但**找到了不等于进得来** —— 防火墙才是决定放行的关卡。

这是本周很重要的一条区分：**「能找到」和「能进入」是两件事。**

- 回答：为什么说「能找到」不等于「能进入」？

## Day 4：VPN、WireGuard 与 Tailscale

**新概念：** VPN、WireGuard、Tailscale、P2P Remote Access

**总时长：** 55 分钟

### 今日目标

- 理解 VPN 的核心思路：不是「开门」，而是「把你接进内网」。
- 从原理上比较端口转发和 VPN 两种思路的差别。
- 理解 Tailscale 这类方案为什么能简化远程访问。

### 学习（25 分钟）

先明确一个问题：**端口转发的思路是「把服务暴露出去」，VPN 的思路是「让你进入内网」。**

```text
思路 A：端口转发
  把 NAS 的某个端口对全世界开放
  → 任何人在互联网上都能尝试连接它

思路 B：VPN
  在你的设备和家庭网络之间建立一条加密通道
  → 效果相当于「你人在家里」，但通道是私密的
```

**VPN（虚拟专用网络）** 的本质是：让你的设备**看起来像是处在另一个网络里**。

用类比：

```text
端口转发  →  在自家墙上开个洞，谁都能伸手进来摸
VPN      →  修一条只有你能走的秘密通道，从外面直接走进家里
```

**WireGuard** 是一种现代的 VPN 协议，特点是配置相对简单、性能好。

**Tailscale** 建立在 WireGuard 之上，进一步简化了配置。它解决的核心痛点是：**传统 VPN 需要自己处理地址、密钥、端口转发这一整套麻烦事。**

Tailscale 的做法：

1. 每台设备装一个客户端，登录同一个账号。
2. 设备之间自动建立加密连接（借助协调服务器交换信息）。
3. 之后这些设备就像处在一个虚拟的私有网络里 —— 不论它们实际在哪里。

**为什么这对家庭用户意义重大？** 因为它让「出门访问 NAS」变得安全且简单：不需要在路由器上开任何端口，不需要固定的公网地址，也不需要懂太多网络知识。

（Tailscale 属于 P2P 远程访问方案的一种：设备之间尽可能直接建立连接，而不是所有流量都绕经中心服务器。）

### 学习（20 分钟）

把第 4 周和第 5 周的内容串起来，回答那个核心问题：

```text
为什么在家能访问，出门却不能？

在家：
  手机和 NAS 在同一个 LAN
  → 数据不出门，直接转发到达        ✓

出门：
  手机在另一个网络
  → NAS 只有私有地址，互联网不转发
  → 路由器默认不接受外部主动连接      ✗
```

然后给出两条解决路径：

```text
路径 A：端口转发（把服务暴露出去）
  需要：公网地址（可能还要 DDNS）+ 路由器上开端口
  风险：该端口对全世界开放，会被持续扫描
  适用：明确知道风险、且有额外加固措施的场景

路径 B：VPN / Tailscale（把设备接进内网）
  需要：两端装客户端
  风险：服务本身不暴露，只有你自己的设备能进来
  适用：绝大多数家用场景的推荐方案
```

**本周的核心判断：优先选「建立私有通道」，而不是「把服务暴露到公网」。**

一个实用的自检问题：

> 如果我开了这个端口，互联网上有多少人能尝试连接我的设备？
>
> 答案通常是「所有人」。这就是为什么默认要选路径 B。
