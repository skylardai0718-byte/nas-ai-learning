## Day 1：Linux、发行版与自托管的关系

**新概念：** Linux、Distribution、Debian、Ubuntu

**总时长：** 55 分钟

### 今日目标

- 理解 Linux 是内核，而发行版是「内核 + 一套软件和包管理」的完整系统。
- 知道 Debian 和 Ubuntu 的关系，以及它们为什么在自托管里常见。
- 理解「Linux 是一个家族，不是一个具体产品」。

### 学习（25 分钟）

先说结论：**Linux 严格来说是内核（Kernel），但你日常说的「Linux」通常指发行版（Distribution）。**

```text
Linux 内核（Kernel）
  └── 负责最底层的事：管理 CPU、内存、磁盘、网络

发行版（Distribution）= 内核 + 工具 + 包管理 + 安装程序
  ├── Debian
  ├── Ubuntu（基于 Debian）
  ├── Fedora
  └── ...
```

这就像「发动机」和「整车」的区别：发动机是核心，但你不能只买一台发动机开回家 —— 你买的是整台车，里面有发动机、变速箱、座椅和仪表盘。**发行版就是那台整车。**

**Debian** 是一个历史很长的发行版，以稳定著称，更新保守。**Ubuntu** 基于 Debian 构建，做了更多面向普通用户的打磨和更快的更新节奏。

自托管场景里经常看到它们，原因很实际：

- 软件生态成熟，你要装的服务器软件通常都有现成的安装方式。
- 稳定版不频繁变动，适合「装好就一直跑」的设备。
- 大量教程和文档默认环境就是这一类系统。

**但要记住边界：** 发行版之间的命令**不完全通用**。同一个操作在不同发行版上可能是不同的命令或不同的包管理器。看到一份教程时，先确认它针对的是哪个发行版，而不是照抄。

## Day 2：Shell、终端与 SSH

**新概念：** Shell、Terminal、SSH

**总时长：** 55 分钟

### 今日目标

- 分清 Terminal、Shell、命令三者各自是什么。
- 理解 SSH 让你在另一台电脑上操作 NAS 的过程。
- 能画出「电脑 → 网络 → NAS → Shell → 命令执行」的路径。

### 学习（25 分钟）

三个词经常被混着用，先分清：

```text
Terminal（终端）  →  一个窗口，你在这里打字、看输出
Shell            →  真正读懂你输入、并去执行的程序
命令（Command）   →  你敲进去的那一行字
```

用类比：**Terminal 是电话听筒，Shell 是电话那头的人，命令是你说的那句话。** 听筒本身不会做事，它只是让你和对方沟通。

你在终端里输入的其实是给 Shell 的指令，Shell 负责解释它、调用系统去执行、再把结果打印回来。

**SSH（Secure Shell）** 解决的是另一个问题：**怎么在另一台电脑上，打开一个属于自己的终端。**

```text
你的电脑  ──SSH（加密连接）──→  NAS
   │                              │
 终端窗口                      Shell 在 NAS 上运行
                                   │
                            你敲的命令在这里执行
```

关键点在于：**命令根本不在你的电脑上执行，而是在 NAS 上执行。** 你的电脑只负责显示和输入。所以你看到的内容，是 NAS 上的真实情况。

SSH 有两个必须记住的边界：

- **登录需要凭据** —— 用户名加密码，或者更安全的密钥。凭据不是你自己的私人信息可以随便记录的，笔记里不要写。
- **登录后的身份决定了你能做什么** —— 用哪个用户登进去，就带着那个用户的权限。这一点是 Day 3 的主题。

### 复述（12 分钟）

- 分别说明 Terminal、Shell、命令是什么。
- 回答：用 SSH 时，你敲的命令在哪里执行？
- 回答：SSH 为什么要加密？

### 测试（13 分钟，不给答案）

1. Terminal 和 Shell 分别是什么？
2. 判断：用 SSH 连接 NAS 后，命令是在你本地电脑上执行的。
3. 判断：SSH 连接是明文的，所以不能用来传密码。

## Day 3：用户、root 与权限

**新概念：** User、root、sudo、Permission；`pwd`、`ls`、`cd`

**总时长：** 55 分钟

### 今日目标

- 理解为什么系统需要区分用户，而不是人人都能改一切。
- 理解 root 和 sudo 的关系，以及为什么不应长期使用 root。
- 会用 `pwd`、`ls`、`cd` 确认自己在哪里、有什么。

### 学习（25 分钟）

**多用户**不是笔记本电脑时代才有的概念 —— Linux 从设计之初就是多用户系统：一台机器可以同时有很多用户，每人有自己的文件，别人的文件默认动不了。

```text
User（用户）      →  一个身份，带着一套权限
root             →  超级用户，几乎不受限制
sudo             →  临时借一下 root 的权限，做一件事
Permission       →  谁可以对哪个文件做什么
```

**为什么需要 root？** 因为有些操作影响全局：装系统级软件、改网络设置、动其他用户的文件。如果每个用户都能做这些，一个人误操作就能毁掉整台机器。

**root 的危险不在于它是坏的，而在于它没有安全网。** 普通用户想删系统文件，系统通常会拦一下；root 不会。你让它做什么，它就做什么。

所以正确姿势是：**平时用普通用户，需要时用 `sudo` 临时提权。**

```text
✗  一直用 root 登录  →  每个命令都是满权限，一次手误就可能造成不可撤销的后果
✓  用普通用户 + sudo →  权限只在那一件事上临时放大
```

`sudo` 也不是万能钥匙 —— 它要求你的用户在授权名单里，而且通常要再输一次密码。**加 `sudo` 只是「以管理员身份做这件事」，它不会帮你判断这件事该不该做。**

`sudo` 的边界同样重要：它**不能**解决「我不知道自己在哪个目录」「我不知道这个文件属于谁」这类问题。那是下面三条命令的活。

三条最基础的自查命令：

```text
pwd   →  print working directory，打印「我现在在哪个目录」
ls    →  list，列出当前目录里有什么
cd    →  change directory，切换到另一个目录
```

这三条命令单独看很简单，但它们回答的是终端操作里最要命的三个问题：**我在哪、这里有什么、我要去哪。** 遇到任何「命令没按预期工作」的情况，先把这三条跑一遍。

## Day 4：目录、路径与基本操作

**新概念：** Directory、Path；`mkdir`、`cp`、`mv`、`cat`、`nano`、`rm`

**总时长：** 55 分钟

### 今日目标

- 分清 Directory 和 Path，以及绝对路径和相对路径。
- 会用六条基本命令完成创建、复制、移动、查看、编辑和删除。
- 养成「删除前先确认路径」的习惯。

### 学习（25 分钟）

**Directory（目录）** 就是「文件夹」。**Path（路径）** 是描述「某个东西在哪里」的一串文字。

路径有两种写法：

```text
绝对路径  →  从最顶层开始写，以 / 开头
             /home/alice/practice/notes.txt

相对路径  →  从「我现在所在的位置」开始写，不以 / 开头
             notes.txt
             ./notes.txt
             ../practice/notes.txt
```

**为什么必须分清？** 因为同一个相对路径，在不同目录下指向完全不同的东西。这也是最容易出事的地方：你以为自己在删练习目录里的文件，实际上你在别的地方。

六条基本命令：

```text
mkdir  →  make directory，新建一个目录
          mkdir practice

cp     →  copy，复制一份
          cp notes.txt notes-backup.txt

mv     →  move，移动位置；也可以用来改名
          mv notes.txt archive/notes.txt

cat    →  把文件内容直接打印到屏幕上，适合看短文件
          cat notes.txt

nano   →  一个简单的文本编辑器，用来手动改文件内容
          nano notes.txt

rm     →  remove，删除
          rm notes.txt
```

逐条说明它们的边界：

- `mkdir` 一次只能建一层目录，除非加参数；建已存在的目录会报错，这其实是保护。
- `cp` 复制的是**当时的内容**，复制之后两边就各自独立了，改一个不影响另一个。
- `mv` 本地移动是瞬间的，因为它只改「位置记录」而不是搬数据。**但跨设备移动就是真的复制一遍，可能很慢。**
- `cat` 适合短文件。文件很长时输出会刷屏，而且 **`cat` 只读不改**，不能用来编辑。
- `nano` 是交互式编辑器，`Ctrl+O` 保存、`Ctrl+X` 退出。新手常常卡在「不知道按什么退出」。
- `rm` 是本周最需要小心的命令。

**关于 `rm` 的安全提醒：**

```text
rm 删除的东西不进回收站，没有任何撤销。
```

删除之前，务必先做两件事：

1. **用 `pwd` 确认自己现在在哪个目录。**
2. **用 `ls` 确认这个目录里到底有什么，要删的文件名写得完整、写对。**

不要在还没确认路径的时候，用通配符一次删一批 —— 通配符会匹配比你预期更多的东西。也**不要**不加确认地递归删除整个目录。删除是唯一一类「做错了就无法挽回」的操作，值得为它多花十秒钟。

**本周的操作纪律：只在你自己建的专用练习目录里做实验**（比如先建一个 `practice` 目录，所有删除练习都发生在这里面），不要碰系统目录、共享目录和有真实数据的地方。

- 解释 Directory 和 Path，并说明绝对路径和相对路径的区别。
- 回答：为什么相对路径容易出错？

### 测试（13 分钟，不给答案）

2. 判断：`rm` 删除的文件会先进回收站，可以恢复。
3. 判断：`cat` 可以用来编辑文件内容。

### 今日产出（5 分钟）

在你的专用练习目录里，走一遍完整流程：`mkdir` 建目录 → `cd` 进去 → `nano` 建一个文件 → `cat` 看内容 → `cp` 复制 → `mv` 改名 → 用 `pwd` 和 `ls` 确认无误后再 `rm` 删掉一个文件。把每一步「我在哪、我做了什么」记下来。

## Day 5：终端场景综合题

**新概念：** （综合应用，无新概念）

### 今日目标

- 遇到问题时能按「在哪里 → 做了什么 → 需要什么权限」的顺序排查。
- 完成本周周测与 Weekly Review。

### 学习（20 分钟）

本周所有命令背后，其实只有三个问题：

```text
在哪里？   →  pwd、路径是绝对还是相对
做了什么？ →  命令本身在操作什么，会不会不可撤销
什么权限？ →  当前用户是谁，需不需要 sudo
```

把 `Permission denied` 当成一张检查表来用：

```text
看到 Permission denied
  ↓
1. 我现在的用户是谁？（可能不是我以为的那个）
2. 我要动的这个文件属于谁？它的权限是什么？
3. 我真的需要改系统级的东西吗，还是只是路径写错了？

只有当答案是「我确实需要、且确实该由管理员做」时，才考虑 sudo。
```

**最常见的错误是顺序反了：看到报错第一反应就是加 `sudo`。** 但 `Permission denied` 经常只是「路径写错了、跑到别人的目录去了」，加 `sudo` 不但没解决问题，还把你的权限放大到了危险级别。

第二条纪律是把「不可撤销」的操作单独对待：

```text
可撤销的：创建、复制、查看        →  出错可以重来
要小心的：移动、改名              →  位置变了，可能找不到
不可撤销：删除                    →  删之前必须确认路径
```
