## Day 1：依赖、环境一致性与隔离

**新概念：** 依赖、环境一致性、隔离

**总时长：** 55 分钟

### 今日目标

- 理解「依赖」是什么，以及为什么它是软件装不上的头号原因。
- 理解「环境一致性」问题：为什么在你的机器上能跑、在我这里就不行。
- 理解「隔离」这个思路，以及它能解决什么、不能解决什么。

### 学习（25 分钟）

先看一个非常常见的场景：

```text
同一个软件，
在开发者的电脑上能跑，
在你的 NAS 上装不上，
在另一台 NAS 上能装上但行为不一样。
```

这不是玄学，而是**依赖**和**环境不一致**造成的。

**依赖（Dependency）** 是「这个程序要跑起来，必须先有别的什么东西」：

```text
一个应用
├── 需要某个版本的运行环境（比如 Python 3.11）
├── 需要某个版本的库（比如某个图像处理库）
└── 需要某个系统配置（比如时区、语言编码）
```

只要其中一项对不上，程序就可能装不上、起不来，或者跑起来行为异常。

**环境一致性** 指的是：让软件无论在谁的机器上运行，面对的都是同一套依赖。

**隔离（Isolation）** 是实现一致性的一种手段：不去修改你的系统，而是给每个应用准备一个「独立小房间」，让它带着自己需要的一切。

用类比：

```text
传统安装   →  把家具直接搬进你家客厅，和你原有的东西混在一起
容器化安装 →  搬进来一个带家具的集装箱，里面自成一套，不碰你家原有的东西
```

- 回答：为什么同一个软件会在不同机器上表现不同？
- 回答：隔离解决了什么问题？它是否让软件本身变得更稳定？

3. 判断：容器化安装会替换掉 NAS 上原有的系统组件。

## Day 2：Docker、Image 与 Container

**新概念：** Docker、Image、Container

**总时长：** 55 分钟

### 今日目标

- 理解 Docker 的角色：它是一套帮助你把应用「打包 + 运行」的工具。
- 区分镜像（Image）与容器（Container）：一个是模板，一个是实例。
- 能解释为什么镜像不是「正在运行的应用」。

### 学习（25 分钟）

**Docker** 是目前最常用的容器工具。它做的事情可以概括成两步：

```text
1. 打包：把应用 + 它的全部依赖，做成一个只读的模板
2. 运行：从这个模板启动一个真正跑起来的实例
```

这两个步骤对应两个核心对象：

```text
镜像（Image）      =  只读模板，包含应用和它的依赖
容器（Container）  =  从镜像启动的一个运行实例
```

关键关系：

```text
一个镜像  →  可以启动出很多个容器
容器      →  一定来自某个镜像
```

用类比：

```text
镜像  =  做蛋糕的配方 + 模具
容器  =  用这个配方真正烤出来的一个蛋糕
```

**配方不会自己变成蛋糕。** 镜像存在硬盘上，不占用 CPU，也「不在运行」—— 它只是描述「该怎么运行」。只有启动成容器之后，才真正有进程在跑。

**镜像为什么不是正在运行的应用：**

```text
镜像：静止的、只读的、可以被复制和共享的一份「说明书 + 材料包」
容器：运行中的、可读写的、占用内存和 CPU 的一个实例
```

一条只需要理解大意、不需要背的命令：

```bash
docker run 某个镜像名
```

它在做的事：**从「某个镜像」启动一个「新的容器」**。命令名 `run` 提示了这一点 —— 运行的不是镜像，而是容器。

## Day 3：Volume 与数据持久化

**新概念：** Volume、Bind Mount、Persistence

**总时长：** 55 分钟

### 今日目标

- 理解容器默认是「一次性的」：删掉容器，里面的改动就没了。
- 区分卷（Volume）和绑定挂载（Bind Mount）两种把数据放到容器外的方式。
- 能判断删除容器时，哪些数据必须提前保存。

### 学习（25 分钟）

容器有一个很容易踩的坑：**容器内部的文件改动默认不持久。**

```text
容器里写了数据
   ↓
删掉容器（docker rm）
   ↓
容器里的数据一起消失
```

这不是 bug，而是设计使然 —— 容器本来就是「用完可以扔掉」的一次性实例。升级软件时最常见的做法就是把旧容器删掉、用新镜像重新起一个。如果数据留在容器里，这一步就等于把数据一起删了。

解决方式是**把数据放在容器外面**，术语叫**持久化（Persistence）**。常见两种做法：

```text
卷（Volume）       由 Docker 管理的存储空间，位置对使用者透明
绑定挂载（Bind Mount） 把你指定的一个真实目录，直接接到容器里的某个路径
```

用类比：

```text
容器          =  酒店房间（退房后房间被清空）
卷 / 绑定挂载 =  你自己的行李箱（走到哪跟到哪）
```

**两者的取舍：**

- **卷**：由 Docker 管理，配置简单，适合「我只想让数据别丢」。
- **绑定挂载**：你明确指定「NAS 上哪个目录」对应容器里哪个路径，适合「我想在文件管理器里直接看到这些文件」。

**关键判断**：不是所有数据都值得保留。临时缓存丢了无所谓；配置、照片、数据库这类丢了就没了的，必须提前放到卷或绑定挂载里。

## Day 4：端口映射与环境变量

**新概念：** Port Mapping、Environment Variable

**总时长：** 55 分钟

### 今日目标

- 读懂 `8080:80` 这种端口映射写法，说清冒号两边各是什么。
- 理解环境变量在做什么，以及为什么它常用来传配置。
- 记住一条安全原则：真实密码、密钥不要写进笔记。

### 学习（25 分钟）

容器默认是隔离的 —— 隔离带来干净，也带来一个副作用：**外面访问不到它。**

要让容器里的服务能被访问，需要做**端口映射（Port Mapping）**。写法长这样：

```text
8080:80
  ↑    ↑
宿主机端口  容器内端口
```

读法是「把外面的 8080 接到里面的 80」。

```text
NAS（宿主机）           容器
  8080   ───────────→   80
```

- **冒号左边**：你在 NAS 上访问时用的端口。可以自由选择，只要不和别的服务冲突。
- **冒号右边**：服务在容器内部监听的端口。通常由这个软件决定，一般不该随便改。

用类比：

```text
镜像内端口  =  房间里面的门牌（由软件决定）
宿主机端口  =  这栋楼对外开的门（由你决定）
端口映射    =  把外面的门接到里面的门牌上
```

**环境变量（Environment Variable）** 是另一种「从外面给容器传信息」的方式。它用来传那些「不该写死在镜像里」的配置，例如：

```text
时区
管理员用户名
数据库地址
日志级别
```

写成示例是这样的（**注意这里都是示例值，不是真实值**）：

```text
TZ=Asia/Shanghai
ADMIN_USER=admin
ADMIN_PASSWORD=CHANGE_ME
```

**为什么用环境变量？** 因为同一个镜像要能服务不同的人、不同的环境。如果配置写死在镜像里，那么每个人都要自己改镜像，镜像就无法共享了。

**安全提醒**：环境变量经常承载密码和密钥。在笔记、截图、公开的配置文件里，**一律用示例值代替**，例如 `CHANGE_ME`、`example-token`。密码一旦写进公开文件，就等于公开了。

## Day 5：Docker 网络

**新概念：** Docker Network

**总时长：** 55 分钟

### 今日目标

- 理解 Docker 网络解决的是「容器之间怎么互相找到」。
- 闭卷画出 `Image → Container → Volume → Port → Network` 这条链。
- 完成本周周测与 Weekly Review。

### 学习（20 分钟）

端口映射解决的是「**外面的人**怎么访问容器」。但还有另一个问题：

```text
容器 A（应用）  →  要访问  →  容器 B（数据库）

它应该访问哪个地址？
```

答案不是 `127.0.0.1`，也不该是某个会变的 IP，而是 **容器名**：

```text
容器 A 里配置数据库地址为：db
                             ↑
                      这是容器的名字
```

**Docker 网络（Docker Network）** 提供的就是这件事：把若干容器放进同一个网络，让它们**能用名字互相找到**。

```text
同一个 Docker 网络内
  容器 A  ──用名字──→  容器 B
```

用类比：

```text
端口映射  =  给这栋楼开一扇对外的门（外面的人进来）
Docker 网络 =  楼里各房间之间的内部电话（房间里的人互相联系）
```

**为什么这很重要？** 因为一个完整的自托管服务通常不是单个容器，而是「应用 + 数据库」甚至更多。它们之间的连接如果靠写死的 IP，一旦容器重建、地址变化，配置就全断了。用名字连接，容器重建后名字不变，配置就还能用。

**本周的完整链条（请闭卷画一遍）：**

```text
Image（模板）
   ↓  启动
Container（运行实例）
   ↓  需要保存数据
Volume / Bind Mount（数据放在容器外）
   ↓  需要被外部访问
Port Mapping（把里面的端口接到外面）
   ↓  多个容器之间互相访问
Docker Network（用名字互相找到）
```

每一环回答一个不同的问题：

| 环节 | 回答的问题 |
|---|---|
| Image | 这个应用和它的依赖长什么样？ |
| Container | 它现在跑起来了吗？ |
| Volume | 删掉它，数据还在吗？ |
| Port | 我在浏览器里怎么访问它？ |
| Network | 它怎么找到另一个容器？ |
