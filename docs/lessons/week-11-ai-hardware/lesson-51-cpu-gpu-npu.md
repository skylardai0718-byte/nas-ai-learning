# 第五十一课：CPU、GPU 与 NPU

> 本课的一句话结论：**CPU、GPU、NPU 不是谁取代谁，而是分工 —— 一件任务交给谁，取决于它能多大程度并行，以及需要多大的容量。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **CPU**：通用处理器，负责调度和「什么都能做一点」的工作。
2. **GPU**：为大量并行计算而生，同一个简单动作可以同时做很多次。
3. **NPU**：为神经网络推理专门设计的加速器，只做这一类事。

你今天要建立的核心结构是：

```text
CPU  →  通用、会调度、能处理复杂逻辑，但并行规模有限
GPU  →  大量并行，适合重复的、结构一致的运算
NPU  →  专用加速，只针对神经网络这一类任务
```

以及一句判断原则：

```text
任务能并行吗？  ┐
需要多大容量？  ┘ →  决定交给谁
```

从本周开始，学习内容从「网络怎么通」转向「AI 怎么跑起来」。今天先认识干活的三类硬件。

## 2. 为什么要学

你可能已经听过「跑 AI 要买好显卡」这种说法。但这句笼统的话解释不了你真正会遇到的疑问：

- 为什么有些 AI 任务用普通 CPU 也能跑，有些却几乎必须用 GPU？
- 为什么现在的设备会单独配一个 NPU，它不是已经有 CPU 和 GPU 了吗？
- 一块 GPU 到底比 CPU 强在哪里 —— 是「更快」还是「更擅长某类事」？
- 为什么有的设备没有独立 GPU 也能做 AI？
- 为什么「有 GPU」不等于「跑得动某个模型」？

不学这一课，你会把「贵」「新」「跑分高」当成判断标准，而真正决定结果的其实是**任务的形状**和**容量**。

**这也是本周后续内容的前提** —— 后面讲显存、量化、软件栈，都要先知道「谁在算」。

## 3. 小白解释

### 3.1 三类硬件，像一个团队里的三种人

你可以把一台机器想象成一个小团队：

```text
CPU    →  项目负责人 + 多面手
          什么都会做，能统筹全局，但一次只能顾上少数几件事

GPU    →  一支人数众多的流水线工人
          每个人只会做很简单的一步，
          但几千个人同时做，总量就非常可观

NPU    →  一台专门为某道工序定制的机器
          只做神经网络这一类活，别的都不会，
          但做这一件事很省电、很快
```

**关键点：他们不是竞争关系。** 负责人（CPU）依然在指挥，只是把适合大量重复的活派给了工人（GPU）或专用机器（NPU）。

### 3.2 为什么「并行」是关键

同样是干活，有两种截然不同的方式：

```text
方式 A：一步一步，每步都很复杂
  适合 CPU —— 它擅长「接下来该做什么」这种判断

方式 B：同一个简单动作，重复几百万次
  适合 GPU —— 它擅长「同时做很多次同样的事」
```

神经网络的计算，本质上是**大量的乘法加法**，而且这些运算彼此之间很独立 —— 正好是方式 B。

所以 GPU 在 AI 上表现突出，不是因为它「更聪明」，而是因为它的形状刚好匹配这类任务。

打个比方：

```text
CPU 像一个数学教授    —— 能解很难的题，但只有一双手
GPU 像一千个算盘手    —— 每人只会加减乘除，但一千人同时算
```

要让一千人同时算一道题，得先把这道题拆成一千份简单的小计算 —— 而神经网络的运算恰好天然就能这样拆。

### 3.3 NPU 是什么，它和 GPU 有什么不同

NPU 也是并行硬件，但它比 GPU 更「专一」：

```text
GPU  →  通用并行：既能算神经网络，也能做图形、视频、科学计算
NPU  →  专用并行：基本只做神经网络推理
```

专用带来的好处是：

- 更省电（因为它只保留需要的电路）。
- 在同等功耗下，做这类任务效率更高。

代价是：

- 它**不能**当通用处理器用，运行不了普通程序。
- 它的能力范围由设计决定，不能像 GPU 那样灵活适应各种新任务。

**所以 NPU 出现，不是要取代 CPU 或 GPU**，而是把「神经网络推理」这件事从通用硬件上卸下来，交给一个更省电的专用部件。这在手机、笔记本这类对功耗敏感的设备上尤其有意义。

### 3.4 三类任务，先给一个粗判断

```text
低频问答（偶尔问一句，等一下没关系）
  →  CPU 常常就够，因为对吞吐量要求不高

图像识别（大量重复的矩阵运算，且要快速处理很多张）
  →  GPU 或 NPU 更合适，因为这是典型的并行任务

LLM 推理（大模型生成文字）
  →  主要看 GPU，而且关键约束往往不是算力，而是显存
```

最后一条本周会反复讲：LLM 推理的特殊之处，是**它不仅要算得快，还要先把一大堆数据装进显存**。这就是为什么「有 GPU」和「跑得动某个模型」是两件事。

## 4. 技术解释

### 4.1 CPU 的角色

CPU（中央处理器）是通用处理器，特点是：

- **核心数量少，但每个核心能力强**：擅长处理有先后依赖、逻辑复杂的指令。
- **负责调度**：操作系统、程序的启动、任务的分配，都由 CPU 统筹。
- **通用**：任何程序都需要它参与执行。

在 AI 任务中，CPU 通常做两件事：一是**组织与调度**（准备数据、启动计算、管理内存），二是**兜底执行**（在没有更合适的加速硬件时，硬着头皮把计算做掉，只是慢）。

### 4.2 GPU 的角色

GPU（图形处理器）最初是为图形渲染设计的，因为渲染图像刚好也是「大量重复的相同运算」。

它的特点是：

- **计算单元数量极多**：可以同时处理成千上万个小计算。
- **适合数据并行**：同一套指令作用在不同数据上。

用术语说，这属于**吞吐量（Throughput）优先**的设计 —— 单个任务不一定快，但同时处理一大批任务时总效率极高。而 CPU 更偏向**延迟（Latency）优先** —— 把单个任务尽快做完。

**这就是为什么「GPU 更快」这个说法不准确**：对一串必须按顺序执行的复杂逻辑，GPU 未必比 CPU 快；只有当任务可以被拆成大量独立小计算时，GPU 的优势才显现。

### 4.3 NPU 的角色

NPU（神经网络处理单元）是为神经网络推理专门设计的加速器。

- 它把神经网络里最常见的运算固化到硬件设计里。
- 因此它的能力范围较窄，但在范围内的效率与功耗表现更好。
- 它通常出现在功耗受限的设备上（手机、笔记本、部分嵌入式设备）。

**要注意区分「推理」和「训练」**：本课程讨论的是**推理（Inference）** —— 也就是使用一个已经训练好的模型。训练对硬件的要求和推理完全不同，不在本周范围。

### 4.4 「谁能跑 AI」取决于两个问题

判断一件 AI 任务该由谁承担，先问两个问题：

```text
问题一：这项计算能并行吗？
  能 → GPU / NPU 有优势
  不能（依赖关系强）→ CPU 更合适

问题二：需要多大的容量？
  模型和数据要放进显存/内存
  容量不够 → 再快的算力也用不上
```

第二条是 LLM 推理的核心约束，也是 Day 2 的主题。

**注意这里的边界**：这两个问题能帮你判断「大致该用哪类硬件」，但**不能**回答「这台机器能不能跑这个模型」。后者还需要知道模型多大、显存多大、上下文多长 —— 这是本周后面几天要补上的信息。

## 5. 类比

把一台机器想象成一家**餐厅的后厨**：

- **CPU 是主厨**：负责统筹、试味、做那些需要判断和经验的复杂菜。他一个人做不了上百份快餐，但没有他，整个后厨就乱了。
- **GPU 是一排快餐工位**：每位工人只做一个简单动作（比如打一个鸡蛋），但一百个工位同时开工，整体产量惊人。他们的强项是「重复且彼此独立」的活。
- **NPU 是一台专用的自动料理机**：只做一件事（比如专门煮面），但做得又快又省电。它做不了别的菜。
- **显存是后厨的台面**：所有食材和半成品都必须先摆在台面上才能加工。台面太小，再多的厨师也无从下手。

这个类比能解释什么：

**它解释了为什么「厨师多」不等于「能出菜」** —— 如果台面（显存）放不下食材（模型），再多的快餐工位也没有用武之地。这正呼应了本课程反复强调的判断习惯：**先看约束，再看能力。**

它也能解释为什么 NPU 不取代 CPU：餐厅里依然需要主厨做统筹和判断，专用料理机只是分担了其中一道工序。

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：只想偶尔让 NAS 回答一两个问题**

如果使用频率很低、每次等几秒也能接受，那么一台没有独立 GPU 的 NAS 用 CPU 也可能应付 —— 因为对吞吐量要求不高。

**但这里的边界是**：这件事成立的前提是「低频」和「模型较小」。一旦变成多人同时使用、或换成更大的模型，CPU 就会成为瓶颈。

```text
判断：低频 + 小模型 → CPU 可能够用
但它没告诉你：模型多大算「小」，多少人算「多」
```

**场景二：想让 NAS 自动识别照片里的内容**

照片识别属于典型的并行任务 —— 大量重复的矩阵运算，而且要处理成千上万张图。

```text
判断：这类任务适合 GPU 或 NPU
但它没告诉你：具体哪一类硬件在你的设备上可用，
              以及识别速度和照片数量之间的关系
```

**场景三：想在 NAS 上跑一个 LLM**

这时判断的重点会从「算得多快」转移到「装不装得下」：

```text
判断：主要看是否有 GPU 以及显存多大
但它没告诉你：模型多大、量化到什么程度、
              上下文要留多长 —— 这些信息都还没有
```

**这正是本周的核心判断习惯：先说出结论，再立刻说出「还缺什么信息」。**

### 6.2 三类任务与硬件的粗略对应

| 任务类型 | 特点 | 更合适的硬件 | 判断时最该看什么 |
|---|---|---|---|
| 低频问答 | 使用不频繁，可接受等待 | CPU 常常够用 | 使用频率、模型大小 |
| 图像识别 | 大量重复的矩阵运算 | GPU 或 NPU | 图片数量、可用加速硬件 |
| LLM 推理 | 需要大容量 + 大规模并行 | 主要是 GPU | 显存容量与带宽（见 Day 2） |

### 6.3 规格表不会告诉你的事

一张硬件规格表通常会写「几核 CPU」「有没有 GPU」「有没有 NPU」。但它**不会**直接告诉你：

- 这个配置能不能跑你想要的**那个具体模型**。
- 你的**使用方式**（单人低频还是多人高频）是否匹配这个硬件。
- 显存**实际可用**的部分有多少（系统和别的程序也会占用）。

**所以看到「带 NPU」或「带 GPU」这类描述时，不要直接推出「能跑 AI」的结论。** 它只是说明「有一类加速硬件可用」，离「能跑某个具体任务」还有好几步判断。

## 7. 常见误区

### 误区一：有了 GPU，CPU 就不重要了

不对。CPU 依然是整个系统的调度者 —— 操作系统的运行、任务的分配、数据的准备，都要靠它。GPU 只是被指派去做其中一类特别适合并行的计算。没有 CPU，GPU 连「该算什么」都不知道。

### 误区二：NPU 是能运行任何程序的通用处理器

不是。NPU 是**专用**加速器，它只为神经网络推理这一类运算设计，运行不了普通程序。它的优势来自「范围窄」—— 正因为只做一类事，才能做得更省电。要它做别的事，超出了它的设计范围。

### 误区三：GPU 比 CPU 快，所以凡是计算都该用 GPU

「GPU 更快」这个说法本身就不准确。GPU 的优势在于**吞吐量**：当任务能被拆成大量彼此独立的小计算时，它效率极高。但如果任务有很强的先后依赖、需要复杂的逻辑判断，CPU 反而更合适。**是不是用 GPU，取决于任务的形状，而不是哪个「更高级」。**

### 误区四：设备带 NPU，就说明它能跑 AI 任务

不一定。NPU 只是说明「有一类专用加速硬件存在」，它不保证：

- 你想用的那个模型能在它上面运行；
- 它的容量足够装下模型；
- 配套软件支持它。

**「有加速硬件」和「能跑某个具体模型」之间，隔着容量、软件支持等好几道判断。** 看到 NPU 就下结论，是本周最需要警惕的推理跳跃。

### 误区五：三类硬件是互相替代的关系

不是替代，是**分工**。CPU 负责调度和通用逻辑，GPU 负责大规模并行，NPU 负责省电地做推理。它们常常同时存在于一台设备里、同时参与同一个任务的不同环节。用「谁取代谁」的框架去理解，会让你看不清它们各自的边界。
