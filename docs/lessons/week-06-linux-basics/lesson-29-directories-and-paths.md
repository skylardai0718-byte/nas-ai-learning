# 第二十九课：目录、路径与基本操作

> 本课的一句话结论：**目录是文件夹、路径是「它在哪里」的写法，而终端里绝大多数事故都来自路径写错 —— 尤其是 `rm`，它删掉的东西不进回收站，所以删除前必须先确认自己和目标的位置。**

## 1. 今天学习什么

今天要掌握 2 个概念和 6 条命令：

1. **目录（Directory）**：就是文件夹，Linux 里所有东西都组织在目录树中。
2. **路径（Path）**：描述某个东西在哪里的文字，分绝对路径和相对路径。
3. 六条基本命令：**`mkdir`**、**`cp`**、**`mv`**、**`cat`**、**`nano`**、**`rm`**。

你今天要建立的核心结构是：

```text
目录树（所有东西挂在这棵树上）
  └── 路径（描述「树上哪个位置」）
        ├── 绝对路径：从树根开始写，以 / 开头
        └── 相对路径：从「我现在的位置」开始写，不以 / 开头
```

以及按危险程度排的命令分组：

```text
可以放心试：mkdir、cp、cat、nano    →  出错能重来
需要留神：  mv                      →  东西位置变了，可能找不到
不可撤销：  rm                      →  删之前必须确认路径
```

## 2. 为什么要学

这是本周最「动手」的一课，也是风险最高的一课。前三天的概念都在为今天做铺垫：你知道了这是什么系统、怎么进去、以什么身份 —— 今天你要真的动手改东西。

不学路径和这六条命令，你会遇到：

- 为什么我在一个目录里建的文件，换个地方就找不到了？
- 为什么同一条命令，在别人那里能用，我敲就报「没有这个文件」？
- 为什么 `cat` 之后屏幕刷了一大片，什么也看不清？
- 为什么进了一个文本编辑器之后就不知道该怎么出来？
- **为什么删掉的东西找不回来了？**

**最后一条是本周最重要的问题。** Linux 终端里的删除通常不进回收站，没有撤销 —— 这是它和图形界面最大的差别，也是最容易造成不可挽回后果的地方。

## 3. 小白解释

### 3.1 目录是一棵倒着长的树

Linux 里所有文件和目录，都挂在一棵树上。树根在最上面，叫 `/`（读作「根目录」）。

```text
/                      ← 树根，一切的起点
├── home/              ← 用户的家目录都在这下面
│   └── alice/         ← 某个用户的家目录
│       ├── practice/  ← 你自己建的练习目录
│       │   └── notes.txt
│       └── photos/
├── etc/               ← 系统配置文件
├── var/               ← 会不断变化的数据（日志等）
└── usr/               ← 系统和软件的文件
```

**「倒着长」的意思是：** 起点在上面（`/`），越往下越具体。就像快递地址从「国家」写到「门牌号」，越写越细。

**为什么用这种结构？** 因为它让「一个东西在哪」有一个唯一、明确的答案 —— 只要沿着树从上往下写一遍，就精确定位到它了。这就是路径。

### 3.2 路径就是「怎么走到那个东西」

路径有两种写法，区别只在**起点**：

```text
绝对路径  →  从树根 / 开始写
             /home/alice/practice/notes.txt
             ↑ 不管你在哪，这个写法指向的都是同一个文件

相对路径  →  从「我现在站的位置」开始写
             notes.txt
             ↑ 你在哪，它就指向哪里的 notes.txt —— 会变的！
```

**用一个比喻：**

```text
绝对路径  →  「中国北京市某区某路 1 号 3 单元 502」
             不管谁在哪里说这句话，指的都是同一个地方

相对路径  →  「楼上那家」
             你现在站在哪一层，这句话指的就是谁
```

**这就是相对路径最危险的地方：它依赖「你现在在哪」。** 同一句 `rm notes.txt`，在练习目录里删掉的是练习文件，在别的地方可能删掉的是完全不同的东西 —— 命令一字不差。

### 3.3 两个特殊符号

```text
.    →  当前目录（我现在在的地方）
..   →  上一级目录（我所在目录的上一层）
```

所以：

```text
./notes.txt      →  当前目录下的 notes.txt
../notes.txt     →  上一层目录里的 notes.txt
../..            →  上两层
```

**`..` 用起来方便，也容易数错层数。** 新手常见的错误是 `../` 写多了一个，结果操作到了完全没想到的目录。**不确定的时候用绝对路径，或者先用 `pwd` 和 `ls` 确认一下。**

### 3.4 六条命令各自做什么

```text
mkdir  →  make directory，新建一个目录
cp     →  copy，复制一份（原件还在）
mv     →  move，移动位置（原件不在了）；也可以用来改名
cat    →  把文件内容打印到屏幕上，适合看短文件
nano   →  打开一个简单的文本编辑器，手动改内容
rm     →  remove，删除
```

**最需要分清的一对是 `cp` 和 `mv`：**

```text
cp a b   →  复制：现在 a 和 b 两份内容相同，改一个不影响另一个
mv a b   →  移动：a 不在了，只剩 b
```

**最容易搞混的一对是「改名」和「移动」：** 在 Linux 里它们其实是**同一个操作** —— `mv` 换个名字就是改名，换个目录就是移动。因为名字和位置本来就都是「路径」的一部分。

### 3.5 关于 rm 的重要提醒

```text
rm 删除的东西，默认不进回收站，没有撤销。
```

在图形界面里，删错了还能去回收站捞回来。在终端里，**通常没有这一层**。所以删除之前，固定做两件事：

```text
1. pwd  →  确认我在哪个目录
2. ls   →  确认这里有什么、我要删的文件名写得对不对
```

还有两条纪律：

```text
不要在没确认路径的时候用通配符批量删除  →  通配符会匹配比你想象更多的东西
不要在没确认路径的时候递归删除整个目录  →  一行命令，全没了
```

**本周的操作纪律：只在你自己建的专用练习目录里做这些实验。** 先建一个练习目录（比如 `practice`），所有复制、移动、删除练习都发生在这个目录里面 —— 这样即使出错，损失的也只是练习文件。

## 4. 技术解释

### 4.1 目录也是文件

在 Linux 里，**目录本身也是文件**，只不过它的内容很特殊：记录着「我这里有哪些东西」。

这个事实有两个重要后果：

```text
后果一：操作一个文件，需要的不只是「对这个文件的权限」
        还需要对「它所在的目录」有相应权限

后果二：删掉一个文件，本质上是从「它所在目录的记录」里去掉一项
        所以你必须对该目录有写权限
```

**这解释了昨天那个疑问：** 「我明明是文件的主人，为什么删不掉它？」—— 因为**目录**不让你改。

### 4.2 目录的权限含义

目录的三种权限含义和普通文件不同：

| 权限 | 对普通文件 | 对目录 |
|---|---|---|
| 读（r） | 能看内容 | 能列出里面有什么 |
| 写（w） | 能改内容 | 能在里面增删东西 |
| 执行（x） | 能运行它 | 能「穿过」它、进入它 |

**目录的「执行」权限最容易被忽略。** 它决定你能否进入这个目录、能否访问里面的东西。所以可能出现这种情况：你**能列出**某个目录里有什么，但**进不去**；或者反过来，你**知道路径**却**列不出内容**。

### 4.3 路径的解析

当系统处理一个路径时，大致是这个过程：

```text
路径里出现 ..    →  回退一级
路径里出现 .     →  不动
路径不以 / 开头  →  在前面接上「当前目录」
路径以 / 开头    →  从根目录开始找
```

**逐层解析、逐层检查权限。** 所以一个长路径中任何一层不让你通过，整个操作就会失败 —— 而且报错往往只提到最后那个文件，让你误以为是文件的问题。

**这是排查时的关键意识：** 遇到权限问题时，要把整条路径上每一层都想一遍，而不是只盯着最后那个文件名。

### 4.4 六条命令的参数要点

```text
mkdir 目录名            →  建一层目录
mkdir -p a/b/c          →  一次建多层，中间的目录自动补上
                           （-p 也让「目录已存在」不再报错）

cp 源 目标               →  复制文件
cp -r 源目录 目标目录     →  复制整个目录需要 -r（递归），否则会被拒绝

mv 源 目标               →  移动或改名
                           同一位置内改名、跨目录移动，用同一条命令

cat 文件名               →  直接打印全部内容
                           文件很长时会刷屏，且不能编辑

nano 文件名              →  打开编辑器
                           文件不存在时会新建

rm 文件名               →  删除一个文件
rm -r 目录名            →  删除目录及其内容（危险）
rm -f                   →  强制，不再询问（更危险，慎用）
```

**关于这些参数的边界：**

- `-p` 让 `mkdir` 更宽容，方便，但也少了一次「目录已存在」的提醒。
- `-r` 是复制和删除目录时的必需参数，同时也是让 `rm` 变得危险的那个参数 —— 它把「删一个文件」变成了「删一整棵树」。
- `-f` 会跳过确认提示。**它省下的那几秒，换来的是没有任何缓冲的删除。**

**一个实用原则：涉及删除时，参数越少越安全。** 如果一条删除命令里有好几个参数，先停下来想清楚它到底会删掉什么。

### 4.5 nano 的进退

`nano` 是新手最容易卡住的命令，因为它一打开就占据了整个屏幕。要点：

```text
打开：nano 文件名
保存：屏幕底部会列出保存的按键组合
退出：屏幕底部同样会列出退出的按键组合
```

**关键认识：屏幕底部的提示栏一直在告诉你按什么。** 不需要背，低头看提示就行。这是 `nano` 对新手友好的地方 —— 它把「怎么出去」直接写在屏幕上了。

**但要注意方向：** 它写着保存和退出，不代表它会在你误改内容时拦你。所以编辑重要文件之前，先想清楚是不是该改、要不要先备份。

## 5. 类比

把 Linux 的文件系统想象成**一栋巨大的图书馆**：

- **目录是书架和隔间** —— 一层套一层，从总馆一直分到某个具体的格子。
- **路径是索书号** —— 绝对路径是「从总馆大门开始，左转第三个书架，第二层，第五本」，不管谁拿着它都能找到同一本书；相对路径是「从我现在站的地方往右数三格」—— 你站的位置不同，指的就是不同的书。
- **`pwd` 是抬头看自己在哪个阅览室** —— 不知道自己在哪，索书号写得再准也没用。
- **`ls` 是扫一眼这个书架有什么** —— 动手之前先看清楚。
- **`cp` 是复印** —— 原本还在架上，多了一份副本，之后两份各自独立。
- **`mv` 是把书挪到另一个架子** —— 原来那个位置空了。
- **`rm` 是把书直接粉碎** —— 没有垃圾桶，没有后悔药。
- **`. 和 ..` 是「本架」和「上一排」** —— 方便，但数错排数就找错地方。

**这个类比能解释什么：**

- 为什么相对路径危险 —— 同一句话在不同位置指向不同的东西。
- 为什么 `pwd` 和 `ls` 要养成习惯 —— 动手前先确认自己在哪、面前是什么。
- 为什么 `rm` 需要额外小心 —— 其他动作都有退路，它没有。
- 为什么 `cp` 和 `mv` 容易混 —— 一个留原件一个不留，后果完全不同。

**类比也有边界：** 图书馆里书挪了位置，管理员能帮你找回来；Linux 里 `mv` 之后你得自己记得挪到哪去了，`rm` 之后连管理员也找不回来。**这棵树上没有「管理员」这个角色。**

## 6. NAS 实际场景

### 6.1 一次安全的文件操作流程

```text
1. cd 到自己的练习目录
2. pwd        →  确认：「我确实在练习目录里」
3. mkdir 建一个子目录
4. cd 进入它
5. pwd        →  再确认一次
6. nano 建一个文件，写点内容，保存退出
7. cat        →  确认内容写进去了
8. cp         →  复制一份
9. ls         →  确认现在有两份
10. mv        →  给副本改个名
11. ls        →  再确认
12. rm        →  删掉其中一份
        ↑
   删之前：pwd 确认位置 + ls 确认文件名写对了
```

**这个流程看起来啰嗦，但它每一步都在做同一件事：确认自己在哪里、面前是什么。** 这是本周最值得养成的习惯。

### 6.2 三个真实判断

**场景一：命令报「没有那个文件或目录」，但文件明明在那里**

最可能的原因是**你不在你以为的目录里**。相对路径是相对于「当前位置」的，位置错了，路径就指向别处了。

```text
查证顺序：
  1. pwd        →  我现在到底在哪
  2. ls         →  这个目录里有什么
  3. 文件真的在这个目录里吗
  4. 如果不在，用绝对路径重新写一遍
```

**一个重要的判断：** 报错信息说的「文件不存在」经常不是「文件真的不存在」，而是「**在你说的那个位置不存在**」。这两种情况的处理方式完全不同。

**场景二：`cat` 一个文件，屏幕刷出一大片，完全看不清**

`cat` 的设计就是「把整个文件倒到屏幕上」。文件一长，它不会分页、不会等待、也不会给你机会慢慢看 —— 直接刷完，你只能看到结尾。

**正确的判断是：**

```text
cat 适合：  短文件、配置文件、你自己刚写的小文件
cat 不适合：长文件、日志

关键认识：cat 是只读的，它不会改文件
          但它也完全不给你控制权
```

**场景三：进 nano 之后出不来了**

不用慌。**屏幕底部一直写着按什么键保存和退出。** `nano` 把操作提示直接印在界面上，这是它对新手最友好的地方。

**但这里有个更值得注意的判断：**

```text
如果这个文件不是练习文件，而是有真实内容的文件
  →  先退出来，想清楚再改
  →  或者先复制一份备份

nano 不会拦你，也不会问你「确定要改吗」
```

**编辑器本身是中立的。** 它给你能力，判断要由你来做。

### 6.3 六条命令对照

| 命令 | 做什么 | 是否可撤销 | 关键边界 |
|---|---|---|---|
| mkdir | 新建目录 | 可以（删掉重建） | 已存在会报错，这是保护 |
| cp | 复制 | 可以 | 复制的是当时的内容，之后两份独立 |
| mv | 移动 / 改名 | 可以（挪回来） | 同设备瞬间完成，跨设备要真复制一遍 |
| cat | 打印内容 | 只读，不改 | 适合短文件；长文件会刷屏 |
| nano | 编辑内容 | 可以（不保存即可） | 不保存退出就不留痕迹 |
| rm | 删除 | **不可以** | 不进回收站，没有撤销 |

**这张表最该记住的一行是最后一行。** 其他命令做错了，你还有机会补救；`rm` 做错了，只能承担后果。

## 7. 常见误区

### 误区一：绝对路径和相对路径差不多，随便用

差别很大。**相对路径依赖你当前所在的位置，位置变了它就指向别的东西。** 这也是为什么同一个命令在不同目录下能造成完全不同的后果。在不确定自己在哪的时候，用绝对路径会更稳妥；或者先用 `pwd` 和 `ls` 把位置和内容都确认一遍。

### 误区二：rm 删掉的东西可以在回收站找回

在图形界面里也许是；**在终端里通常不是。** 命令行的删除默认不经过回收站，没有撤销，也没有提示。正因为如此，`rm` 的事前确认不是「谨慎一点更好」，而是**必须**。删除是本周唯一一类真正不可逆的操作。

### 误区三：cp 和 mv 差不多，都能把文件放到别处

结果看起来相似，过程完全不同。**`cp` 之后原件还在，`mv` 之后原件不在了。** 而且在 Linux 里「改名」和「移动」是同一条命令（`mv`）—— 因为名字本身就是路径的一部分。搞混这两条命令，轻则留下多余文件，重则以为文件还在、其实已经挪走了。

### 误区四：cat 可以用来编辑文件

不能。**`cat` 是只读的**，它只负责把内容打印出来。要改内容得用编辑器（比如 `nano`）。反过来说，因为 `cat` 不会改文件，它也是相对安全的一条命令 —— 它的问题不是危险，而是不好用：文件一长就会刷屏，你根本看不清。

### 误区五：路径写对了，命令就一定能执行

不一定。**路径正确只是「找到了目标」，能不能操作它还要看权限。** 而且权限是逐层检查的 —— 路径上任何一层目录不让你通过，整个操作都会失败，哪怕最后那个文件是你自己的。**「找不到」和「没权限」是两类不同的问题，报错信息往往指向不同的原因。**

```text
                  你现在学的路径写法，那时候会原样用上
```

今天只需要真正记住一句话：

> **目录是树，路径是从树的某处走到目标的走法 —— 绝对路径不会变，相对路径跟着你走；而六条命令里只有 rm 不可撤销，所以删除之前，先 pwd 再 ls，只在练习目录里动手。**
