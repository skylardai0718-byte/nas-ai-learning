# 第四十八课：Token 与上下文窗口

> 本课的一句话结论：**Token 是模型处理文字的最小单位，上下文窗口是它一次能同时看到的 token 上限 —— 而「上下文窗口」不等于「永久记忆」，这是本课最需要记住的一条边界。**

## 1. 今天学习什么

今天要掌握 2 个概念：

1. **Token（词元）**：模型处理文字时的基本单位，文字会被切成一块块的 token。
2. **上下文窗口（Context Window）**：模型一次能处理的 token 上限，包括你输入的内容和它输出的内容。

你今天要建立的核心结构是：

```text
一段文字  →  切成 Token  →  送进模型
                             ↑
                  上限是「上下文窗口」
                  （输入 + 输出 都算在内）
```

以及今天最要破除的一条：

```text
上下文窗口  ≠  永久记忆
```

## 2. 为什么要学

你大概遇到过这些情况：聊到一半，模型突然「忘了」前面说过的话；或者你的问题一长，它就抓不住重点了。这些都不是随机的毛病 —— 它们和今天这两个概念直接相关。

不学这两个概念，会遇到这些问题：

- 为什么模型不是「一个字一个字」读你的话？它是按什么单位读的？
- 为什么聊得越久，模型越容易「忘记」前面说过的东西？
- 为什么输入很长的文档给它，效果有时反而变差？
- 为什么说「上下文窗口大」是一个卖点？它大在哪里、有什么用？
- 为什么模型关掉对话后，就不记得你刚才说过什么了？

**这里最容易出错的一点是：把上下文窗口当成「模型的记忆」。** 它不是。它是**一次对话里能同时装下的内容上限** —— 一个容器的容量，而不是一个记忆库。这条边界搞混了，后面关于记忆、Agent 的所有内容都会错位。

## 3. 小白解释

### 3.1 Token：模型不是按「字」读的

人读中文，是一个字一个字（或者一个词一个词）读的。模型不是。它读的是**token（词元）**。

模型会把文字切成一块一块的小片段，每一块就是一个 token：

```text
你写的：  我喜欢学习人工智能

模型看到：[我][喜欢][学习][人工][智能]
           ↑ 每一块就是一个 token
```

注意：**切法和你熟悉的「字数」不一样。**

- 一个 token 可能是一个完整的词，也可能是半个词。
- 常见的词可能单独成为一个 token，生僻的词可能被切成好几块。
- 标点、空格、甚至换行，也可能各占一个 token。

```text
常见词：  [学习]      → 1 个 token
生僻词：  [蝙][蝠]    → 可能 2 个 token
```

**为什么这件事重要？** 因为模型的一切限制，都是按 token 数算的，不是按字数算的。同一个意思，写成不同的说法，占用的 token 数可能不一样。

### 3.2 上下文窗口：一次能装多少

**上下文窗口（Context Window）** 是模型一次能处理的 token 数量上限。

关键点在于：**它统计的不只是你输入的内容，还包括模型输出的内容。**

```text
上下文窗口 = 你输入的内容 + 模型输出的内容  （两者合计的上限）
```

打个比方：上下文窗口像一个**一次能装多少东西的托盘**。

```text
托盘容量 = 上下文窗口
你放上去的东西 = 你的输入
模型放上去的东西 = 它的回答
托盘满了 → 装不下新东西，最早放上去的会被挤掉
```

一旦内容超过这个上限，**最早的那些内容就会被挤出去** —— 从模型的角度看，它们就「不存在」了。这解释了那个常见现象：聊得很久之后，模型似乎忘了开头说过的话。不是它「记性差」，而是那些内容已经不在窗口里了。

### 3.3 上下文窗口不是永久记忆

这是本课最重要、也最容易搞错的一条。

很多人以为：既然模型能接着上文聊天，那它一定是「记住」了我。**不是。**

```text
上下文窗口：一次对话里能同时看到的内容（临时的）
永久记忆：  跨对话、长期保留的信息（普通模型默认没有）
```

区别在于：

- **上下文窗口里的内容是临时的。** 这一轮对话结束、或者内容超出上限，它就没了。
- **模型内部并没有一个长期记忆库。** 它不会把你今天说的话存起来，明天还记得。

**那为什么它能接着聊？** 因为你这次对话的所有内容一直「摆在托盘上」，模型每次回答前都会把这些内容重新看一遍。是内容一直在它眼前，不是它记住了。

一个直观的类比：

> 上下文窗口像**一块白板**。你在上面写字，模型看着白板回答。写满了，就得擦掉最早的，才能写新的。**关掉对话，相当于把白板擦干净** —— 下一块新白板，什么也没有。

模型能接着上文，是因为白板上还写着这些字；不是因为它把字抄进了笔记本。

### 3.4 窗口大，不等于更聪明

上下文窗口大，意思是「一次能装更多内容」—— 你可以一次给它更长的文档。这是有用的能力。

但要注意边界：

```text
窗口大 = 一次能装下的内容更多     ✓
窗口大 ≠ 它更能记住、更聪明       ✗
```

内容放进窗口里，也不代表模型一定能用好。就像把一本书摊开放在桌上，不等于你已经读懂了它。**「装得下」和「用得好」是两件事。**

## 4. 技术解释

### 4.1 Token 是怎么来的

模型处理文本前，会先用一套固定的切分方法把文字转成一串 token。这套切分方式在模型训练时就定好了，使用时不改变。

几个要点：

- **切分单位介于「字」和「词」之间**：常见片段可能整体成为一个 token，罕见片段会被拆开。
- **切分规则是和模型绑定的**：不同模型可能用不同的切分方式，所以同一段文字在不同模型里的 token 数可能不同。
- **标点、数字、符号都会占 token**：所以一段看起来很短的代码或数字串，token 数可能比预想的多。
- **token 数决定了很多限制**：上下文长度、生成速度、费用（如果按量计费）通常都按 token 算。

**实用含义**：估算长度时，用 token 数比用字数更接近实际。尤其在英文和代码里，一个「词」常常就是一个 token，中文里则常见多个字合成一个 token。

### 4.2 上下文窗口的组成

一次请求里，模型的上下文通常包含：

```text
[系统设定] + [历史对话] + [你这次的输入] + （模型生成的输出）
└──────────────── 合计受上下文窗口上限约束 ────────────────┘
```

它们**共享同一个上限**。这意味着：

- 历史对话越长，留给新输入和新回答的空间就越少。
- 如果输出了很长的内容，剩下的空间也会相应减少。
- 超出上限时，通常的做法是丢弃最早的内容（具体策略依实现而定）。

**所以「聊得越久越容易忘」是有机制原因的**：不是模型坏了，是窗口被历史内容占满了。

### 4.3 为什么必须有这个上限

这个限制不是随便设的，它来自模型的工作方式：

- 注意力机制要处理的连接数量，会随上下文长度快速增长。
- 窗口越长，需要的计算和存储资源越多。
- 因此窗口大小直接关系到运行模型需要的硬件资源。

**这解释了第 11 周要讲的一件事**：上下文窗口设得越大，对显存的需求越高。所以在 NAS 上跑模型时，窗口大小往往是一个需要权衡的设置，而不是越大越好。

### 4.4 上下文窗口与「记忆」的边界

把这件事说清楚，是本课的核心：

| 维度 | 上下文窗口 | 永久记忆 |
|---|---|---|
| 存什么 | 本次对话中的内容 | 跨对话保留的信息 |
| 存在哪 | 就在这一次的输入里 | 需要一个额外的存储机制 |
| 保留多久 | 对话结束或超出上限就没了 | 长期 |
| 普通模型有吗 | 一定有 | 默认没有 |

**结论**：上下文窗口是「一次能看多宽」，不是「能记多久」。一个窗口很大的模型，依然可能在关掉对话后对你一无所知。要让它「记住」跨对话的信息，需要模型之外的额外机制去实现 —— 这是第 12 周讲 Agent 和记忆时要展开的内容。

## 5. 类比

把模型想象成一位**坐在白板前答题的人**。

```text
白板        =  上下文窗口
你在白板上写的 =  你的输入和历史对话
他写在白板上的 =  模型的输出
白板的大小   =  上下文窗口的上限
```

这个人的工作方式是：

- 他**只看白板**。白板上有什么，他就根据什么回答。
- 白板**写满了**，就得擦掉最早写的，才能写新的。被擦掉的内容，他再也看不到了。
- **换一块新白板，他就完全重新开始** —— 上一块白板上写了什么，他一点印象都没有。

**这个类比能解释什么？**

- 它能解释**为什么聊久了模型会忘**：不是他记性差，是白板被擦过。
- 它能解释**为什么关掉对话就什么都不记得**：换白板了。
- 它能解释**为什么给他一份长文档有时效果反而变差**：白板被文档占满，留给思考的空间少了。
- 它能解释**为什么「窗口大」是优点但不等于「聪明」**：白板大意味着能同时看到更多材料，但他看得懂多少，是另一回事。

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：聊到一半，模型忘了前面说过的要求**

这是**上下文窗口被占满**的典型表现，不是模型坏了。历史内容被挤出去了，模型看不到，自然就无法遵守。可行的做法是：把关键要求**重新说一遍**，或者开一段新对话、把必要信息一次性给全。

**场景二：把一份很长的文档丢给模型，回答质量反而下降**

这可能是因为文档把窗口大部分占满了，留给模型处理的空间变少。**能装下，不代表用得好。** 更实际的做法是先自己筛选出相关部分，而不是整份丢进去。

**场景三：关掉对话，明天再问，模型完全不记得昨天聊过什么**

这**符合预期**。普通模型没有跨对话的永久记忆，昨天的内容早就随着对话结束消失了。指望它「记得你」，需要模型之外的额外机制 —— 那不在本周范围里。

### 6.2 一张对照表

| 现象 | 真正的原因 | 不是原因 |
|---|---|---|
| 聊久了，模型忘了开头 | 早期内容被挤出上下文窗口 | 不是模型「记性差」 |
| 同一段文字，不同模型 token 数不同 | 不同模型的切分方式不同 | 不是有一方算错了 |
| 窗口很大的模型，关掉对话照样不记得你 | 窗口是临时的，不是永久记忆 | 不是这个功能坏了 |
| 很长的输入，回答反而变差 | 窗口被占满，可用空间减少 | 不是模型「不支持长文本」 |

## 7. 常见误区

### 误区一：上下文窗口就是模型的记忆

这是本课最需要纠正的一条。上下文窗口是**一次对话里能同时看到的内容上限**，是临时的；永久记忆是跨对话长期保留的信息，普通模型默认没有。把「一次看多宽」误当成「能记多久」，后面关于记忆和 Agent 的内容都会错位。

### 误区二：Token 就是「字」或「词」

Token 是介于两者之间的切分单位。一个 token 可能是一个词、半个词、一个标点。不同模型的切分方式还不同，所以同一段文字在不同模型里的 token 数可能不一样。用「字数」去估算限制，往往不准。

### 误区三：上下文窗口只算输入，不算输出

窗口统计的是**输入加输出的合计**。模型生成的长回答同样占用窗口空间。所以一段很长的输出之后，能继续容纳的内容就变少了 —— 不是只有你写的东西才算数。

### 误区四：窗口越大，模型就越聪明

窗口大只意味着**一次能装下更多内容**。装得下不等于用得好 —— 材料再多，模型能不能抓住重点、用好它们，取决于模型本身的能力，而不是容器的大小。这是两个独立的维度。

### 误区五：模型能接着上文聊，说明它记住了我

能接着上文聊，是因为这段对话的内容一直「摆在它眼前」，它每次回答前都会重新看一遍。**是内容在那里，不是它记住了。** 关掉对话后，这个「可见范围」就清空了。
