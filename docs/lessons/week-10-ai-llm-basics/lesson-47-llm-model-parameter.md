# 第四十七课：LLM、模型与参数

> 本课的一句话结论：**模型不是存资料的数据库，而是从数据里学到的规律；参数不是你在设置里能改的选项，而是模型内部那些训练时自动调整出来的数值。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **LLM（大语言模型，Large Language Model）**：专门处理语言的、规模很大的神经网络。
2. **模型（Model）**：训练得到的产物，它把从数据里总结出的规律保存了下来。
3. **参数（Parameter）**：模型内部那些通过学习得来的数值，参数量衡量模型的规模。

你今天要建立的核心结构是：

```text
神经网络（一大类方法）
└── LLM（专门处理语言、规模很大）
    └── 模型 = 一堆参数的集合
        └── 参数量（如 7B）= 模型规模的一个指标
```

今天还要**破掉两个极其常见的误解**：

```text
误解一：模型是一个存了海量资料的数据库     → 错
误解二：参数就是软件设置界面里那些选项     → 错
```

## 2. 为什么要学

昨天你知道了 LLM 在 AI 地图里的位置。今天要往里面看一层：**这个「模型」到底是什么东西？它里面装的是什么？**

不把这一层搞清楚，会遇到这些问题：

- 为什么说模型「没有原样存下任何一句话」，但它又能回答几乎任何话题？那它到底存了什么？
- 为什么同一个问题问两次，模型可能给出略微不同的回答？如果是查数据库，应该每次一样才对。
- 「7B 参数的模型」这个说法，参数到底指什么？为什么它能用来描述模型的大小？
- 为什么别人说「调一下参数」，指的却是另一件完全不同的事？
- 模型文件为什么会那么大 —— 它到底把什么存了那么大？

**这一课是理解后面所有内容的地基。** Token、上下文、推理速度、显存需求，全都建立在「模型是一堆参数」这个事实上。

## 3. 小白解释

### 3.1 模型不是数据库：它学的是「规律」，不是「原文」

很多人以为，模型回答问题是因为它把海量资料存起来了，你一问，它就去里面翻。**这个理解是错的。**

```text
数据库：存的是原始资料。
        你存了什么，它就有什么；你没存的，它一定没有。
        同样的查询，每次给你同样的结果。

模型：  存的是从资料里总结出的规律。
        它没有原样保留任何一句话，但它学到了「话通常该怎么说」。
        同样的输入，可能给出不同的措辞。
```

用一句话区分：

> **数据库是「记住了」，模型是「学会了」。**

这件事可以这样体会：你见过成千上万只猫，就算你记不住每一只具体的样子，你也能一眼认出「这是一只猫」。你脑子里存的不是猫的照片集，而是「猫长什么样」的规律。模型也是这样工作的。

**为什么这个区别要紧？** 因为它解释了两件反常识的事：

- 模型能回答它「没背过」的问题 —— 因为它是在按规律生成，不是在查表。
- 模型有时会一本正经地编错 —— 因为它追求的是「说得像」，不是「查得准」。

### 3.2 参数：模型内部学到的数值

**参数（Parameter）** 就是模型内部那一大堆数值。训练的过程，本质上就是**不断调整这些数值**的过程，直到模型表现变好。

```text
训练前：参数是随机的        → 模型什么都不会
训练中：不断调整参数        → 模型逐渐学会了
训练后：参数固定下来        → 这就是「模型」
```

所以「模型」这个词，指的就是**这一整套数值的集合**。把它保存成文件，你得到的就是一个模型文件 —— 它之所以大，就是因为里面有海量的数值。

参数量常常用一个数字加 B 来表示。**B 是十亿（Billion）的意思。**

```text
一个 7B 参数的模型   → 内部约有 70 亿个数值
```

这个数字衡量的是**规模**，不是质量。更大的模型通常能力更强，但也需要更多资源 —— 这一点在第 11 周讲硬件时会展开。

### 3.3 参数不是「用户设置项」

这是今天第二个要破掉的误解，也是中文语境里特别容易混的一点。

在中文里，「参数」这个词常常出现在软件设置界面里 —— 比如「高级参数」「渲染参数」。所以很多人看到「模型参数」，第一反应是：那不就是设置里那些可以调的选项吗？

**不是。** 这是两个完全不同的东西：

```text
用户设置项（Settings）
  → 在界面上改的，比如主题、语言、字体大小
  → 由你决定，随时可改

模型参数（Parameter）
  → 训练时机器自己调整出来的数值
  → 藏在模型内部，训练完就固定
  → 普通用户通常完全不会去动它
```

用一个类比：**用户设置项像是你在车里调座椅、调后视镜；模型参数像是发动机内部齿轮的尺寸** —— 后者是造车时定下来的，不是你开车时能旋一个按钮就改的。

所以当你看到「调整参数」这种说法时，**先问一句：说的是哪一个？** 是用户能改的设置项，还是模型内部学到的数值？这两个意思被同一个词盖住了，最容易造成混乱。

### 3.4 那为什么会有人真的去「调参」？

有一种真实存在的活动，叫训练或微调 —— 那是在**改变模型参数本身**，需要大量数据和算力，是技术团队做的事。

而你在 NAS 上做的事，通常连这一步都不涉及：你只是**加载一个已经训练好的模型来用**，参数一动不动。

这两件事的区别，第 4 天会专门讲。今天你只要记住：

> **对绝大多数使用者来说，模型参数是一个「只读」的东西 —— 它在那里，但不归你调。**

## 4. 技术解释

### 4.1 LLM 的定义

LLM（Large Language Model，大语言模型）是神经网络中的一类，特征是：

- **目标是语言**：它的输入和输出都是文本。
- **规模很大**：参数量远超早期模型，因此被称作「大」。
- **通用性强**：同一个模型能处理问答、翻译、摘要、写作等多种任务，而不需要为每个任务单独设计。

它建立在上一课的神经网络方法之上，是那个大圈里最具体、也是本课程最常打交道的层级。

### 4.2 模型是什么

在机器学习语境里，**模型指的是训练过程的产物**：一套从数据中得到的规律表示。

它的关键性质有：

- **它是一个计算过程，不是一份资料清单**：你给它输入，它按内部数值算出一个输出。
- **它认识的是模式，不是原文**：训练数据中的具体句子不会原样保存在里面。
- **输出可能带有随机性**：这也是为什么同一问题可能得到不同措辞的回答。
- **它是有限的**：模型只知道它训练时接触过的那类规律；超出范围的提问，它可能编造出听起来合理但错误的内容。

### 4.3 参数的作用

参数是模型内部可被调整的数值。它们的作用可以这样理解：

- 训练时，这些数值被反复微调，使模型输出越来越接近期望。
- 训练结束后，数值固定，成为模型的一部分。
- 使用时，输入的文本被转换成一系列数值，与这些参数做大量计算，最终得到输出。

**参数量是描述模型规模的一个常用指标**，但它不能单独说明一个模型好不好用 —— 它还取决于训练数据、训练方法、以及是否针对任务做过调整。

### 4.4 为什么模型不是数据库

从技术角度看，两者的差别在于**存储的内容类型**：

| 维度 | 数据库 | 模型 |
|---|---|---|
| 存什么 | 原始资料本身 | 从资料中学到的数值规律 |
| 查询方式 | 精确定位、原样取出 | 根据输入计算、生成结果 |
| 同样输入 | 结果完全一致 | 结果可能略有不同 |
| 没存过的内容 | 一定查不到 | 可能生成出合理答案 |
| 出错方式 | 查不到就是查不到 | 可能生成「听起来对」的错误内容 |

最后一行尤其重要：数据库不会「编」，模型会。这不是模型坏了，而是它的工作方式本就如此。

## 5. 类比

把模型想象成一位**读了很多书的人**，而不是一间**藏书丰富的图书馆**。

```text
图书馆（数据库）：
  书都原样摆在架上
  你问什么，管理员去架上找
  架上没有，就是没有
  同一个问题，永远给你同一本书

读书人（模型）：
  书读完了，具体句子记不住，但学会了语言的规律和大量知识
  你问他什么，他用自己的话讲出来
  没读过的领域，他可能凭印象讲得头头是道 —— 但可能是错的
  同一个问题问两次，措辞可能不一样
```

**这个类比能解释什么？**

- 它能解释**为什么模型能答没背过的问题**：读书人不是在背书，是在用学会的规律表达。
- 它能解释**为什么模型会一本正经地说错**：读书人遇到不懂的，也会顺着印象讲下去，而不是老实说「书上没有」。
- 它能解释**为什么输出会不固定**：读书人每次复述的措辞不会完全一样。
- 它还能解释**参数是什么**：参数就像这位读书人头脑里那些看不见的「经验值」，是读书的过程中一点点形成的，而不是他自己随手能改的。

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：为什么下载一个模型要占那么大空间？**

因为它里面装的是**海量参数**，不是几段文字。参数量越大，需要保存的数值越多，文件就越大。你下载的不是一份「资料库」，而是一整套数值。

**场景二：为什么同一个问题问两次，回答措辞不一样？**

因为模型不是去数据库里取原文，而是**按学到的规律现场生成**。生成过程中带有随机性，所以同一输入可能得到不同表述 —— 这是正常现象，不是故障。

**场景三：有人说「我把模型的参数调了一下」，他在说什么？**

先别急着理解成「改了个设置」。这句话可能指两件完全不同的事：

- 如果他指的是界面上的配置项（比如生成长度、语气偏好），那其实是**应用层的设置**，不是模型参数。
- 如果他真的改动了模型本身的数值，那属于训练或微调，需要大量算力和数据 —— 通常不是家用场景在做的事。

**把「参数」这个词的两种意思分开，是这一课最实用的一点。**

### 6.2 一张对照表

| 你看到的说法 | 实际指的是 | 你能改吗 |
|---|---|---|
| 「模型有 7B 参数」 | 模型内部数值的规模 | 不能，这是属性 |
| 「在设置里调一下参数」 | 应用层的配置选项 | 能，这是设置项 |
| 「模型的参数被更新了」 | 训练/微调改变了内部数值 | 通常不由普通用户做 |
| 「这个模型参数很大」 | 规模大，占空间、要更多资源 | 不能，这是属性 |

## 7. 常见误区

### 误区一：模型就是一个存了海量资料的数据库

模型**没有原样保存**训练时看过的文本。它保存的是从这些文本中学到的规律。所以它没存过的内容也可能答得出（按规律生成），而它「读过」的内容也可能记不准（记住的是模式，不是原文）。数据库和模型在「存什么」上有本质区别。

### 误区二：参数就是软件设置里那些可以调的选项

中文里「参数」一词两用，极易混淆。**模型参数是训练时自动调整出来的内部数值**，训练完就固定，普通用户通常不会去动。你在界面上能改的那些，是应用层的设置项 —— 它可能影响模型怎么被使用，但它不是模型参数。

### 误区三：参数量越大，模型一定越好

参数量只表示**规模**，不直接等于质量。一个模型好不好用，还取决于训练数据、训练方法、以及有没有针对具体任务做过调整。更大的模型通常能力更强，但也更慢、更占资源 —— 第 11 周会讲这中间怎么权衡。

### 误区四：模型的回答每次都一样，说明它更可靠

正相反。**每次措辞不同是生成式模型的正常工作方式**，因为它在按规律现场生成，而不是查表。反过来，如果你发现一个「模型」每次逐字给出同样的长段落，那更值得怀疑它是不是真的在生成。

### 误区五：模型答错了，一定是坏了或者被限定了

模型可能生成听起来合理但实际错误的内容 —— 这是它工作方式的固有特点，不是故障。它在做的是「按规律生成最像样的话」，而不是「核对事实」。理解这一点，你才不会把它的每句话都当作事实来用。
