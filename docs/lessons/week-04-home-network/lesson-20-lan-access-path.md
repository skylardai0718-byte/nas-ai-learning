# 第二十课：一次局域网访问的完整路径

> 本课的一句话结论：**手机在家能访问 NAS，是因为它们处在同一个 LAN 里，数据只经过家里的设备，从头到尾没有离开过你家。**

## 1. 今天学习什么

今天没有新概念。**本周的六个概念到这里要串成一条完整的链路**：

| 概念 | 在链路中的角色 |
|---|---|
| LAN | 手机和 NAS 所处的同一个网络 |
| WAN | 这次访问**不需要**经过的部分 |
| Router | LAN 内部转发的必经环节 |
| Switch | 接口不够时扩展出来的转发设备 |
| Private IP | 手机和 NAS 各自的地址 |
| DHCP | 手机进入网络时拿到地址 |
| DNS | 把 NAS 的名字翻译成地址（如果用名字访问） |

你今天要建立的是**一条可以完整讲出来的路径**：

```text
手机连上 Wi-Fi
↓  向路由器请求地址（DHCP）
手机拿到 192.168.1.11
↓  和 NAS（192.168.1.10）处于同一个 LAN
输入 NAS 的地址或名字
↓  如果用名字，需要 DNS 翻译
数据出发
↓  同一个 LAN 内，路由器/交换机转发
NAS 收到请求，返回照片
↓  全程在家庭网络内部完成
```

## 2. 为什么要学

前四天你分别学了范围、设备、地址和服务。但真实的问题从来不是「DHCP 是什么」，而是：

**「为什么我的手机能找到 NAS？」**

能把这个过程完整讲出来，说明你真正理解了整张网络地图 —— 而不是记住了几个名词。这也是本周的验收标准。

更重要的是，**这条路径是下周的对照基础**：

```text
本周：手机在家 → 能访问   ✓ 因为同一个 LAN
下周：手机出门 → 不能访问 ✗ 因为不在同一个 LAN
```

**理解了「为什么能」，才能理解「为什么不能」。**

## 3. 小白解释

### 3.1 完整的访问过程

假设你在家，用手机看 NAS 上的照片。把整个过程拆开：

**第一步：手机进入网络**

手机打开 Wi-Fi，连上你家的网络。此时它还没有地址 —— 就像刚进酒店还没办入住。

```text
手机：「我来了，给我一个地址」
路由器（DHCP）：「你住 192.168.1.11 吧」    ← Day 4 的 DHCP
```

**第二步：手机和 NAS 在同一个「楼」里**

手机拿到 `192.168.1.11`，NAS 是 `192.168.1.10`。它们的地址前缀相同（`192.168.1.x`），说明**处于同一个网络**。

```text
手机 192.168.1.11  ┐
                   ├── 同一个 LAN
NAS  192.168.1.10  ┘
```

**第三步：手机找到 NAS**

你在手机上操作，可能是：

- 输入 IP 地址 `192.168.1.10`
- 或输入名字（如 `nas.local`）—— 这时需要 **DNS 或本地名称解析**把它翻译成 IP

**第四步：数据在楼内传递**

```text
手机 → 路由器/交换机 → NAS
```

**注意这里：数据不需要「出门」。** 手机和 NAS 在同一栋楼里，中间只经过家里的网络设备。

**第五步：NAS 回应**

NAS 找到照片，沿着原路返回。

**整条路径结束。数据从来没有离开过你家。**

### 3.2 为什么这条路径又快又私密

对比一下同样看一张照片的两种方式：

```text
方式 A：看 NAS 上的照片
手机 → 路由器 → NAS
✓ 不出门，速度快（取决于家里网络）
✓ 不经过任何外部服务器

方式 B：看云盘上的照片
手机 → 路由器 → 互联网 → 云服务商 → 互联网 → 路由器 → 手机
✗ 出门再回来，路径长
✗ 数据经过第三方服务器
```

**这就是为什么 NAS 的核心价值在于「数据在自己手里」。**

### 3.3 为什么出门就不行了

现在把场景换一下：你在公司，想访问家里的 NAS。

```text
公司手机 → 公司网络 → 互联网 → ？
```

问题出在最后一步：**你家的路由器不知道该怎么把这个请求交给 NAS。**

回忆 Day 3 的内容：NAS 用的是**私有地址** `192.168.1.10`，这个地址在互联网上没有意义 —— 互联网上的路由器不认识它，数据包会被丢弃。

**而且就算能找到你家的公网地址，路由器的默认行为也是「不理会外面来的、要找内部设备的请求」** —— 这是一道安全边界（Day 2 讲过）。

```text
在家：  手机和 NAS 同一栋楼  →  走两步就到        ✓
出门：  手机在别的城市      →  需要「进门」的许可   ✗ 默认没有
```

**这个「许可」怎么获得，就是第 5 周的全部内容。**

## 4. 技术解释

### 4.1 判断「是否在同一个网络」

技术上的判断依据是：**两台设备的 IP 地址是否属于同一个网段**（由子网掩码决定）。

家用场景下最常见的情况：

```text
手机  192.168.1.11
NAS   192.168.1.10
掩码  255.255.255.0
      ↓ 前三段相同
      同一个网段 → 可以直接通信
```

**本周不要求做子网计算**，只需建立这个直觉：**地址前缀相同 → 在同一个网络 → 能直接通信。**

### 4.2 数据在 LAN 内的转发

在同一个网络内，数据是怎么找到目标的？

**通过 MAC 地址（设备的物理地址）。**

```text
1. 手机知道 NAS 的 IP（192.168.1.10）
2. 但实际传输需要用 MAC 地址
3. 手机询问：「谁的 IP 是 192.168.1.10？」（ARP 协议）
4. NAS 回答：「是我，我的 MAC 是 XX:XX:...」
5. 手机把数据发往这个 MAC 地址
6. 交换机根据 MAC 地址把数据送到 NAS
```

**本周不需要记住 ARP 的细节**，只需理解：在 LAN 内部，设备之间能直接找到对方。

### 4.3 路由器和交换机在其中的角色

```text
如果手机和 NAS 接在同一台交换机上：
     手机 → 交换机 → NAS
     （同一网络内直接转发）

如果它们接在路由器的不同网口上：
     手机 → 路由器内部交换 → NAS
     （家用路由器的网口部分本身就是个小交换机）

如果 NAS 接在额外的交换机上：
     手机 → 路由器 → 交换机 → NAS
     （多一跳，但仍在同一个 LAN 内）
```

**关键点：无论哪条路径，数据都没有出 LAN。** 路由器在这里扮演的是「交换机」的角色，而不是「连接 WAN 的路由器」—— 这就是 Day 2 讲的「家用路由器是一体机」。

### 4.4 用 IP 访问和用名字访问

```text
用 IP 访问：192.168.1.10
  → 不需要 DNS，直接用
  → 缺点：IP 可能变（DHCP 租约），要记数字

用名字访问：nas.local
  → 需要 DNS 或本地名称解析
  → 优点：地址变了也还能用
```

**这也解释了为什么之前会遇到「能用 IP 访问但用名字不行」**（Day 4 的内容）：网络是通的，但名字解析这一环出了问题。

## 5. 类比

把这次访问想象成**在同一个小区里串门**：

```text
1. 你搬进小区，物业给你分配了门牌号     →  DHCP 分配地址
2. 你住 3 号楼 502，朋友住 3 号楼 305     →  同一个 LAN
3. 你想找朋友，查一下他家的具体位置      →  DNS / 名称解析
4. 你穿过走廊走到他家门口               →  LAN 内转发
5. 你敲门，他开门给你看照片              →  NAS 响应
```

**整个过程你都在小区里，没有出大门。** 所以你走得快（速度快）、别人也不知道（不经过外部）。

再对比「去另一个城市找朋友」：

```text
你得先出小区大门（经过路由器）
↓
上高速、走城市道路（WAN / 互联网）
↓
到达对方的小区
↓
但对方小区的门卫不允许陌生人随便进（默认的安全边界）  ✗
```

**最后这一步被拦住，就是下周要解决的问题。**

## 6. NAS 实际场景

### 6.1 完整的排障路径

把本周所有内容合成一张排查表：

```text
现象                                  →  可能的问题层
─────────────────────────────────────────────────────
手机连不上 Wi-Fi                       →  无线接入
连上了但拿不到地址（169.254.x.x）       →  DHCP
拿到地址但访问不了 NAS                 →  LAN 内转发 / 服务本身
能 ping 通 NAS 的 IP，但用名字不行      →  DNS / 本地名称解析
在家能访问，出门不能                    →  正常现象（第 5 周解决）
```

**这张表是本周最实用的产出。** 它的价值在于把「网络坏了」变成了「哪一层坏了」。

### 6.2 三个真实判断

**场景一：手机在家访问 NAS 很慢**

先判断慢在哪一段：

- LAN 内的传输速度取决于网线和接口速率（第 2 周学过：千兆还是 2.5G）。
- 如果 NAS 在做重负载任务（比如生成照片缩略图），CPU 或硬盘可能成为瓶颈（第 1 周的「瓶颈」思维）。
- Wi-Fi 信号弱也会拖慢速度。

**关键在于：LAN 内慢和「上网慢」是两回事，排查方向不同。**

**场景二：家里两台设备互相能通，但都上不了网**

能互相通信说明 **LAN 部分完全正常** —— 路由器、交换机、Wi-Fi、DHCP 都在工作。

上不了网，问题出在**路由器通往 WAN 的那一段**：可能是宽带线路、光猫、运营商侧，或者路由器的外网配置。

**这个分层判断能立刻缩小排查范围。**

**场景三：为什么 NAS 的地址变了，书签就失效了**

因为 DHCP 分配的地址有租约（Day 4）。租约到期后重新分配，NAS 可能拿到不同的地址。

解决办法：

- 在路由器里给 NAS 做**静态分配**（推荐 —— 既保留自动配置的可靠性，又固定地址）。
- 或者在 NAS 上设置固定的私有地址（注意不要和 DHCP 分配范围冲突）。
- 或者使用**本地名称解析**，用名字访问（地址变了也不影响）。

### 6.3 一句话总结本周

```text
在家能访问 NAS
= 在同一个 LAN
+ 有地址（DHCP）
+ 能找到（LAN 内转发 / DNS）
```

任何一项缺失，访问都会失败 —— 而这三项的检查方法，就是上面那张排查表。

## 7. 常见误区

### 误区一：在家访问 NAS 要经过互联网

不需要。手机和 NAS 在同一个 LAN 内，数据只经过家里的路由器或交换机，**不出门**。这也是它比云盘更快、更私密的原因。

### 误区二：能 ping 通就说明一切正常

不一定。ping 通说明**网络层是通的**，但不代表名称解析、服务本身或权限配置正常。比如 DNS 出问题时，IP 能通但域名不行 —— 这时 ping IP 是成功的。

### 误区三：出门访问不了是因为 NAS 坏了

不一定。最常见的原因恰恰是**正常的网络设计** —— NAS 使用私有地址，默认不接受来自外部的直接访问。这是安全边界，不是故障。

### 误区四：把 NAS 的地址设成公网 IP 就能在外访问

不是这么简单，而且这样做风险很高。让内部设备直接暴露在公网上会带来严重的安全隐患。正确的做法是第 5 周要学的：通过 VPN 建立私有通道，或者谨慎地做端口转发。

### 误区五：网络只要能通就行，不用搞清楚路径

能通的网络，出问题时你也会毫无头绪。**理解路径的价值在于排障**：知道数据经过哪些环节，才知道该检查哪里。

## 8. 知识地图

本周完整地图，从范围到完整路径：

```text
网络
├── 范围                          （Day 1）
│   ├── LAN 局域网                 （自己管、范围小、速度快）
│   └── WAN 广域网                 （运营商管、互联网）
├── 设备                          （Day 2）
│   ├── Switch 交换机              （同一网络内转发，扩展口数）
│   └── Router 路由器              （不同网络间转发，LAN/WAN 边界）
├── 地址                          （Day 3）
│   ├── Private IP                 （内部房间号，可重复）
│   └── Public IP                  （全球唯一，通常一个）
├── 服务                          （Day 4）
│   ├── DHCP                       （分配地址，有租约）
│   └── DNS                        （名字翻译成地址）
└── 综合                          ← 今天在这里
    └── 一次局域网访问的完整路径
        手机(拿地址) → 同一 LAN → 找到 NAS → 数据不出门
```

```text
Week 1     →  硬件、操作系统、应用三层；数据流思维
Week 2     →  硬件规格；瓶颈概念
Week 3     →  存储系统与数据保护
Week 4     →  家庭网络基本地图（本周）
     ↓
Week 5     →  端口、NAT、端口转发、DDNS、VPN、Tailscale
              回答「为什么出门访问不了，以及怎么解决」

```

今天只需要真正记住一句话：

> 手机在家能访问 NAS，是因为**它们在同一栋楼里**（同一个 LAN），靠 DHCP 拿到地址、靠 LAN 内转发找到对方 —— 而**出门访问不了，不是故障，是因为你不在那栋楼里了**。
