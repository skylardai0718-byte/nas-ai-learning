# 第十九课：DHCP 与 DNS

> 本课的一句话结论：**DHCP 解决「地址从哪来」，DNS 解决「名字怎么变成地址」—— 前者让你连上网络，后者让你能用人能记住的名字访问。**

## 1. 今天学习什么

今天要掌握 2 个概念：

1. **DHCP**：自动给设备分配 IP 地址的服务。
2. **DNS**：把域名翻译成 IP 地址的服务。

你今天要建立的核心结构是：

```text
DHCP  →  设备接入网络时，自动拿到一个 IP 地址
DNS   →  你输入域名时，自动查出它对应的 IP 地址
```

两个服务解决的是**两个不同阶段**的问题：

```text
阶段 1：设备连上网络
        →  需要一个地址        →  DHCP 负责

阶段 2：访问某个服务
        →  需要把名字变成地址   →  DNS 负责
```

**这个区分很重要**：它们出问题时的表现完全不同，排查方向也不同。

## 2. 为什么要学

昨天你知道设备需要 IP 地址。但你可能没想过：**这个地址是谁给的？**

如果每台设备都要手动填地址、填网关、填 DNS 服务器，那家里来客人想连个 Wi-Fi 都得先配置一遍 —— 这不现实。

DHCP 和 DNS 就是让网络变得「傻瓜化」的两个服务。不理解它们，会遇到这些问题：

- 为什么新设备连上 Wi-Fi 就能用，什么都不用配？
- 为什么重启路由器后，设备地址有时会变？
- 为什么能上 QQ 但打不开网页？（经典问题）
- 为什么设了静态 IP 之后反而上不了网？
- 为什么访问 NAS 有时要输 IP，有时可以输名字？

这些问题的答案指向同一件事：

```text
网络能「自动工作」，是因为有人在背后自动分配地址、自动翻译名字
```

## 3. 小白解释

### 3.1 DHCP：自动分房间号

**DHCP（动态主机配置协议）** 做的事情很直接：**设备接入网络时，自动给它分配一个 IP 地址。**

用酒店类比：

> 你入住酒店时，前台直接给你一张房卡，上面写着房间号。你不需要自己挑房间、也不需要知道这栋楼怎么编号 —— **DHCP 就是那个前台。**

没有 DHCP 会怎样？每台设备都要手动填：

```text
IP 地址      →  自己挑一个没被占用的
子网掩码     →  得知道填什么
默认网关     →  得知道路由器地址
DNS 服务器   →  得知道填哪个
```

**任何一项填错，设备就连不上网。** 所以 DHCP 的价值不只是「方便」，而是「让网络对普通人可用」。

### 3.2 DHCP 的关键：租约

DHCP 分配的地址是有**期限**的，叫做**租约**。

```text
设备拿到地址  →  租约开始
租约到期前    →  设备自动申请续租
没续上        →  地址被收回，可能分配给别人
```

**租约机制解释了一个常见现象**：重启路由器后，设备的 IP 地址有时会变 —— 因为路由器重启后，之前的租约信息可能丢失，设备重新申请时会拿到一个可能不同的地址。

**这也带来了一个实际问题**：如果你总是用 `192.168.1.10` 访问 NAS，某天它变成了 `192.168.1.15`，你的书签就失效了。解决办法有两种：

- **静态分配**：在路由器里把某个地址固定分配给 NAS 的物理地址。
- **用名字访问**：这就轮到 DNS 出场了。

### 3.3 DNS：把名字翻译成地址

**DNS（域名系统）** 做的事情是：**把人类能记住的名字，翻译成机器需要的 IP 地址。**

用电话簿类比：

> 你能记住「张三」这个名字，但拨电话需要号码。**DNS 就是那本电话簿** —— 你说名字，它告诉你号码。

```text
你输入：nas.local 或 example.com
↓ DNS 查询
得到：某个 IP 地址（比如 192.168.1.10）
↓
设备向这个地址发起请求
```

**为什么需要它？** 因为 `93.184.216.34` 这样的数字没人记得住，而 `example.com` 可以。

### 3.4 两个服务的分工

```text
DHCP：这时候我该用哪个地址？      （分配）
DNS：这个名字对应哪个地址？        （查询）
```

**一个是「发地址」，一个是「查地址」。** 别把两者混在一起 —— 它们出问题时的表现完全不同：

| 服务 | 出问题的表现 |
|---|---|
| DHCP 故障 | 设备拿不到地址，根本连不上网络 |
| DNS 故障 | 能连上网络，但输入域名打不开（输 IP 可以） |

**「能上 QQ 但打不开网页」就是 DNS 故障的经典表现** —— 因为 QQ 客户端直接连服务器的 IP，而浏览器需要先把域名翻译成 IP。

## 4. 技术解释

### 4.1 DHCP 的工作过程

简化后的四步（也叫 DORA）：

```text
1. Discover  设备广播：「有没有 DHCP 服务器？」
2. Offer     服务器回应：「我可以给你这个地址」
3. Request   设备：「我要这个地址」
4. Ack       服务器：「确认，这个地址归你了，租期 X 小时」
```

关键特性：

- **自动**：设备无需配置，插上就能用。
- **租约制**：地址有期限，可续租。
- **可保留**：多数路由器支持「把某个地址固定分配给某台设备」，兼顾自动与稳定。
- **通常由路由器提供**：家用场景下，DHCP 服务就在那台多合一设备里。

### 4.2 拿不到地址会怎样

如果设备连上了网络但没能从 DHCP 拿到地址，很多系统会自动给自己分配一个 `169.254.x.x` 的地址。

**看到这个地址段，基本可以确定是 DHCP 出了问题** —— 这是一个非常实用的排查线索。

### 4.3 DNS 的工作过程

简化后的查询过程：

```text
1. 设备问本地 DNS 服务器（通常是路由器）：「example.com 的地址是？」
2. 路由器如果有缓存，直接回答
3. 如果没有，它去问上游 DNS 服务器
4. 逐级查询，最终得到 IP 地址
5. 结果返回给设备，并缓存一段时间
```

关键特性：

- **分层查询**：不是一台服务器知道所有域名，而是逐级询问。
- **有缓存**：查询结果会被缓存一段时间，所以第二次访问更快。
- **可指定**：你可以把 DNS 服务器改成运营商提供的、公共的（如 `1.1.1.1`、`8.8.8.8`）或自建的（这正是 Pi-hole 这类自托管项目的用武之地）。

### 4.4 局域网内的名字解析

在家庭网络里，还有一类特殊的「DNS」：**本地名字解析**。

有些路由器或 NAS 支持让设备用名字互相访问，比如：

```text
nas.local      →  192.168.1.10
```

这不是互联网 DNS，而是**局域网内部的名称解析**。它的好处是：**即使 NAS 的 IP 变了，你仍然可以用名字访问** —— 正好解决了 DHCP 租约变化带来的问题。

第 9 周会接触到的 Pi-hole，本质上就是一个自建的 DNS 服务器，同时兼具广告拦截功能。

## 5. 类比

用**酒店**来理解这两个服务：

- **DHCP 是前台**：你入住时，前台直接给你一张房卡和房间号。你不需要自己挑房间，也不需要知道这栋楼怎么编号 —— **它负责「分配」**。
- **DNS 是问询处**：你想找「健身房」，但楼里标识都是房间号。问询处告诉你「健身房在 3 楼 305」—— **它负责「翻译」**。

两个岗位的分工很清楚：

```text
前台（DHCP）：你住哪个房间？        →  给你地址
问询处（DNS）：健身房在哪？          →  告诉你地址
```

**其中一个坏了，症状完全不同：**

- **前台坏了（DHCP 故障）**：你根本进不了房间 —— 设备连不上网络。
- **问询处坏了（DNS 故障）**：你能进房间、能打电话（用已知的号码），但想找某个地方时问不到 —— 用 IP 能访问，用域名不行。

**这个类比能帮你快速判断问题出在哪一环。**

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：为什么设置静态 IP 之后反而上不了网**

手动设置地址时，需要同时填对四项：IP 地址、子网掩码、默认网关、DNS 服务器。**任何一项填错都会导致上不了网。** 常见错误有：

- IP 地址和现有设备冲突。
- 默认网关填错（应该指向路由器）。
- DNS 没填（结果能连上但打不开网页）。
- 子网掩码不对（导致设备认为外部设备在同一网络里）。

**手动配置容易出错，这正是 DHCP 存在的理由。** 如果确实需要固定地址，更稳妥的做法是在路由器里做「静态分配」—— 设备仍然通过 DHCP 拿地址，但每次拿到的都是同一个。

**场景二：用 IP 能访问 NAS，用名字不行**

说明网络连接是通的（IP 能用），问题出在**名字解析**这一环：

- NAS 的本地名称解析服务有没有开启？
- 你用的名字格式对不对（不同系统支持的后缀不同）？
- 设备的 DNS 设置是否正确？

**这个判断方法很实用**：能通 IP 不能通名字 → 查 DNS；IP 也不通 → 查网络连接本身。

**场景三：改完路由器设置后设备上不了网，重启一下又好了**

因为设备可能还持有旧的地址信息（旧的网关或 DNS）。重启设备或重新连接 Wi-Fi 会让它重新走一遍 DHCP 流程，拿到与新设置匹配的信息。

**这也解释了为什么「重新连一下 Wi-Fi」是很有效的排查手段。**

### 6.2 排障时的判断顺序

```text
设备连不上 Wi-Fi             →  无线层
连上了但拿不到地址（169.254.x.x）→  DHCP 问题
拿到地址但只能访问局域网       →  路由器到 WAN 那一段
能访问局域网，输 IP 能开网页、输域名不行  →  DNS 问题
```

**注意最后两行的区别**：这是把「网络通不通」和「名字能不能解析」分开判断的典型例子。

### 6.3 关于自建 DNS

Day 4 的内容和第 9 周的 Pi-hole 直接相连：

```text
路由器默认提供 DNS  →  方便，但你会看到所有广告域名
改用自建 DNS       →  可以拦截广告、也能看到家里哪些设备在访问什么
```

**这也带来一个隐私提醒**：DNS 服务能看到你访问了哪些域名。用运营商默认 DNS 意味着这些信息经过运营商；自建则可以自己掌控。这是第 9 周会展开的话题。

## 7. 常见误区

### 误区一：DHCP 分配的地址是永久固定的

不是。DHCP 分配的是**租约**，有期限。到期会续租，续不上就可能被收回并分配给别人。所以设备的 IP 地址**可能变化**。

### 误区二：DHCP 和 DNS 是同一件事

完全不同的两件事。DHCP 负责**分配地址**（设备接入网络时），DNS 负责**翻译名字**（访问服务时）。它们常常在同一台设备上运行（比如路由器），但功能毫不相干。

### 误区三：能上 QQ 说明网络完全正常

不一定。QQ 这类客户端可能直接使用 IP 连接，而浏览器需要 DNS 解析。**「能上 QQ 但打不开网页」正是 DNS 故障的典型表现。**

### 误区四：改成静态 IP 会更稳定

不一定。手动配置有四项要填对，任何一项出错都会断网。如果只是想让 NAS 地址不变，在路由器里做静态分配更稳妥 —— 既保留了自动配置的可靠性，又保证了地址固定。

### 误区五：DNS 只是个技术细节，不影响使用

DNS 直接影响你能否用域名访问服务，同时也涉及隐私 —— 它记录了你的访问目标。第 9 周的自建 DNS 项目就是围绕这一点展开的。
