# 第十四课：备份、快照与同步

> 本课的一句话结论：**备份是「另一份拷贝」，快照是「回到过去」，同步是「保持一致」—— 三者解决三种不同的危险，任何一个都替代不了另外两个。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **备份（Backup）**：把数据复制到另一个位置，形成独立副本。
2. **快照（Snapshot）**：记录某个时间点的数据状态，可以快速回退。
3. **同步（Sync）**：让两个位置的内容保持一致。

你今天要建立的核心结构是：

```text
三种机制，三种思路
├── 备份  →  另存一份        （防「丢了」）
├── 快照  →  记住过去        （防「改错了」）
└── 同步  →  保持一致        （防「两边不一样」）
```

**关键认知：这三者常被混为一谈，因为它们在日常语言里都像「保护数据」。但它们防的不是同一种危险。**

## 2. 为什么要学

前三天你学了 RAID。RAID 能防硬盘损坏，但有三种情况它**完全无能为力**：

- 你误删了一个重要文件。
- 勒索软件加密了你的所有文件。
- 整台 NAS 被偷走了。

这三种情况，RAID 一个都防不住。那靠什么防？靠今天这三个概念。

不理解它们的区别，会遇到这些问题：

- 为什么 NAS 上有「快照」功能，还需要另外做备份？
- 为什么云盘同步不能当备份用？
- 为什么勒索软件连备份一起加密了？怎么避免？
- 什么是「3-2-1 原则」？为什么要这么麻烦？
- 快照很快就能建，备份却要很久，那快照是不是就够了？

这些问题的答案指向一件事：

```text
不同危险需要不同防护
↓
所以要把「防什么」和「用什么防」对应起来
```

## 3. 小白解释

### 3.1 备份：另存一份，放在别处

**备份就是把数据复制一份，存到另一个位置。**

关键在于「另一个位置」。如果备份和原件在同一块硬盘上，那块盘坏了两个一起没 —— 这不叫备份，叫浪费空间。

用办公类比：

> 备份就像把重要合同**复印一份，锁进另一个办公室的柜子**。原件烧了、被咖啡泡了、被偷了，复印件还在。

备份的价值在于**独立**：它与你日常使用的数据在物理上分开。

### 3.2 快照：给数据拍张照，能回到那一刻

**快照记录的是某个时间点的数据状态。**

想象你在写一份很长的文档，每隔一段就点一次「保存版本」。

```text
周一版本  →  周二版本  →  周三版本
```

周三你改坏了，可以退回周二那一版。**快照就是系统级的「保存版本」。**

它有几个重要特点：

- **很快**：大多数快照只记录「变化了什么」，不复制全部数据，所以创建几乎是瞬间完成的。
- **省空间**：同样因为只记录变化，占用的空间远小于完整副本。
- **依赖原存储**：快照通常和数据放在同一个存储系统里。**原存储坏了，快照也跟着没了。**

### 3.3 同步：让两边内容一样

**同步是让两个位置的内容保持一致。**

比如你把手机照片同步到 NAS，手机里加一张，NAS 上也多一张。

同步有一个非常关键的问题：**方向。**

```text
单向同步：只从 A 推到 B     →  A 上的误删不会传到 B
双向同步：两边互相同步       →  A 上的误删会传到 B
```

双向同步很方便——两台设备随时保持一致。**但正因为它太「忠实」，危险也随之而来**：你在 A 上误删一个文件，它会忠实地把这个删除也同步到 B。勒索软件加密了 A 上的文件？它同样会把加密结果同步过去。

**同步的目标是「一致」，不是「安全」。** 这两件事有时候是冲突的。

## 4. 技术解释

### 4.1 备份（Backup）

备份的核心特征：

- **独立副本**：数据存在于与原件分离的位置或介质上。
- **可恢复历史**：通常保留多个时间点，能回到过去的某个状态。
- **离线可能**：好的备份方案会包含离线或异地的副本。

**为什么「离线」重要？** 因为勒索软件会加密它能访问到的一切。如果你的备份盘一直插在 NAS 上、随时可写，那它同样会被加密。**只有断开连接或位于异地的那份，才真正安全。**

这引出了备份领域最实用的一条经验法则：

### 4.2 3-2-1 原则

```text
3  →  至少 3 份数据（1 份原件 + 2 份备份）
2  →  存放在 2 种不同的介质上
1  →  其中 1 份在异地
```

逐条理解为什么：

- **3 份**：单份怕意外，双份怕同时出事，三份才算稳。
- **2 种介质**：全部放在同一批同型号硬盘上，如果这批盘有共同的缺陷或同时老化，可能一起出问题。
- **1 份异地**：防的是火灾、水灾、盗窃这类「整个地点全毁」的事件。

### 4.3 快照（Snapshot）

快照的技术实现有多种，但共同点是**记录数据在某一时刻的状态**。

主流实现依赖于能追踪变化的文件系统或存储层（如 Btrfs、ZFS 等支持快照的文件系统 —— 这正好回扣了 Day 1 的内容：**文件系统决定了你能用哪些能力**）。

关键特性：

- **创建快**：大多采用写时复制等机制，只在数据被修改时才保存原版本，所以创建瞬间完成。
- **占空间少**：只保存变化的部分。
- **回退快**：恢复某个快照通常比从备份恢复快得多。

**但快照有一个根本局限：它通常和原数据在同一个存储系统内。** 这意味着：

```text
硬盘损坏      →  快照跟数据一起没
存储系统故障  →  快照跟数据一起没
NAS 被偷      →  快照跟数据一起没
勒索软件加密  →  同机的快照也可能被加密
```

**所以快照解决的是「快速回到过去」，不是「数据丢失后的最后保障」。**

### 4.4 同步（Sync）

同步的目标是**内容一致**，常见形式：

- **单向同步**：A → B。A 的变化推到 B，B 的变化不影响 A。
- **双向同步**：A ↔ B。两边任何变化都会传播到另一边。

对数据保护而言，差别很大：

| 类型 | 误删文件的后果 | 能否当备份 |
|---|---|---|
| 单向同步 | 只在 A 上删掉，B 上的副本还在 | 接近备份（但若立即传播则不是） |
| 双向同步 | 删除会传播到 B，两边都没了 | 不能 |

**需要准确理解的一点：即使是单向同步，如果它是实时的，也未必是备份。** 因为你删除文件的瞬间它就同步过去了 —— 你没有「回到昨天」的能力。**备份的核心价值是保留历史，同步的核心价值是保持一致。**

## 5. 类比

把数据想象成**一份正在写的重要手稿**。

- **备份**：把手稿**复印一份，寄到另一个城市的家里**。原稿烧了、被撕了、被偷了，你还有一份。
- **快照**：写到每一章就**存一个版本**。第 5 章写砸了，可以退回第 4 章的版本。但**这些版本都放在同一张书桌上** —— 书桌被烧，所有版本一起没。
- **同步**：把手稿**同步到另一台电脑**，两边始终一样。但如果有个捣乱的人在原稿上乱涂，这个涂改会**同样出现在那台电脑上**。

三种思路对应三种危险：

```text
怕「弄丢了」     →  备份（寄到别处）
怕「改坏了」     →  快照（存版本）
怕「两边不一致」 →  同步（保持一致）
```

**用错工具的典型例子**：担心手稿被烧，却只在同一张书桌上存了很多版本 —— 那就是把快照当成了备份。

## 6. NAS 实际场景

### 6.1 风险与方案的对应表

这是本课最实用的一张表：

| 风险 | 有效方案 | 为什么 |
|---|---|---|
| 误删文件 | 快照 / 备份 | 需要能回到删除之前的状态 |
| 硬盘故障 | RAID / 备份 | RAID 保服务不中断，备份保数据能恢复 |
| 勒索软件 | 离线或异地的备份 | 已连接、可写的备份也会被加密 |
| 设备被盗 | 异地备份 | 同机内的副本跟着一起丢 |
| 文件版本改坏 | 快照 | 需要时间点回退能力 |

### 6.2 三个真实判断

**场景一：NAS 上开了快照，还需要备份吗？**

**需要。** 因为快照和原数据通常在同一个存储系统里。硬盘损坏、NAS 被盗、系统故障，快照都会跟着一起失效。快照能快速恢复误删和误改，但它不满足「独立副本」这个备份的核心条件。

**场景二：我用云盘同步文件夹，算备份吗？**

要看同步方式和云盘的行为。如果是**双向同步**，你在本地的误删会传播到云端，云端也删了 —— 这不是备份。另外还要确认云盘是否保留历史版本：**如果它保留了版本历史，那部分具备了备份价值；如果只是保持最新状态，那就不是。**

**场景三：为什么勒索软件能连备份一起加密？**

因为那台备份设备处于**在线且可写**的状态。勒索软件会加密它能访问到的一切网络位置，包括映射的网盘、联网的备份服务器。

**防护方法**：保证至少有一份备份是**离线**的（物理断开、用完就拔）或**异地**的，并且**不可被覆盖**（比如追加写入或版本化存储）。

### 6.3 一条实用的组合策略

家用 NAS 的常见做法是把几种机制叠加，各自负责不同风险：

```text
RAID 1 / 5        →  硬盘坏了服务不中断
定时快照          →  误删、误改能快速回退
异地 / 离线备份   →  勒索软件、被盗、火灾的最后保障
```

**三者不是互相替代，而是层层叠加。** 每一层都补上前面那层的漏洞。

## 7. 常见误区

### 误区一：有快照就不需要备份

快照通常与原数据位于同一存储系统，硬盘损坏、设备被盗、系统故障时，快照会一起失效。**快照提供的是「快速回退」，不是「独立副本」。**

### 误区二：双向同步等于备份

双向同步的目标是保持一致，它会把误删和加密**忠实地传播**到另一边。这不是保护，而是把风险复制了一份。

### 误区三：备份放在 NAS 里就够了

如果备份和原件在同一台 NAS 上，那么设备被盗、火灾、勒索软件这些「整机级」的风险，会让两者一起失效。**备份必须在物理上分开。**

### 误区四：在线备份就是安全的

在线服务本身可能没问题，但**如果它是联网且可写的**，勒索软件就能加密它。真正可靠的做法是保有一份离线或不可覆盖的副本。

### 误区五：备份做一次就够了

数据在变，备份也必须持续。而且**没验证过的备份等于没有备份** —— 定期做一次实际恢复测试，确认备份真的能用，是方案的一部分。
