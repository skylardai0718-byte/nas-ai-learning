# 第十一课：数据如何从硬盘变成可用空间？

> 本课的一句话结论：**一块新硬盘只是一堆能存 0 和 1 的空间，要经过分区和格式化，加上文件系统，才能变成你熟悉的「文件夹和文件」。**

## 1. 今天学习什么

今天要掌握 5 个概念，它们构成一条**从物理到逻辑的链**：

1. **磁盘（Disk）**：物理硬盘本身。
2. **分区（Partition）**：把一块盘切分成几个可以独立使用的部分。
3. **文件系统（File System）**：定义文件如何命名、如何组织目录、数据存在哪里。
4. **卷（Volume）**：可以被系统挂载使用的逻辑存储单元。
5. **存储池（Storage Pool）**：把多块硬盘的容量汇集起来，再从中划分卷。

你今天要建立的核心结构是：

```text
物理磁盘（Disk）
↓ 划分
分区（Partition）
↓ 格式化
文件系统（File System）
↓ 被管理
卷 / 存储池（Volume / Pool）
```

**上周你学的是「存储的物理形态」（HDD、SSD、SATA、NVMe）。这周开始往上一层走：硬盘之上怎么长出「文件」这个概念。**

## 2. 为什么要学

你在第 1 周学过「磁盘是长期保存数据的部件」。但如果你打开一块新买的硬盘，会发现它**什么也存不了** —— 不能新建文件，也不能建文件夹。

这个过程是怎么发生的？不理解这一层，会遇到这些问题：

- 为什么新硬盘装上去之后，系统看不到它？
- 为什么硬盘要「格式化」？格式化会删数据吗？
- 为什么 Windows 和 Mac 的硬盘常常不能互相读取？
- 为什么 NAS 上的存储空间和硬盘数量对不上？
- 为什么「存储池」里的容量和实际可用容量不一样？

这些问题的答案都在同一件事上：

```text
物理空间  ≠  可用的文件空间
     ↓ 需要
分区 → 文件系统 → 挂载
```

**这也是理解 RAID 的前提：RAID 是在「物理磁盘」这一层做文章，而文件系统是在它上面。搞清楚谁在谁下面，后面才不会乱。**

## 3. 小白解释

### 3.1 新硬盘为什么什么也存不了

想象你买了一块**空地**。

空地本身可以盖房子，但你没法直接告诉别人「把东西放在第三个窗户旁边」—— 因为还没有房子、没有门牌号、没有房间划分。

一块新硬盘就是这样。它有容量，能存 0 和 1，但**没有结构**。系统不知道哪个位置是文件的开头、哪些字节属于哪个文件、文件叫什么名字。

要让这块空地变成能住人的地方，需要三步：

```text
1. 分区   →  把空地划分成几块地
2. 格式化 →  在地块上建房子、编门牌号
3. 挂载   →  让大家知道从哪条路能进去
```

### 3.2 分区：把一块地切成几块

**分区（Partition）** 就是把一块物理硬盘切成几个部分，每部分可以独立使用。

为什么要切？常见原因：

- 一块盘一半装系统、一半存数据，重装系统时不影响数据。
- 不同部分使用不同的文件系统。
- 把系统区和数据区分开，便于管理和备份。

分区只是在**盘上划了线**，记录「从哪个位置到哪个位置属于第几块」。它本身还不包含文件系统。

### 3.3 文件系统：让「文件」这个概念成立

这是今天最重要的一个概念。

**文件系统（File System）** 定义了数据在存储上的组织方式。它负责：

- **命名**：文件叫什么名字。
- **结构**：文件夹的层级关系。
- **定位**：这个文件的第 100 个字节在硬盘的哪个物理位置。
- **权限**：谁能读、谁能写。
- **元数据**：创建时间、大小、修改时间。

**没有文件系统，你只能按「第几个扇区」来读写数据。** 有了它，你才能说「打开 `照片/2024/旅行.jpg`」这样一句话。

这也是为什么**不同文件系统之间常常不能直接互相读写** —— 它们的「档案系统规则」不一样。比如 Windows 常用的 NTFS、Linux 常用的 ext4、NAS 上常见的 Btrfs 和 ZFS，各自的组织方式不同。

格式化，本质就是**在分区上建立一个文件系统**。

### 3.4 卷与存储池：向上一层抽象

- **卷（Volume）**：一个可以被系统挂载、像普通硬盘一样使用的逻辑单元。它可能对应一个分区，也可能是由多块盘组合出来的。
- **存储池（Storage Pool）**：把多块硬盘的容量汇集到一起，再从这个总池子里划分卷。

存储池的价值在于**聚合与灵活**：

```text
3 块 4TB 硬盘
↓ 组成存储池
一个 12TB 的池子
↓ 从中划分
卷 A（2TB）、卷 B（6TB）……
```

**注意：不同厂商对这两个词的叫法不完全一致。** 有的把池叫「存储空间」，有的把卷叫「逻辑卷」「共享文件夹」。**看到不认识的词时，先判断它属于哪一层，比记住具体名字更重要。**

## 4. 技术解释

### 4.1 磁盘（Disk）

物理存储设备，比如一块 8TB 的 HDD 或一块 1TB 的 NVMe SSD。

操作系统把它视为一块**连续的、可按固定大小块寻址的空间**。传统上以扇区（通常 512 字节或 4096 字节）为最小读写单位。

磁盘本身只提供能力，不提供结构。

### 4.2 分区（Partition）

分区表记录磁盘上的分区划分信息，常见的有 MBR 和 GPT 两种格式。

- **MBR**：较老，对分区数量和磁盘容量都有限制。
- **GPT**：较新，支持更大的磁盘和更多分区，是现代系统的默认选择。

分区是**逻辑划分**，不改变物理结构。一块盘分成三个分区，它仍然是一块盘。

### 4.3 文件系统（File System）

文件系统负责在分区之上建立数据组织结构，主要包含：

- **目录结构**：文件和文件夹的层级关系。
- **元数据**：文件名、大小、时间戳、权限等。
- **空间分配**：记录哪些块已用、哪些空闲。
- **日志或校验机制**：部分文件系统（如 ext4、ZFS、Btrfs）带有日志或校验能力，能在异常断电后更快恢复一致性，甚至检测数据损坏。

常见文件系统的定位：

| 文件系统 | 常见场景 |
|---|---|
| NTFS | Windows |
| APFS | macOS |
| ext4 | Linux，成熟稳定 |
| Btrfs | NAS 常用，支持快照和校验 |
| ZFS | NAS 常用，强调数据完整性 |

**注意：文件系统决定了你能用哪些功能。** 比如快照能力，就依赖文件系统是否支持 —— 这是本周 Day 4 的内容。

### 4.4 卷（Volume）

卷是一个**可被挂载的逻辑存储单元**。它向上提供「块设备」的接口，让文件系统可以建立在它之上，或者本身就包含了文件系统。

卷的几种来源：

- 直接来自一个分区。
- 由多个磁盘通过 RAID 组合而成。
- 从存储池中划分出来。

**「挂载」是理解卷的关键**：卷被挂载到某个路径后（比如 `/mnt/data`），其中的内容才出现在文件树里，用户才能访问。

### 4.5 存储池（Storage Pool）

存储池把多块物理磁盘的容量汇集管理，是比卷更上一层的抽象。

它的好处：

- **容量聚合**：不必再关心「哪个文件在哪块盘上」。
- **灵活划分**：可以从池中划分多个卷，按需分配。
- **统一管理**：扩容、快照、校验在池一级统一处理。

不同实现的叫法不同（ZFS 叫 pool、Btrfs 叫 pool、厂商 NAS 可能叫存储空间），但概念是一致的。

### 4.6 完整的层次关系

```text
物理磁盘（1 块或多块）
↓
分区 / 存储池
↓
卷
↓
文件系统
↓
挂载到某个路径
↓
用户看到的「文件夹和文件」
```

**关键认知：用户看到的文件，是这一整条链条最终的结果。** 任何一层出问题，文件都可能访问不到。

## 5. 类比

把存储想象成**建一座图书馆**：

- **磁盘是空地**：有面积，但什么也没有。
- **分区是把空地划成几块地**：一块盖主楼，一块盖仓库。划了线，但还没盖房。
- **文件系统是图书馆的编目系统**：给每本书编号、记录放在哪个书架第几层、谁借走了。**没有编目系统，书堆得再多也找不到。**
- **卷是可以开放的一个馆区**：读者可以进去借书。
- **挂载是把馆区接入整个图书馆网络**：从此它出现在导览图上。
- **存储池是把几块地合并成一个园区统一规划**。

这里最关键的一点：**空地和图书馆的差别，不在于面积，而在于有没有编目系统。** 这就是分区和文件系统的分工 —— 分区只是划线，文件系统才让「找到某本书」成为可能。

## 6. NAS 实际场景

### 6.1 一块新硬盘装进 NAS 会发生什么

```text
1. 物理安装     → 硬盘接上 SATA 或 M.2 接口，但系统只看到「一块新设备」
2. 初始化       → 系统建立分区表
3. 创建文件系统 → 选择 ext4 / Btrfs / ZFS 等
4. 加入存储池   → 与其他硬盘一起组成池（可选）
5. 划分共享文件夹 → 从池中划出卷，挂载给用户访问
```

**第 1 步之后系统看不到可用空间，是正常现象**，不是硬盘坏了。

### 6.2 三个真实问题

**问题一：新硬盘装上去，系统里看不到容量**

先确认到哪一步了。通常的排查顺序：

- 系统是否识别到物理设备（说明接口和供电正常）。
- 是否已建立分区和文件系统（没有的话就还只是一块裸盘）。
- 是否已挂载（没挂载的话有文件系统也访问不到）。

**问题二：为什么 NAS 显示的总容量比硬盘相加要少**

可能有三层原因：

1. **RAID 或存储池的冗余开销**：如果做了 RAID 5，一块盘的容量用于校验，不贡献可用容量。
2. **文件系统自身的开销**：元数据、校验信息会占用一部分。
3. **厂商标注与系统计算方式不同**：硬盘厂商标称容量按十进制，操作系统常按二进制显示，所以 8TB 的盘在系统里显示约 7.3TB。

**这三层要分开看，不要笼统地认为「容量被吃掉了」。**

**问题三：硬盘拆到另一台设备上读不出来**

很可能是文件系统不兼容。不同文件系统的组织规则不同，Windows、macOS、Linux 各自的原生文件系统常常不能互相直接读写。

这直接引出本周 Day 4 的内容：**快照等高级功能依赖文件系统支持**，所以选文件系统不只是选「能不能用」，而是选「能用哪些能力」。

### 6.3 排查时的分层思路

```text
看不到硬盘        →  物理层：接口、供电、硬盘本身
看得到但没容量     →  分区/文件系统层：是否初始化、是否格式化
有容量但进不去     →  挂载层：是否挂载、权限是否正确
能进但文件丢失     →  数据保护层：本周 Day 4–5 的内容
```

**这个分层思路和第 1 周的「硬件 → 操作系统 → 应用」是同一套方法，只是层次更细了。**

## 7. 常见误区

### 误区一：新硬盘插上就能用

不行。新硬盘需要建立分区表和文件系统，否则系统只能看到「有个设备」，不能存文件。这个过程通常叫「初始化」或「格式化」。

### 误区二：分区就是文件系统

不是。分区只是在磁盘上划线，记录范围的起止位置；文件系统才定义文件如何组织和命名。**先分区，再在分区上建文件系统**，是两件事。

### 误区三：格式化只是清空数据

不只如此。格式化的本质是**在分区上建立一个新的文件系统结构**。它会导致原有数据不可访问，但目标不是「删除数据」，而是「建立可用的组织结构」。

### 误区四：所有文件系统都一样

差别很大。不同文件系统在最大容量、快照支持、数据校验、断电恢复能力、跨平台兼容性上都不同。**NAS 上尤其要注意**：想用快照，就必须选支持快照的文件系统。

### 误区五：存储池就是 RAID

不是。存储池是**容量管理**层面的抽象，把多块盘的空间汇集成一个池子；RAID 是**冗余和性能**层面的技术。存储池可以建立在 RAID 之上，但两者解决的不是同一个问题。

## 8. 知识地图

本周从物理层往上一层，进入逻辑存储结构：

```text
存储
├── 物理形态                （Week 2 Day 4–5）
│   ├── 介质：HDD / SSD
│   ├── 连接：SATA / NVMe
│   ├── 外形：3.5 寸 / M.2
│   └── 通道：PCIe / Lane
└── 逻辑结构                ← 本周在这里
    ├── Disk 磁盘           （物理设备）
    ├── Partition 分区       （划分范围）
    ├── File System 文件系统  （组织文件）
    ├── Volume 卷            （可挂载单元）
    └── Storage Pool 存储池   （容量聚合）
        ↓ 之上才是
    用户看到的数据
```

```text

     ↓

     ↓
```

今天只需要真正记住一句话：

> 硬盘提供的是**空间**，文件系统提供的是**结构** —— 从「一块空盘」到「能打开一个文件」，中间要经过分区、格式化、挂载三步；分不清这几层，就分不清故障出在哪一层。
