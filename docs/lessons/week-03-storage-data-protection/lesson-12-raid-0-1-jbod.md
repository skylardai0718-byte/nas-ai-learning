# 第十二课：RAID 0、RAID 1 与 JBOD

> 本课的一句话结论：**RAID 是用多块硬盘换取容量、性能或容错的技术 —— 三样东西通常不能同时拿满，选哪个取决于你最怕失去什么。**

## 1. 今天学习什么

今天要掌握 4 个概念：

1. **RAID**：把多块硬盘组合成一个逻辑单元的技术。
2. **RAID 0**：把数据分散到各块盘上，换取速度和容量，**但没有任何容错**。
3. **RAID 1**：两块盘互为主副，内容完全一样，用一半容量换取容错。
4. **JBOD**：把几块盘串起来当一个大盘用，**既无性能提升也无容错**。

你今天要建立的核心结构是：

```text
RAID 换取的三样东西
├── 容量   →  能用多少空间
├── 性能   →  读写快不快
└── 容错   →  坏一块盘会不会丢数据
```

**关键认知：这三者常常是此消彼长的。** 想要容错，往往要牺牲容量；想要速度和容量都拉满，就没有容错。

## 2. 为什么要学

单块硬盘有两个无法回避的问题：**容量有上限，以及它总有一天会坏。**

RAID 就是应对这两个问题的常见手段。但如果不理解不同级别的取舍，会遇到这些问题：

- 为什么有人说「RAID 0 千万别用在重要数据上」？
- 为什么两块 4TB 硬盘做 RAID 1，只能用 4TB？
- 为什么 JBOD 常被误认为是一种 RAID？
- 为什么硬盘数量一样，不同配置的可用容量差很多？
- 为什么「为了快」和「为了安全」常常要做取舍？

理解这些，才能做出本周最重要的那个判断：

```text
这块数据，我更怕它慢，还是更怕它丢？
```

**这个问题没有统一答案 —— 答案取决于数据本身。** 这一点会在 Day 5 展开。

## 3. 小白解释

### 3.1 RAID 是什么

**RAID** 的英文全称是「独立磁盘冗余阵列」，但名字不重要，你只需要记住它的实际作用：

> **把多块硬盘组合起来，让它们在系统里看起来像一块。**

组合之后能得到什么？通常是这三样中的一到两样：

- **更大的容量**
- **更快的速度**
- **坏一块盘也不丢数据的能力**

### 3.2 JBOD：只是把盘串起来

**JBOD** 是「Just a Bunch Of Disks」的缩写，意思是「就是一堆硬盘」。

它做的事情非常朴素：把几块盘的空间**首尾相接拼成一个大盘**。

```text
盘 1（4TB）+ 盘 2（4TB）= 一个 8TB 的空间
```

用图书馆类比：JBOD 就像把两个书柜并排放在一起，贴上连续的编号。它更方便了，但：

- **没有变快**：不会因为多了个书柜就找得更快。
- **没有更安全**：一个书柜塌了，那部分书就没了。

**JBOD 不是 RAID。** 它没有冗余，也没有性能优化，只是容量的简单相加。

### 3.3 RAID 0：把数据切开分散放

**RAID 0** 把每一份数据**切成小块，轮流分散写到各块盘上**（这个做法叫条带化）。

```text
要写入的数据： ABCD
盘 1:  A  C
盘 2:  B  D
```

好处很明显：

- **速度变快**：两块盘可以同时读写，相当于两个人一起搬东西。
- **容量全用上**：两块 4TB 得到 8TB。

代价也很明显：

- **完全没有容错。** 任何一块盘坏了，整组数据都读不出来了 —— 因为每个文件都被切散在所有的盘上，缺一块就拼不完整。

**打个比方**：RAID 0 像是把一份文件撕成两半，分别放在两个抽屉里。找起来更快（两个抽屉同时翻），但只要有一个抽屉丢了，整份文件就废了。

### 3.4 RAID 1：内容完全一样的两块盘

**RAID 1** 把同一份数据**完整地写到两块盘上**，两块盘的内容始终一模一样。

```text
要写入的数据： ABCD
盘 1:  A B C D
盘 2:  A B C D
```

好处：

- **能坏一块盘**：一块坏了，另一块上还有完整的一份，系统可以继续用。

代价：

- **容量只用一半**：两块 4TB 只能得到 4TB，因为另外 4TB 是副本。
- **写入速度不会提升**：数据要写两份，写入并没有变快（读取可以并行，会略快一些）。

**打个比方**：RAID 1 像是同一份文件复印两份，放在两个抽屉里。丢了任意一个抽屉，你还有一份完整的。

## 4. 技术解释

### 4.1 RAID 的基本原理

RAID 通过两种基本技术实现目标：

- **条带化（Striping）**：把数据分散到多块盘上，并行读写以提升性能。
- **镜像（Mirroring）**：把数据复制到多块盘上，以提供冗余。

不同 RAID 级别的差别，本质上就是**这两种技术怎么组合、有没有额外存校验信息**。

### 4.2 RAID 0

使用条带化，不含任何冗余。

```text
可用容量 = 所有盘容量之和
容错能力 = 0
```

- **性能**：读写性能随盘数提升，是常见级别中最快的。
- **风险**：阵列中任何一块盘故障，整个阵列的数据全部失效。
- **盘数要求**：至少 2 块。

**准确的理解是：RAID 0 不是「提高了安全性」，而是「用安全性换了速度和容量」。** 它的可用性反而比单块盘更差 —— 两块盘的故障概率叠加，而任何一块坏都会导致全部数据丢失。

### 4.3 RAID 1

使用镜像，不含条带化。

```text
可用容量 = 单盘容量（盘数 × 单盘容量 ÷ 2）
容错能力 = 可容忍 1 块盘故障（两盘配置）
```

- **性能**：读取可以并行，通常略有提升；写入需要写多份，不会更快。
- **容量**：利用率 50%，这是换取容错的直接代价。
- **盘数要求**：2 块（4 块可组成两组镜像，可容忍每组各坏一块）。

### 4.4 JBOD

不使用条带化，也不使用镜像，只是空间拼接。

```text
可用容量 = 所有盘容量之和
容错能力 = 0
```

需要澄清的一点：**JBOD 中单块盘的故障，通常只影响该盘上的数据，而不是全部**（因为数据不是分散的，只是按顺序填）。这看起来比 RAID 0 安全，但它**没有任何冗余** —— 坏掉的那块盘上的文件就是彻底没了，无法恢复。

**JBOD 的价值在于灵活**：可以把不同容量的硬盘拼在一起用，而不像 RAID 那样通常要求容量一致。

### 4.5 三者对比

以两块 4TB 硬盘为例：

| 级别 | 可用容量 | 读取性能 | 写入性能 | 能坏几块盘 | 数据受影响的盘损坏 |
|---|---|---|---|---|---|
| JBOD | 8TB | 单盘水平 | 单盘水平 | 0 | 仅损坏盘上的文件 |
| RAID 0 | 8TB | 提升 | 提升 | 0 | 全部数据 |
| RAID 1 | 4TB | 略提升 | 无明显提升 | 1 | 无影响 |

**注意最后一列**：RAID 0 和 JBOD 都「不能坏盘」，但坏盘后的后果不同 —— RAID 0 是全丢，JBOD 是丢一部分。这是 JBOD 常被误解的地方。

## 5. 类比

把数据想象成**重要文件**，硬盘想象成**抽屉**：

- **JBOD**：几个抽屉挨着放，按顺序编号。抽屉多了，能放的资料更多，但找资料的速度没变。**某个抽屉坏了，里面那份就没了，其他抽屉不受影响。**
- **RAID 0**：把每份文件**撕成两半**，一半放抽屉 A、一半放抽屉 B。找文件时两个人同时翻，速度翻倍；但**任何一个抽屉丢了，所有文件都不完整** —— 因为每份文件都同时依赖两个抽屉。
- **RAID 1**：每份文件**复印两份**，抽屉 A 和 B 各放一份完整的。丢了任意一个抽屉，你手上还有完整的文件；但**能装的资料总量只有一半**，因为一半空间用来放复印件了。

这个类比点出了核心：**RAID 0 是「分散」，RAID 1 是「复制」，JBOD 是「堆叠」。** 三种思路，对应三种完全不同的风险特征。

## 6. NAS 实际场景

### 6.1 三种选择的典型用途

```text
JBOD      →  想把不同容量的旧硬盘都用起来
             接受「坏一块丢一部分」的风险

RAID 0    →  数据可以从别处重新获取的场景
             比如临时缓存、可重新下载的媒体

RAID 1    →  重要但容量需求不大的数据
             比如文档、配置、照片原图
```

### 6.2 三个真实判断

**场景一：两块 4TB 硬盘，想存全家照片**

选 **RAID 1**。照片丢了无法重拍，容错的价值远高于那 4TB 容量。

需要确认：这些照片在别处还有没有副本。如果没有，RAID 1 只是第一层保护，仍需备份（Day 4–5）。

**场景二：想用两块旧硬盘（4TB + 8TB）尽量减少浪费**

选 **JBOD**。RAID 通常要求容量一致，混插会按最小容量计算，8TB 盘会有 4TB 被浪费。JBOD 可以把不同容量拼起来。

但要清楚代价：**没有冗余**，坏一块盘就丢那块盘上的数据。

**场景三：做一个存放可重新下载内容的临时空间**

**RAID 0** 可以考虑。影视资源可以重新获取，用速度换容量是划算的。

**但这句判断的前提是「数据可以重新获取」。** 如果是自己拍摄的视频，这个前提就不成立。

### 6.3 做选择时先问一个问题

```text
这份数据如果丢了，我能重新拿到吗？
├── 能    →  可以接受 RAID 0 / JBOD
└── 不能  →  需要 RAID 1 或更好的容错方案
```

**注意：即使选了 RAID 1，也不等于不需要备份。** 这一点是本周 Day 5 的核心，现在只需先记住：**RAID 1 能防硬盘坏，不能防误删。**

## 7. 常见误区

### 误区一：RAID 0 又大又快又安全

前两个对，第三个错。RAID 0 **没有任何冗余**，而且因为数据分散在所有盘上，它的可用性比单块盘更差：两块盘只要坏一块，全部数据就没了。

**RAID 0 是用安全性换速度和容量，不是「全都更好」。**

### 误区二：JBOD 是一种 RAID

JBOD 全称就是「就是一堆硬盘」，它不提供冗余，也不提升性能，只是容量的简单拼接。把它叫成 RAID 会让人误以为有保护。

### 误区三：RAID 1 就是备份

这是本周最重要的伏笔。RAID 1 的两块盘是**实时镜像**的：你误删一个文件，两块盘上同时消失；勒索软件加密文件，两份一起被加密。

**RAID 1 防的是「硬盘坏了」，不防「数据被弄没了」。** Day 5 会完整展开。

### 误区四：硬盘越多越安全

取决于级别。RAID 0 和 JBOD 中，硬盘越多，**任意一块出问题的概率越大**，而后果依然严重。只有带冗余的级别（RAID 1、5、6）才随盘数增加而提升容错。

### 误区五：RAID 1 让写入变快

不会。数据要写两份，写入并没有更快（甚至可能略慢）。RAID 1 提升的是**读取**（可以并行从两块盘读）和**可用性**，不是写入性能。
