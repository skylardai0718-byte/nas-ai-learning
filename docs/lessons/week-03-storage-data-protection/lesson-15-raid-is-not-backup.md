# 第十五课：RAID 不是备份

> 本课的一句话结论：**RAID 保证的是「硬盘坏了，服务不中断」，不是「数据不会丢」—— 前者是可用性，后者是可恢复性，这是两件事。**

## 1. 今天学习什么

今天没有新概念。**本周的六个概念到这里要合成一个整体**：

| 层次 | 概念 | 解决的问题 |
|---|---|---|
| 逻辑结构 | Disk、Partition、File System、Volume、Pool | 硬盘如何变成可用空间 |
| 冗余 | RAID 0 / 1 / 5 / 6、JBOD | 硬盘坏了服务是否中断 |
| 数据保护 | Backup、Snapshot、Sync | 数据没了能否找回 |

你今天要建立的核心判断链：

```text
RAID       →  硬盘坏了还能继续用，但误删会同时发生在所有盘上
快照       →  能快速回到某个时间点，但原存储坏了它也一起没
备份       →  有独立副本，能回到过去，但通常不是即时的
同步       →  让两边一致，方向决定了它是保护还是帮凶
```

**这四条链的共同点：它们各自只管一件事。** 任何一条都不能替代另一条。

## 2. 为什么要学

本周前四天你学了 RAID、备份、快照和同步。但真正的问题不是「它们分别是什么」，而是：

**当有人说「我的数据很安全」时，他到底在说什么？**

最常见的错误推理是这样的：

> “我做了 RAID 1，两块硬盘互为备份，所以数据很安全。”

这句话里有两个错误，而且都是**听起来很合理**的错误：

1. 「互为备份」——RAID 1 是**实时镜像**，不是备份。
2. 「所以很安全」——它只覆盖了硬盘损坏这一种风险。

不理解这一点，会导致真实的损失：有人做了 RAID 觉得万无一失，结果误删了文件，或者中了勒索软件，才发现 RAID 一点忙都帮不上。

**本课的目标就是建立一条清晰的判断链，让你以后看到任何「数据保护方案」时，能立刻问出：它防的是哪一种危险？**

## 3. 小白解释

### 3.1 RAID 1 的「备份」是假的备份

先用一个具体的场景说明。

假设你用两块硬盘做了 RAID 1，存了一份重要的家庭照片。现在：

```text
操作：你误删了这张照片
结果：两块硬盘上同时消失
```

为什么？因为 RAID 1 的工作方式是**实时镜像** —— 你写入任何数据，它立刻同时写到两块盘上；你删除任何数据，它立刻同时在两块盘上删除。

**它没有「过去」。** 两块盘永远是一样的，都反映「当前状态」。

再假设：

```text
操作：勒索软件加密了你的照片
结果：两份都被加密
操作：NAS 被偷走
结果：两块盘一起丢
```

**RAID 1 一点都帮不上忙。** 因为它防的不是这些。

### 3.2 RAID 到底防什么

RAID 只防一件事：**硬盘物理损坏。**

当一块硬盘坏了：

```text
RAID 1：另一块盘上还有完整数据 → 服务继续运行
RAID 5/6：用校验信息重建丢失的数据 → 服务继续运行
```

这时 RAID 的价值是**「不中断」** —— 你的服务不会因为一块盘坏掉就停了，你有时间去买新盘、去替换。

**但它保护的是「服务可用」，不是「数据可恢复」。** 这两个词的区别是本课的核心：

```text
可用性（Availability）  →  服务现在能不能用
可恢复性（Recoverability）→  数据丢了能不能找回来
```

RAID 给的是前者。误删、病毒、被盗损失的是后者。**用前者的手段去解决后者的问题，就是本课要破除的错误。**

### 3.3 一个类比：保安和保险柜

把数据安全想象成**保护一批重要文件**。

- **RAID 是一位保安**：他的职责是「如果有一个人受伤了，立刻换上替补，工作继续」。文件柜坏了、里面的抽屉打不开，他马上补上一个新的，工作不受影响。
- **但如果有小偷进来把文件撕了，或者有人故意把文件烧了，保安帮不上忙** —— 因为文件是「被销毁」了，不是「柜子坏了」。

**备份才是保险柜**：另一份文件锁在另一个地方。不管这边发生什么（被撕、被烧、被偷），保险柜里的那份都还在。

**保安和保险柜都需要，但它们解决的是完全不同的问题。**

## 4. 技术解释

### 4.1 为什么 RAID 1 不能防误删

从机制上说：

RAID 1 的工作方式是**写时镜像**。当文件系统发出「删除文件 X」的指令时，RAID 层把这个写操作**同时应用到两块盘上**。对 RAID 来说，删除和写入没有区别 —— 都是一个写操作，都要同步。

RAID 层**不知道也不关心**上层在做什么。它看不到「文件」这个概念（回想 Day 1：文件是文件系统这一层才有的概念，RAID 在它下面）。它只知道「某个位置要写入某些字节」。

**所以 RAID 无法阻止任何逻辑层面的数据损失。** 它只保证物理层面的读写能继续。

### 4.2 为什么 RAID 也防不住勒索软件和被盗

**勒索软件**：它通过系统正常可访问的路径加密文件。它发出的同样是写操作，会忠实地同步到 RAID 的所有盘上。加密完成后，两块盘上都是加密后的文件。

**设备被盗**：RAID 的所有盘都在同一台设备里。设备被搬走，盘自然一起没了。

**火灾水灾**：同理，所有盘在同一个物理位置。

**这三种风险的共同特征：它们同时影响所有盘。** 而 RAID 的冗余是**盘与盘之间**的，它无法应对「所有盘一起出事」的情况。

### 4.3 四种机制的正确分工

把本周所有机制放在一张表里：

| 机制 | 防什么 | 不防什么 | 恢复速度 |
|---|---|---|---|
| RAID 1 / 5 / 6 | 硬盘物理损坏 | 误删、病毒、被盗、火灾 | 不中断，无需恢复 |
| 快照 | 误删、误改、错误的批量操作 | 硬盘故障、被盗（同机） | 很快 |
| 备份 | 几乎全部（取决于是否离线/异地） | 无（需配合方案设计） | 较慢 |
| 同步 | 多设备内容不一致 | 误删（双向）、病毒 | 快 |

**关键理解**：这张表的价值不在于记住每一格，而在于建立一个提问习惯 ——

> **遇到任何数据保护方案，先问：它防的是哪一格？缺了哪一格？**

### 4.4 常见的漏洞组合

**漏洞一：只有 RAID，没有备份**

```text
防住了：硬盘坏
漏掉了：误删、病毒、被盗、火灾
```

这是最典型的错误。用户觉得自己做了「冗余」，实际上只买了一份保险。

**漏洞二：快照和原数据在同一块盘上**

```text
防住了：误删、误改
漏掉了：硬盘坏、整机故障
```

快照很快很好用，但它和原数据是「同生共死」的关系。

**漏洞三：备份一直在线且可写**

```text
防住了：硬盘坏、误删
漏掉了：勒索软件（会加密联网可写的备份）
```

**只有离线或异地的备份，才能防住勒索软件。**

**漏洞四：双向同步当作备份**

```text
防住了：设备故障（其实也没有——删了就是删了）
漏掉了：误删、病毒（会被忠实同步过去）
```

双向同步的目标是「一致」，它把风险也复制了一份。

### 4.5 一个完整的家用方案

把三层叠加，各自补上对方的漏洞：

```text
第 1 层：RAID 1 / RAID 5
          →  硬盘坏了不中断

第 2 层：定时快照
          →  误删误改能快速回退

第 3 层：异地 / 离线备份
          →  病毒、被盗、火灾的最后保障
```

再配合 **3-2-1 原则**（3 份数据、2 种介质、1 份异地）检查：

```text
3 份：原件 + 快照 + 备份        ✓
2 种介质：硬盘 + 外置硬盘/云     ✓
1 份异地：云备份或异地硬盘       ✓
```

## 5. 类比

本周的内容可以用**一个家庭的防灾准备**来整体理解：

- **RAID 是家里的灭火器**：一间屋子着火了，能快速扑灭，不影响其他房间。但**如果整栋楼都烧了，灭火器也没用**。
- **快照是给每个房间拍的照片**：家具摆错了、东西打碎了，可以照着照片恢复原样。但**照片也存在这栋楼里，楼烧了照片也没了**。
- **备份是把贵重物品的复制品放在亲戚家**：这栋楼发生任何事，亲戚家那份都还在。
- **同步是让两栋楼的布置保持一致**：方便，但如果有人在这栋楼里砸了东西，另一栋楼也会被砸。

于是那句错误推理可以翻译成：

> “我家里有灭火器，所以我的财产很安全。”

**灭火器确实重要，但它只对付火灾这一种情况。** 盗窃、水淹、地震，它都管不了。

**这就是本课的核心：不要把「防住了一种风险」误认为「防住了所有风险」。**

## 6. NAS 实际场景

### 6.1 三个真实的错误推理

**推理一**：“我做了 RAID 1，两块盘互为备份，数据不会丢。”

**问题**：RAID 1 是实时镜像，不是备份。没有任何「历史版本」可以回退，误删会同时发生在两块盘上。它只保证硬盘坏了一块时服务不中断。

**推理二**：“我开了快照，每天一次，所以不用备份了。”

**问题**：快照和原数据在同一个存储系统里。硬盘损坏、NAS 被盗、系统故障时，快照一起失效。快照能很好地应对误删误改，但它不是独立副本。

**推理三**：“我把重要文件同步到云盘，这就是我的备份。”

**问题**：要看同步方式和云盘行为。如果是双向同步，本地误删会传播到云端。只有云盘**保留了历史版本**时，它才具备部分备份价值。而且要确认云端那份不会被本地感染的文件覆盖。

### 6.2 一个排查清单

评估任何 NAS 数据保护方案时，按这四问检查：

```text
问 1：硬盘坏了，服务会不会中断？      →  看有没有 RAID
问 2：误删文件，能不能找回来？         →  看有没有快照或备份
问 3：中了勒索软件，还有干净副本吗？    →  看有没有离线/异地备份
问 4：整台设备被偷，数据还在吗？        →  看有没有异地副本
```

**四个问题全部答「是」，方案才算完整。** 任何一个是「否」，那就是漏洞所在。

### 6.3 关于成本

一个常见的顾虑是：全都做，成本是不是太高？

其实可以按数据分级：

```text
不可替代（家庭照片、文档）
  →  全套保护：RAID + 快照 + 异地备份

可重新获取（影视资源、可下载的软件）
  →  基础配置即可，甚至可以接受无冗余

临时数据（缓存、可重建的索引）
  →  不需要保护
```

**关键是「不可替代」那部分一定要覆盖完整。** 影视资源丢了可以重新下载，家庭照片丢了就是永久损失 —— 这两类数据值得投入的保护力度完全不同。

## 7. 常见误区

### 误区一：RAID 就是备份

本课的核心。RAID 提供的是**可用性**（硬盘坏了服务不中断），备份提供的是**可恢复性**（数据丢了能找回）。RAID 无法防误删、病毒、被盗，因为它对上层逻辑一无所知，只会忠实地把每个写操作同步到所有盘。

### 误区二：RAID 1 的两块盘互为备份

RAID 1 是**实时镜像**：两块盘永远反映同一个当前状态，没有历史。你删了它就一起删，病毒加密就一起加密。**「两份」不等于「两个时间点」。**

### 误区三：快照可以替代备份

快照依赖原存储。原盘坏、整机丢，快照跟着一起没。它的强项是**快速回退**，短板是**不独立**。

### 误区四：同步也是备份的一种

同步的目标是保持一致，不是保留历史。双向同步尤其危险 —— 它会把误删和加密结果忠实地传播到所有同步的设备上。

### 误区五：做了备份就万事大吉

还要看备份是否**离线或异地**、是否**保留多个版本**、以及**有没有实际验证过能恢复**。一个一直联网可写的备份，会被勒索软件一起加密；一个从未测试恢复的备份，可能根本无法使用。
