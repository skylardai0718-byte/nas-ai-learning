# 第五课：NAS、Server、Self-hosting 与 Homelab

> 本课的一句话结论：**Server 是一种角色，Service 是它提供的功能；自己运行和维护这些功能叫 Self-hosting，承载它们的整体环境叫 Homelab。**

## 1. 今天学习什么

今天只掌握 4 个核心概念：

1. **Server（服务器角色）**：当一台计算机持续向其他设备提供资源或功能时，它就在扮演的角色。
2. **Service（服务）**：一台 Server 对外提供的具体功能，例如文件共享、影音播放或照片管理。
3. **Self-hosting（自托管）**：服务运行在自己控制、自己维护的设备上，而不是交给服务商代管。
4. **Homelab（家庭实验室）**：用来学习、实验和运行个人服务的小型环境，一台 NAS 或迷你电脑就可以起步。

你今天要建立的核心结构是：

```text
Physical Computer / NAS
↓ 运行
Operating System
↓ 承载
Services
↓ 提供给
Other Devices / Users

自己管理这些服务 = Self-hosting
用于学习和实验的整体环境 = Homelab
```

这节课会把本周前四课的内容串起来：硬件三层的结构（第 1 课）、四个硬件角色（第 2 课）、数据怎样流动（第 3 课）、以及 NAS 与 DAS、云存储的区别（第 4 课）。

## 2. 为什么要学

如果不理解「角色」和「功能」的区分，以后会很难理解这些问题：

- 为什么一台旧电脑、一台迷你主机，甚至一台 NAS 都能叫 Server？
- 为什么同一台 NAS 上可以同时跑文件共享、影音和照片服务？
- 为什么「用了云」不等于 Self-hosting，而「放在家里」也不一定就是 Self-hosting？
- 为什么别人说自己在搭 Homelab，用的却只是一台旧电脑？
- 为什么这个词看起来像机房术语，其实和家里的设备没什么距离？

理解之后，你才能把「设备」和「角色」分开看：

```text
哪台机器？          → 设备
谁在持续对外提供？   → Server（角色）
提供的是什么？       → Service（功能）
谁在运行和维护？     → Self-hosting 还是托管
在什么环境里实践？   → Homelab
```

这也是后续学习 Linux、Docker、网络服务和各种自托管应用的起点。

## 3. 小白解释

### 3.1 什么是 Server

很多人听到「服务器」，会想到机房里一排排亮着灯的机柜，或者一块很贵的专业硬件。

但 Server 首先不是一个东西的名字，而是一种**角色**。

判断一台计算机是不是在扮演 Server，可以看它是否在做这件事：

```text
持续开机
↓
通过网络等待其他设备的请求
↓
收到请求后，提供资源或功能
```

家里的 NAS 就是一个典型例子：它平时不需要你坐在面前操作，只是安静地待在角落，等手机、电脑或电视来请求文件、影片或照片。只要它在做这件事，它就在扮演 Server。

同样的角色，一台旧电脑、一台迷你电脑也能扮演。「Server」回答的是**它在做什么**，而不是**它长什么样、花了多少钱**。

### 3.2 什么是 Service

Service 是 Server 对外提供的**具体功能**。

同一台 NAS 可以同时提供好几个 Service：

```text
一台 NAS
├── 文件共享        → 让家里的电脑存取文件
├── Jellyfin        → 播放影音
├── Immich          → 备份和浏览照片
└── Pi-hole         → 过滤网络广告
```

这些功能的共同点是：它们不是给 NAS 自己用的，而是**提供给其他设备或用户**。

所以 Server 和 Service 是一对关系：Server 是「提供者」，Service 是「提供出来的东西」。一台设备扮演一个 Server 角色，却可以同时提供很多个 Service。

### 3.3 Self-hosting 和 Homelab

**Self-hosting（自托管）** 描述的是一种**运行与管理方式**：

```text
服务运行在谁的设备上？
↓
自己控制、自己维护 → Self-hosting
交给服务商代管     → 托管服务
```

判断的关键不是「它放在哪里」，而是「**谁来运行和维护**」。把照片交给第三方云端，由对方负责服务器、备份和可用性，那不是 Self-hosting。把自己的一台 NAS 长期开着，自己更新、自己排错、自己决定数据怎么放，那才是 Self-hosting。

**Homelab（家庭实验室）** 描述的是一个**环境**：

> 用于学习、实验和运行个人服务的小型计算环境。

Homelab 的重点是「练习」和「承载」。你可以在里面试着装一个 Jellyfin，玩坏了再重装；也可以先拿一台旧电脑起步，不需要一次到位。它不要求专门的房间，更不要求机架和企业级设备。

两者经常重合：你往往就是在自己的 Homelab 里实践 Self-hosting。但它们回答的是不同问题——Self-hosting 关心「谁在运行和维护」，Homelab 关心「在哪里学习和承载这些服务」。

## 4. 技术解释

### 4.1 Server

从技术上说，Server 描述的是计算机在**客户端—服务器关系**中承担的一端：它监听网络请求，并持续响应这些请求，向客户端提供资源或功能。

这个角色与硬件形态无关。满足以下条件，一台机器就在扮演 Server：

- 长期在线，等待请求；
- 通过网络接受其他设备的请求；
- 收到请求后提供资源或功能。

```text
客户端（手机 / 电脑 / 电视）  →  发出请求
                                        ↓
Server（NAS / 旧电脑）        →  响应并提供资源
```

一台机器也可以既是客户端又是 Server：NAS 向电视提供影片时是 Server，同时它去云端同步数据时又成了客户端。

### 4.2 Service

Service 是运行在操作系统之上、对外提供某一项具体功能的程序或功能单元。

```text
Physical Computer / NAS
↓ 运行
Operating System
↓ 承载
Services
↓ 提供给
Other Devices / Users
```

几个要点：

- Service 由操作系统承载，操作系统负责管理它的运行环境、权限和网络。
- 一台设备可以同时承载多个 Service。
- Service 面向的是「其他设备或用户」，不是本机自己。
- 某个 Service 出问题，通常不代表整台设备出问题——这是第 1 课「分层理解故障」的延续。

### 4.3 Self-hosting

Self-hosting 是一种运行与管理方式：服务的运行环境由使用者自己控制和维护。

它的关键判断标准是**控制权**，而不是地理位置：

```text
由自己运行和维护   → Self-hosting
由服务商运行和维护 → 托管（hosted）服务
```

自托管意味着你要自己负责更新、配置、备份和故障处理。它带来更多控制权和灵活性，也带来更多维护责任——这是一个权衡，而不是单纯的「更好」。

### 4.4 Homelab

Homelab 是一个用于学习、实验和运行个人服务的小型环境。

它的特征：

- 规模小：一台 NAS、一台迷你电脑，甚至一台旧电脑就可以起步；
- 目的是学习与实验：允许试错，允许推倒重来；
- 可以承载个人服务：也就是在这个环境里实践 Self-hosting；
- 不绑定特定硬件等级：机架和企业级设备不是前提。

Homelab 是一种**实践环境**的定位，所以它的门槛由你的目标决定，而不是由设备清单决定。

### 4.5 四个概念与前三课的关系

```text
第 1 课：NAS 是计算机
        ↓ 计算机分三层，Service 位于应用层
第 2 课：四个硬件角色（CPU / RAM / Storage / Network）
        ↓ 它们支撑所有 Service 运行
第 3 课：数据流与瓶颈
        ↓ 一次请求怎样穿过三层
第 4 课：NAS / DAS / 云存储
        ↓ 存储由谁管理
第 5 课：Server（角色）/ Service（功能）
        / Self-hosting（谁维护）/ Homelab（在哪实践）
```

## 5. 类比

继续用第 1 课的**数字图书馆**来理解：

- **硬件是实体设施**：房屋、书架、工作台和通信设备。
- **操作系统是管理体系**：决定资料放在哪里、谁能访问、设施如何协调。
- **Service 是图书馆提供的具体服务**：借阅、书目检索、预约、影音室、照片档案馆。

在这个类比里：

- 图书馆面向读者**持续提供**借阅和检索，所以它在这件事里就是那个「提供服务的一方」——这对应 **Server 角色**。角色由「持续对外提供」决定，和楼大不大、装修贵不贵无关。
- 借阅、检索、影音室、照片档案馆是**不同的服务项目**——这对应 **Service**。同一座图书馆可以同时开放好几个窗口。
- **Self-hosting** 就像「这所图书馆由你自己出资、自己管理」：馆藏怎么分类、什么时候开门、谁能借，都由你决定，也由你负责维护；而不是把书全托管给外面的连锁机构，由对方替你运营。
- **Homelab** 就像「你先在家里搭一个小书架做试点」：用来练习怎么编目、怎么出借、怎么处理丢书，不必一开始就盖一栋大楼。

所以请记住这句话的类比版本：

> 提供服务的一方是 Server，提供的每一项服务是 Service，自己管理这座图书馆是 Self-hosting，而你先用来练手的那个小书架就是 Homelab。

## 6. NAS 实际场景

假设家里有一台 NAS，它同时在做这些事：

```text
NAS（一台计算机）
├── 文件共享        ← 电脑存取文件
├── Jellyfin        ← 电视和手机播放影片
├── Immich          ← 手机自动备份照片
├── Pi-hole         ← 全屋设备过滤广告
└── Tailscale       ← 在外网安全访问上面的服务
```

按今天学的概念拆开看：

- **设备**：就是这台 NAS，它是一台完整的计算机（第 1 课）。
- **Server 角色**：因为它持续向家里其他设备提供资源或功能，所以它在这件事里扮演 Server。注意——它扮演这个角色，靠的是「持续对外提供」，不是因为它叫 NAS。
- **Service**：文件共享、Jellyfin、Immich、Pi-hole 各自都是一个 Service，说明一台设备可以同时承载多个服务。
- **Tailscale**：它是让外网设备也能访问这些服务的连接方式，让「其他设备」不限于家里。
- **Self-hosting**：这些服务由你自己安装、更新、排错和备份，运行在你控制的设备上——这就是 Self-hosting。
- **Homelab**：如果这台 NAS 同时还是你试装软件、练习排错的地方，那它也就承担了 Homelab 的角色。

再看三个判断场景：

- **同一台 NAS 上 Immich 打不开，但文件共享正常**：按第 1 课的分层思路，问题可能只在 Immich 这一个 Service，不是整台设备坏了。
- **把照片交给第三方云端保存**：那是托管服务，不是你自己的 Self-hosting，因为运行和维护都由服务商负责。
- **用一台旧电脑长期给家人提供照片服务**：它也在扮演 Server，如果由你自己维护，同样构成 Self-hosting 和 Homelab 的起步环境。

分层和分角色的价值是：**不要把「设备」「角色」「服务」「谁来维护」混成一句话。**

## 7. 常见误区

### 误区一：Server 只指专门生产的大型服务器硬件

Server 首先是**角色**而不是某类硬件。一台 NAS、一台迷你电脑、一台旧电脑，只要持续向其他设备提供资源或功能，就在扮演 Server。硬件的价格和外形不决定它是不是 Server。

### 误区二：一台 NAS 只能干一件事

一台 NAS 可以同时提供多个 Service，例如文件共享、Jellyfin、Immich 和 Pi-hole。它扮演的是一个 Server 角色，但对外提供的功能可以有多个。

### 误区三：把应用部署在第三方云端也算 Self-hosting

Self-hosting 的关键是**运行和维护由自己控制**。放在第三方云端、由服务商负责运行的系统属于托管服务，不是自托管。判断标准是「谁来管」，不是「放在哪」。

### 误区四：搭建 Homelab 必须购买机架和企业级设备

Homelab 是一个用于学习、实验和运行个人服务的小型环境，一台 NAS 或一台迷你电脑就可以起步。机架和企业级设备不是前提，规模由你的目标决定。

### 误区五：Server 和 Service 是同一件事

Server 是提供者，Service 是提供出来的功能。同一台设备扮演一个 Server 角色，却可以同时提供很多个 Service。把两者当成同一件事，就没法解释「一台 NAS 同时跑好几个服务」。

## 8. 知识地图

这是 Week 1 的完整知识地图，把五天的内容串在一起：

```text
计算机（第 1 课）
├── 硬件（第 1 课）
│   └── 四个硬件角色（第 2 课）
│       ├── CPU        做事：执行指令与运算
│       ├── RAM        临时工作区：暂存正在使用的数据
│       ├── Storage    长期保存：硬盘、SSD
│       └── Network    对外连接：网卡与数据进出
├── 操作系统（第 1 课）
│   └── 管理硬件、文件、用户权限和网络
└── 应用层（第 1 课）
    └── Service（第 5 课）
        ├── 文件共享
        ├── Jellyfin
        ├── Immich
        └── Pi-hole
```

```text
数据流（第 3 课）
用户 → 应用（Service） → 操作系统 → 硬件
        ↑ 每一段都可能成为瓶颈，实际表现由最慢的一段决定
```

```text
存储方案（第 4 课）：Storage 的三种对外方式
├── DAS            直接连接一台设备（USB 等）
├── NAS            接入网络，给多台设备访问
└── Cloud Storage  数据在服务商的远程系统里
```

```text
角色与方式（第 5 课）
一台计算机持续向其他设备提供资源或功能  = Server（角色）
它对外提供的每一项具体功能              = Service
自己运行和维护这些服务                  = Self-hosting
用来学习、实验和承载这些服务的整体环境  = Homelab
```

把第 5 课的结构单独画出来，就是本课开头那张图：

```text
Physical Computer / NAS
↓ 运行
Operating System
↓ 承载
Services
↓ 提供给
Other Devices / Users

自己管理这些服务 = Self-hosting
用于学习和实验的整体环境 = Homelab
```

注意这张图没有引入任何新硬件——它只是给前三课的「计算机三层」换了一个看问题的角度：

```text
第 1–4 课问：这台机器由什么构成、数据怎么流、存储归谁管
第 5 课问  ：它在对谁提供什么、由谁维护、在什么环境里实践
```

本周只需要真正记住一句话：

> NAS 是一台计算机；当它持续向其他设备提供功能时，它就在扮演 Server，它提供的每一项功能是 Service；自己运行和维护这些服务是 Self-hosting，而用来学习和承载它们的整体环境就是 Homelab——一台 NAS 或一台迷你电脑就足够起步。
