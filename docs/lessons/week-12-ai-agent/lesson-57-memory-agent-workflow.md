# 第五十七课：记忆、Agent 与 Workflow

> 本课的一句话结论：**Agent = LLM + 工具 + 记忆 + 循环 —— 它是一个由你画出边界的系统，而不是一个万能且完全自主的程序；能写死的流程，就别交给它即兴发挥。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **记忆（Memory）**：把上下文之外的信息，在需要时重新送进模型的视野。
2. **Agent（智能体）**：LLM + 工具 + 记忆 + 循环，组成的「会自己做几步」的系统。
3. **Workflow（工作流）**：步骤由人预先写死，每次都一样。

你今天要建立的核心结构是：

```text
Agent  =  LLM  +  工具  +  记忆  +  循环

          会说话   会做事   记得住   会自己走下一步
```

以及本周第二重要的一条区分：

```text
Workflow  →  步骤由人写死：A → B → C
Agent     →  步骤由模型决定：走几步、走哪条路都不一定
```

## 2. 为什么要学

昨天你知道了模型怎么申请调用工具。但只有工具还不够 —— 你会发现它还缺两样东西：

- 为什么模型不记得我上一句说了什么？
- 为什么有的 AI 能自己连着做好几步，有的只能一问一答？
- 为什么同一个任务，有时用固定流程更靠谱？
- 为什么「AI 全自动帮我打理 NAS」听起来很吸引人，实际很危险？

不理解记忆和循环，你会把 Agent 想象成一个「什么都能自己搞定」的东西，
从而既高估了它的能力，也低估了它的风险。

**今天的核心任务是破除误解：Agent 不是万能的、完全自主的程序。**
它的每一步能力，都来自你明确给它的东西 —— 你给什么，它才有什么。

## 3. 小白解释

### 3.1 模型的「失忆」是天生的

先看一个现象：

```text
第 1 轮：我下周要交报修单
模型：好的，我记下了
第 2 轮：那份单子什么时候交？
模型：哪份单子？
```

这不是模型「不上心」，而是它的工作机制决定的：**它只看得到这一次交给它的内容。**

```text
模型的视野 = 这一次提问里包含的所有文字
视野之外  = 它不知道，也不记得
```

### 3.2 记忆是「把话说回来」

既然模型看不到视野之外的东西，那就**在需要的时候，把那些东西重新塞进去**。这就是记忆。

```text
不用记忆：
  第 2 轮只送「那份单子什么时候交？」
  → 模型不知道「那份」指什么

用了记忆：
  第 2 轮把「上一轮的对话 + 这一句」一起送进去
  → 模型看到前文，就知道你在说什么
```

所以「记忆」并不是模型真的记住了什么，而是**每次都把旧内容重新递到它面前**。

> **注意边界**：能递进去的内容是有限的（这就是 Week 10 学的上下文长度）。
> 记忆不是无限的，也正因如此，才需要挑选「哪些旧内容值得递回去」。

### 3.3 循环：让模型自己走下一步

有了工具和记忆，还差最后一块 —— **循环**。

普通的问答是一问一答：

```text
问 → 答。结束。
```

Agent 是：

```text
想 → 调用工具 → 看结果 → 再想 → 再调用 → …
直到它认为可以回答了
```

```text
用户：把 docs 目录里最新的文件内容总结一下
  ↓
Agent：申请 list_files        → 看到 3 个文件
  ↓
Agent：申请 read_file（最新的那个） → 拿到内容
  ↓
Agent：内容够了 → 输出总结
```

**走几步、走哪条路，都是模型自己判断的。** 这就是「循环」带来的灵活性。

### 3.4 但 Agent 不是万能的

现在可以说清楚那个常见的误解了。很多人以为 Agent 是「一个能自己搞定一切的智能程序」。

**实际上它的每一样能力都是你给的：**

```text
它有多聪明   →  取决于你用的模型
它能做什么   →  取决于你给的工具
它记得什么   →  取决于你递回去的内容
它能走多远   →  取决于你允许它循环几次
```

**它的边界是你画的。** 你没给的工具，它申请不了；你没让它看的目录，它看不到。

### 3.5 Workflow：另一种选择

并不是所有「多步任务」都该交给 Agent。有一类做法叫 **Workflow（工作流）**：
**步骤由人预先写死。**

```text
Workflow：每天 9 点 → 读日志 → 提取错误行 → 生成表格 → 发邮件
          （步骤固定，每次都一样，不用模型判断）

Agent   ：你看着办
          （模型自己决定走几步、走哪条路）
```

**什么时候用哪个？**

```text
流程明确、步骤固定  →  Workflow（可预测、好排查、风险低）
情况多变、需要判断  →  Agent（灵活，但更难控制）
```

**核心判断：能写死的流程，就不要交给模型即兴发挥。**

## 4. 技术解释

### 4.1 记忆的几种形式

记忆大致可以分两类：

| 类型 | 保存什么 | 特点 |
|---|---|---|
| 短期（对话内） | 本轮对话的历史 | 就是上下文，随对话结束而消失 |
| 长期（外部存储） | 存到文件或数据库里的信息 | 需要时检索出来，再放回上下文 |

**长期记忆的关键在「怎么找到该递回去的那部分」** —— 全塞进去既放不下也没必要。
这个「找出来」的动作，和 Day 3 要学的检索是同一个思路。

### 4.2 Agent 的循环

一个典型的 Agent 循环包含几步：

1. **思考**：根据当前信息，判断下一步做什么。
2. **行动**：输出调用意图（可能调用工具，也可能直接回答）。
3. **观察**：拿到工具返回的结果。
4. **判断**：信息够了吗？不够就回到第 1 步。

**终止条件非常重要。** 如果没有限制，循环可能一直转下去。因此实践中通常要限制：

```text
最多循环几步
最多调用几次工具
总共可以花多久
```

**没有上限的循环，是 Agent 最现实的风险之一** —— 它可能反复申请同一个操作。

### 4.3 Agent 与 Workflow 的取舍

| 维度 | Workflow | Agent |
|---|---|---|
| 步骤由谁决定 | 人预先写死 | 模型每步判断 |
| 可预测性 | 高 | 低 |
| 排查难度 | 低（步骤固定） | 高（路径不定） |
| 灵活性 | 低 | 高 |
| 风险 | 低 | 高 |
| 适合 | 重复、明确的流程 | 情况多变、需要判断的任务 |

**注意这不是「谁更高级」的问题。** 一个稳定的 Workflow 通常比一个 Agent 更可靠，
只是它应对变化的能力差。选择依据是任务本身，不是技术新不新。

### 4.4 为什么 Agent 更难控制

三个原因：

- **路径不确定**：你不知道它这次会走哪条路，测试很难覆盖全。
- **错误会累积**：第一步理解偏了，后面几步可能一路偏下去。
- **会调用工具**：每一步都可能产生真实的副作用（Day 1 讲的「外部程序真的会动手」）。

**所以对 Agent 的信任，应该建立在你给它的边界上，而不是建立在它的表现上。**

### 4.5 Agent 的能力上限

```text
Agent 的能力 =  模型的判断力
              ∩  工具提供的动作
              ∩  记忆提供的上下文
              ∩  循环允许的次数
              ∩  权限允许的范围
```

**这五项里，只有第一项是模型自带的，其余四项都由你决定。** 这也解释了为什么「换个更强的模型」
并不总能解决问题 —— 如果工具、权限、循环次数没配好，换模型也无济于事。

## 5. 类比

把 Agent 想象成一个**刚入职的助理**：

- **LLM 是他的脑子**：聪明、会说话，但对你的公司一无所知。
- **工具是他的门禁卡**：有哪几扇门能进，取决于你给他配了什么权限。没配的门，他进不去。
- **记忆是他的笔记本**：他本身不记事，靠翻笔记才知道「上周你说过什么」。
- **循环是他的工作方式**：接到任务后，他自己决定先做哪一步、要不要再来一轮。
- **你给他的边界，就是他的职权范围。**

**这个类比能解释什么？**

它一下子解释了两件容易混淆的事。

第一，**新人不是万能的**。他再聪明，没门禁卡也进不了机房 —— Agent 的能力，取决于你给的工具和权限。

第二，**「他自己决定怎么做」和「他可以随便做」是两回事**。助理可以自己安排工作顺序，
但不能因此就能推开任何一扇门。**自主的是「怎么做」，被约束的是「能做什么」。**

而且你还会想到：如果这个任务步骤明确、重复发生（比如每月整理一次报表），
与其让助理每次自由发挥，不如给他一张固定的清单 —— 这就是 Workflow 的价值。

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：一个「每天整理下载目录」的任务该怎么做**

```text
人写死的 Workflow：
  每天 2:00 → 扫描 /volume1/downloads → 按扩展名分类 → 写日志
  → 步骤固定、结果可预测、出问题好排查  ✓ 推荐

交给 Agent 自由发挥：
  「你自己看看这个目录该怎么整理」
  → 可能判断不同、可能反复调用、可能误移动文件  ✗ 风险高
```

**判断：流程明确的任务，用 Workflow。** 不是因为 Agent 做不到，而是因为不需要它的灵活性，
却要承担它的风险。

**场景二：一个「问我 NAS 上文档讲了什么」的任务**

```text
需要 Agent 的理由：
  问题不固定（用户想问什么不一定）
  需要判断「找哪个文件、读几段、够不够」
  → 灵活判断确实有价值  ✓ 适合 Agent

但仍要限制：
  最多读几个文件
  只在指定目录内读（Day 4 详述）
  不能写、不能删
```

**判断：任务需要判断题，Agent 才有价值；但有价值不等于可以放开权限。**

**场景三：为什么 Agent 会「转圈」**

它可能在反复申请同一个操作：读了文件、没找到答案、又读一遍。
这是「循环没有终止条件」的典型表现。

```text
→ 设计时要设上限：最多几轮、最多几次调用
→ 转圈本身不危险，但如果每轮都在做写操作，就很危险
```

### 6.2 Agent 与 Workflow 对照

| 任务 | 更适合 | 原因 |
|---|---|---|
| 每天固定时间整理日志 | Workflow | 步骤固定，不需要判断 |
| 回答关于一堆文档的随机提问 | Agent | 问题不固定，需要判断 |
| 按固定规则把照片归档 | Workflow | 规则明确，可预测 |
| 帮我找出某个报修问题的相关记录 | Agent | 需要检索与判断 |

**这张表想说明的是**：Workflow 和 Agent 不是新旧关系，而是「固定」与「灵活」的取舍。

### 6.3 一句话提醒

```text
Agent 的自主，是「怎么做」的自主；
它「能做什么」，永远由你画的边界决定。
```

## 7. 常见误区

### 误区一：Agent 是万能且完全自主的程序

这是本周最需要破除的误解。Agent 的能力完全来自你给它的四样东西：模型、工具、记忆、
循环次数。**你没给的，它做不了。** 它不是自己长出能力来的，而是被组装出来的。

### 误区二：记忆意味着模型真的记住了

不是。模型本身不存储任何对话。所谓记忆，是**每次把旧内容重新递回它的视野**。
这也是为什么记忆有上限 —— 上下文放不下那么多东西。

### 误区三：Agent 一定比 Workflow 高级

不对。它们解决的是不同问题。**流程固定时，Workflow 通常更可靠、更好排查、风险更低。**
技术新不新不是选择的依据，任务适不适合才是。

### 误区四：循环次数越多，Agent 就越聪明

循环次数多只意味着它能走更多步，不意味着走得更对。**没有上限的循环反而会带来风险** ——
比如反复执行同一个写操作。设计时要主动设上限。

### 误区五：换个更强的模型就能解决 Agent 的问题

很多时候问题不在模型，而在工具太少、记忆没接好、权限开得太大、或者循环没设限。
**这五项里有四项由你决定**，换模型只动了其中一项。
