# 第四十四课：虚拟机、Hypervisor 与 VM vs Docker

> 本课的一句话结论：**虚拟机和 Docker 容器都能在一台机器上隔离地运行程序，但虚拟机自带一个完整操作系统、隔离更强、开销更大；Docker 共用宿主机内核、更轻更快、隔离较弱 —— 选哪个取决于你是否需要独立操作系统，而不是哪个更「先进」。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **虚拟机（Virtual Machine，VM）**：在一台物理机上模拟出的一台完整计算机。
2. **Hypervisor（虚拟机管理程序）**：创建和运行虚拟机的软件层。
3. **VM vs Docker**：两种隔离方式的准确比较。

你今天要建立的核心结构是：

```text
物理机（真硬件）
└── Hypervisor          （切分资源的软件层）
    ├── VM 1            （完整操作系统 + 应用）
    ├── VM 2            （完整操作系统 + 应用）
    └── VM 3            （完整操作系统 + 应用）
```

以及一个关键对照：

```text
                 VM                        Docker
是否带完整 OS    带（每台一个内核）          不带（共用宿主机内核）
隔离程度         很高（硬件级）              较强（进程级）
资源开销         大（每台都要跑一个 OS）     小（只跑进程）
```

## 2. 为什么要学

前面几周你一直在学 Docker，可能会以为「容器就是唯一的隔离方式」。**其实不是 —— 虚拟机是另一种隔离方式，而且它出现得更早、隔离更彻底。**

理解两者的差别，才能回答一个很实际的问题：**这个服务，我到底该用 Docker 装，还是该开一台虚拟机？**

不懂这两者的区别，会遇到这些问题：

- 为什么有的教程让你装 Docker，有的却让你先装个 Proxmox？
- 为什么说「Docker 更轻」不等于「Docker 更好」？
- 为什么我想在 NAS 上跑一个完全不同的操作系统，Docker 做不到？
- 为什么虚拟机启动起来比容器慢那么多？
- 为什么同样一个应用，装在 VM 里和装在容器里，资源占用差好几倍？

**这一课的核心不是「谁更好」，而是「什么场景该用谁」。** 这是本周六问法里第③问「运行在哪里」的完整答案。

## 3. 小白解释

### 3.1 虚拟机：在一台电脑里「隔出」好几台电脑

想象你有一台性能不错的电脑。虚拟机做的事，是**在这台电脑里，用软件「隔」出好几台看起来完全独立的电脑**。

```text
你的物理机（一台真电脑）
├── 虚拟机 A  →  看起来是一台独立的电脑，有自己的系统
├── 虚拟机 B  →  另一台独立的电脑
└── 虚拟机 C  →  再一台
```

每台虚拟机都**以为自己独占了一台真机器**：有自己的操作系统、自己的文件、自己的网络。但它们其实共用同一台物理机的 CPU、内存和硬盘。

### 3.2 Hypervisor：负责「隔」和「分」的那个东西

**Hypervisor（虚拟机管理程序）** 就是干这件事的软件。它负责：

```text
把物理机的资源  →  切分给各个虚拟机
并保证            →  虚拟机之间互不干扰
```

你可以把它理解成**一个分房子的管理员**：把一栋楼分成几套独立的公寓，每套有自己的门锁，租户之间互不打扰。

### 3.3 那 Docker 是什么？区别在哪

Docker 也能「隔离」，但方式完全不同：

```text
虚拟机：给你隔出一整台电脑（连操作系统都给你一份新的）
Docker：不给你新电脑，只把你的程序「圈」在一个小盒子里
```

**最直观的差别是——是否带一个完整的操作系统：**

- 虚拟机：每台都带一个完整的操作系统（这是它重、但隔离强的原因）。
- Docker：所有容器**共用宿主机的操作系统内核**，只隔离程序本身（这是它轻、但隔离弱的原因）。

## 4. 技术解释

### 4.1 虚拟机的定义与构成

**虚拟机**是在物理硬件之上，由软件模拟出来的一台计算机。它包含：

- **虚拟 CPU、虚拟内存、虚拟硬盘、虚拟网卡** —— 由 Hypervisor 从物理资源中切分而来。
- **一个完整的操作系统（Guest OS）** —— 客户机操作系统，和宿主机可以是不同的系统。
- **运行在这个操作系统上的应用**。

**关键点：VM 里的应用，看到的是一个「完整、独立」的计算机环境** —— 包括自己的内核。这就是为什么 VM 能做到很强的隔离。

### 4.2 Hypervisor 的作用

**Hypervisor** 是位于物理硬件和虚拟机之间的软件层，负责：

- 创建、启动、停止虚拟机；
- 把 CPU 时间、内存、存储、网络分配给各台虚拟机；
- 隔离各虚拟机，让它们互不影响。

有两种常见形态：

```text
Type 1（裸机型）：Hypervisor 直接装在硬件上，上面跑虚拟机
Type 2（宿主型）：Hypervisor 装在某个操作系统之上
```

家庭场景里，专门的虚拟化平台通常是 Type 1。

### 4.3 VM 和 Docker 的三个核心差别

这是本课最重要的部分，必须讲准：

**差别一：是否带完整的操作系统**

```text
VM     →  每台 VM 都有自己的内核和完整的操作系统
Docker →  所有容器共用宿主机的内核，容器里只有应用和依赖
```

这一条是最根本的差别，它直接导致了后面两条。

**差别二：隔离程度**

```text
VM     →  硬件级隔离，非常强，一台 VM 被攻破很难影响其他 VM
Docker →  进程级隔离，较强，但共享内核 —— 内核出问题会影响所有容器
```

隔离强度的差别，来自「是否共享内核」。共享内核带来了效率，也带来了隔离上的妥协。

**差别三：资源开销**

```text
VM     →  开销大：每台 VM 都要跑一个完整的操作系统（占内存、占磁盘、启动慢）
Docker →  开销小：只跑应用进程，共享内核，启动快、占资源少
```

### 4.4 为什么不能说「Docker 更轻所以更好」

这是最容易出错的一条，必须讲清楚：

```text
Docker 的优势：轻、快、省资源、部署方便
Docker 的代价：隔离较弱、不能换内核、不能跑异构操作系统

VM 的优势：隔离极强、可以跑完全不同的操作系统、环境完全独立
VM 的代价：重、慢、占资源
```

**选择依据是需求：**

- 需要**跑一个和宿主机内核不同的操作系统**？→ 只能 VM，Docker 做不到。
- 需要**极强的隔离**（比如跑不信任的代码）？→ VM 更合适。
- 只是想**方便地部署、升级一个应用**？→ Docker 更合适。
- 资源有限，想**多跑几个服务**？→ Docker 更省。

**「更轻」只是一个维度，不是全部。** 拿「更轻」直接推出「更好」，是忽略了另外两个维度。

### 4.5 Hypervisor 的边界（它不告诉你什么）

- 它**不保证性能**：虚拟机拿到的资源是切分来的，性能通常低于同等物理机。
- 它**不解决配置**：装了 Hypervisor 只是有了跑虚拟机的能力，具体怎么用还是你的事。
- 它**有硬件门槛**：虚拟化通常需要 CPU 支持特定功能，不是所有机器都行。
- 它**不替你选**：Hypervisor 提供了 VM 这个选项，但「该用 VM 还是 Docker」，仍然要你来判断。

## 5. 类比

把物理机想象成**一块地皮**。

```text
虚拟机   →  在地皮上盖几栋独立的房子
            每栋有独立的水电、独立的门锁、独立的住户
            好处：互不干扰、可以完全不同的户型
            代价：每栋都要单独通水通电（每台 VM 都要一个 OS）

Docker   →  在同一个房子里隔出几个房间
            共用同一套水电（共用宿主机内核），只是门锁分开
            好处：省材料、盖得快
            代价：共用一套水电，一户水管爆了可能影响全楼
```

**这个类比能解释什么？**

- 它解释了**为什么 VM 隔离更强**：独立房子 vs 共用同一套房子的房间。
- 它解释了**为什么 VM 开销大**：每栋房子都要单独通水电，这是「带完整操作系统」的代价。
- 它解释了**为什么 Docker 更方便**：盖房间比盖房子快得多。
- 它解释了**为什么不能说「Docker 更好」**：如果你就是需要一栋和邻居完全不相干的独立房子（跑不同操作系统、要强隔离），隔出来的房间满足不了 —— **需求决定选择。**

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：想在 NAS 上跑一个影音服务，用 VM 还是 Docker？**

用 Docker。这是一个应用，没有「换操作系统」的需求，Docker 更省资源、升级更方便。**开一台 VM 只为了跑一个应用，是典型的「杀鸡用牛刀」** —— 白白多背了一个操作系统的开销。

**场景二：想体验一个完全不同的操作系统**

必须用 VM。**Docker 容器共用宿主机内核，跑不了和宿主机内核不同的系统。** 这是「是否带完整操作系统」这条差别的直接后果 —— 这是 Docker 做不到、VM 才能做的事。

**场景三：一台机器想跑好几个互相隔离的实验环境**

考虑 VM（甚至专门的虚拟化平台，下一课讲）。因为实验环境往往需要**强隔离**和**独立的系统环境**，这正是 VM 的强项。**代价是资源开销大**，所以机器配置要跟得上。

### 6.2 VM vs Docker 对照表

| 维度 | VM | Docker 容器 |
|---|---|---|
| 是否带完整操作系统 | 带，每台一个内核 | 不带，共用宿主机内核 |
| 隔离程度 | 很高（硬件级） | 较强（进程级） |
| 资源开销 | 大（每台跑一个 OS） | 小（只跑进程） |
| 启动速度 | 慢 | 快 |
| 能否换操作系统 | 能 | 不能 |
| 适合的场景 | 强隔离、异构系统、独立环境 | 应用部署、快速升级、省资源 |

**记住这张表的用法：不是比谁分高，而是看你的需求落在哪几行上。**

## 7. 常见误区

### 误区一：Docker 和 VM 是一回事，只是叫法不同

不对。**它们是最根本的区别：是否带完整操作系统。** VM 每台都有独立内核，容器共用宿主机内核。这条差别导致了隔离程度、资源开销、启动速度上的全部不同。

### 误区二：Docker 更轻量，所以在所有场景下都比 VM 更好

错。**「更轻」只是一个维度。** 当你需要跑不同的操作系统、或者需要极强的隔离时，Docker 根本做不到 —— 这时「更轻」帮不上忙。**选择看需求，不看谁更先进。**

### 误区三：VM 里也可以共用宿主机的内核

不对。**每台 VM 都自带一个完整的操作系统和内核**，这正是它重、但隔离强的原因。共用内核的是 Docker 容器，不是 VM。把这两者搞混，整个比较就乱了。

### 误区四：Hypervisor 是一个操作系统

不准确。**Hypervisor 是运行在硬件和虚拟机之间的一层软件**，它的职责是切分资源和隔离虚拟机 —— 它上面跑的那些虚拟机，才各自运行着操作系统。

### 误区五：隔离越强越好，所以应该尽量用 VM

不对。**隔离强度是有代价的 —— 资源开销、性能、管理复杂度。** 对一个普通的家庭应用来说，Docker 的隔离已经足够，用 VM 只会白白浪费资源。**「够用」比「最强」更实际。**
