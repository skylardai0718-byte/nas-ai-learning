# 第四十三课：Pi-hole、Immich 与 Tailscale

> 本课的一句话结论：**同一套六问法，用来分析三个完全不同层次的服务 —— Pi-hole 在网络层拦广告、Immich 在应用层管照片、Tailscale 本身就是一条访问通道 —— 你会看到框架不变，但答案因服务而异，而它们的共同点是都接触隐私数据。**

## 1. 今天学习什么

今天继续用六问法，快速分析三个不同类型的服务：

1. **Pi-hole**：在网络层拦截广告和追踪域名。
2. **Immich**：自建的照片与视频备份服务，替代云相册。
3. **Tailscale**：一条安全访问内网的通道（第五周学过原理）。

你今天要建立的核心结构是：

```text
三个服务分别在系统的哪一层

Pi-hole   →  网络层（它本身就是 DNS 服务）
Immich    →  应用层（它是个应用，且由多个容器组成）
Tailscale →  通道层（它提供的是连接，不是功能）
```

以及一个共同点：

```text
三个服务都接触隐私数据
Pi-hole   →  全家的访问域名记录
Immich    →  私人照片和视频
Tailscale →  登录密钥和网络拓扑
```

## 2. 为什么要学

昨天你分析的是「影音服务」这一类。今天要拓宽视野：**同样是六问，答案可以差得很远。**

更重要的是，这三类服务代表了三种完全不同的问题：

- Pi-hole 让你意识到：**有些服务不在应用层，而在网络层** —— 它影响的是整个网络的行为。
- Immich 让你意识到：**有些服务本身就是由多个容器组成的**，Docker 不是可选项，而是它工作的前提。
- Tailscale 让你意识到：**有些东西根本不是「服务」，而是一条通道** —— 用分析服务的框架去看它，会得出奇怪的结论。

不理解这一课，会遇到这些问题：

- 为什么 Pi-hole 装了之后，全家所有设备都受影响，而不只是某一台？
- 为什么 Immich 不是「装一个容器」，而是「装一组容器」？
- 为什么 Tailscale 问「数据存在哪里」这么难回答？
- 为什么这三类服务都特别需要小心隐私？
- 为什么 Home Assistant、Vaultwarden 这类服务，第一轮只需要「定位」而不必深入研究？

**这一课的目的，是让你看到 : 六问法通用，但每个服务的答案会告诉你它「是什么样的人」。**

## 3. 小白解释

### 3.1 Pi-hole：在网络门口拦广告

普通广告拦截是装在浏览器里的，只拦截这一个浏览器看到的广告。

**Pi-hole 不一样：它装在整个网络的「门口」。** 家里所有设备上网，都要经过它。它的工作方式很巧：

```text
设备要访问某个网站
    ↓
先问「这个网站的地址是多少？」（这就是 DNS，Week 4 学过）
    ↓
Pi-hole 接过这个问题
    ↓
如果是广告域名 → 回一个「查无此址」→ 广告加载失败
如果是正常域名 → 正常告诉设备地址
```

**关键点：Pi-hole 不拦截广告内容，它拦截的是「找到广告服务器的路」。** 设备压根找不到广告服务器，自然就显示不出广告。这就是为什么它一次配置，全家设备都生效。

### 3.2 Immich：把云相册搬回自己家

**Immich 让你自建一套类似商业云相册的服务**：手机自动备份照片、按时间线和地点浏览、支持人脸和内容搜索。

它的特点是：**它不是一个容器，而是一组容器协同工作。** 有负责网页界面的、有负责数据库的、有负责图片处理的。所以对它来说，Docker 不是「可选的部署方式」，而是**它正常工作的前提**。

### 3.3 Tailscale：不是服务，是通道

第五周你学过 Tailscale 的原理：它让外面的设备安全地接入家里网络，不用开放端口。

**这里要特别提醒：用「服务」的框架去看 Tailscale 会别扭。** 因为：

```text
普通服务：跑在 NAS 上，你访问它
Tailscale：装在每台设备上，它让你能访问别的设备
```

它不是一个「你去访问的东西」，而是「你用来访问的通道」。所以问它「数据存在哪里」「怎么联网访问」，答案和别的服务很不一样。

## 4. 技术解释

### 4.1 六问分析：Pi-hole

```text
① 解决什么问题：在整个家庭网络层面拦截广告和追踪域名
② 硬件需求：很轻，低功耗小机器就能跑
③ 运行在哪里：Docker 或裸机，通常需要在网络入口附近
④ 怎么联网访问：它本身是 DNS 服务；家里设备把 DNS 指向它
⑤ 数据存在哪里：查询记录、黑名单/白名单配置
⑥ Docker 的作用：打包运行环境；配置目录需要持久化
```

**技术要点**：Pi-hole 抢占的是 DNS 这一层。所以它必须离网络入口足够近，设备也必须把 DNS 指向它 —— 这两点是它生效的前提，也是它出问题时最先要检查的地方。

### 4.2 六问分析：Immich

```text
① 解决什么问题：自建的照片/视频备份与浏览，替代云相册
② 硬件需求：照片多了需要较大存储；机器学习类功能吃资源
③ 运行在哪里：Docker（它本身就是围绕容器部署设计的）
④ 怎么联网访问：局域网访问；远程访问参考 Week 5 结论
⑤ 数据存在哪里：照片原件 + 数据库 + 缩略图，三者都要备份
⑥ Docker 的作用：Immich 由多个容器组成，Docker 是它正常工作的前提
```

**技术要点**：Immich 的数据分三块 —— 原件、数据库、缩略图。**很多人只备份了原件，结果重装后发现数据库和缩略图都没了**，浏览体验大打折扣。这是第⑤问要特别小心的地方。

### 4.3 六问分析：Tailscale

```text
① 解决什么问题：让外部设备安全访问家里网络，不用开放端口
② 硬件需求：几乎可以忽略
③ 运行在哪里：每台设备装客户端，不是「一个服务跑在 NAS 上」
④ 怎么联网访问：它本身就是联网方式
⑤ 数据存在哪里：主要是密钥和登录状态，配置很少
⑥ Docker 的作用：可以容器化，但更适合直接装在需要联网的设备上
```

**技术要点**：Tailscale 的「运行在哪里」和「怎么联网访问」两问几乎是同一个答案 —— 因为**它的存在本身就是联网方式**。这也说明六问法不是死板模板：当某个服务的性质特殊时，答案自然会重叠。

### 4.4 三个服务的定位对比

| 维度 | Pi-hole | Immich | Tailscale |
|---|---|---|---|
| 作用层次 | 网络层（DNS） | 应用层 | 通道层 |
| 是否多容器 | 单容器为主 | 是，一组容器 | 通常不是容器 |
| 数据敏感度 | 查询记录 | 照片、人脸 | 密钥、拓扑 |
| Docker 角色 | 打包环境 | 工作前提 | 可选 |

**再补充两个「第一轮只需定位」的服务**：Home Assistant（智能家居中枢）在应用层、通常由容器组成；Vaultwarden（密码管理）在应用层、数据极度敏感。它们只需要知道大概在哪一层、做什么，不必立即深入研究。

## 5. 类比

把这三种服务想象成**一栋大楼里的三种角色**。

```text
Pi-hole    →  大门口的保安：决定谁能收到访客（拦掉不受欢迎的）
Immich     →  住户家的相册柜：存放私人物品，只有主人能看
Tailscale  →  一条只有住户能走的秘密通道：从外面直接进家
```

**这个类比能解释什么？**

- 它解释了**为什么 Pi-hole 影响全家**：保安在大门口，管的是整栋楼所有人的访客。
- 它解释了**为什么 Immich 由多个容器组成**：相册柜不是一件家具，而是一套系统 —— 柜子、目录、索引各司其职。
- 它解释了**为什么 Tailscale 用服务框架看会别扭**：秘密通道不是「大楼里的一个房间」，而是「怎么进大楼的一种方式」。
- 它还解释了**共同的隐私风险**：保安记着谁来过、相册柜里是私人物品、秘密通道关乎进出安全 —— **三者都在碰敏感信息。**

## 6. NAS 实际场景

### 6.1 三个真实判断

**场景一：装了 Pi-hole，结果全家断网了**

这是最常见的翻车。**因为 Pi-hole 成了全家的 DNS，它一旦出问题，所有设备的域名解析都会失败** —— 表现为「大家都上不了网」。这个案例说明：**Pi-hole 在网络层，它的故障影响范围是全网，而不是单个服务。** 上线前要留好后路（比如设备上还保留一个备用 DNS）。

**场景二：Immich 重装后照片还在，但时间线和人脸都没了**

这是第⑤问只答了一半。**照片原件在（挂载的存储里），但数据库和缩略图随容器删掉了。** 教训：Immich 的数据是三块，**三块都要备份**，缺一块体验就不完整。

**场景三：以为 Tailscale 是装在 NAS 上的一个服务**

其实不是。**Tailscale 是要装在你**每一台**需要联网的设备上的。** 只装在 NAS 上，你的手机还是进不来。理解它是「通道」而不是「服务」，才能正确使用它。

### 6.2 三个服务的隐私数据对照

| 服务 | 接触的隐私数据 | 公开笔记里不能写什么 |
|---|---|---|
| Pi-hole | 全家设备的访问域名记录 | 真实的查询日志、内网设备清单 |
| Immich | 私人照片、视频、人脸信息 | 照片内容、人脸数据、相册地址 |
| Tailscale | 登录密钥、设备网络拓扑 | 账号、密钥、设备真实地址 |

**一个共同的判断标准：这些服务记录的不只是「技术信息」，而是你的生活痕迹。** 所以哪怕是在学习笔记里，也要用示例代替真实内容。

## 7. 常见误区

### 误区一：Pi-hole 是装在浏览器里的广告拦截

不对。**Pi-hole 在网络层工作，它拦截的是 DNS 查询**，影响的是整个网络里所有设备 —— 不是某一个浏览器。这也意味着它出问题时影响的是全网。

### 误区二：Immich 的照片存在容器里，删容器就没了

不准确，但很危险。**照片原件通常挂在容器之外的存储上，不会因删容器而丢**；但数据库和缩略图如果不做持久化和备份，就会随容器一起消失。**「照片没丢」不代表「什么都没丢」。**

### 误区三：Tailscale 是一个需要专门跑在 NAS 上的服务

不对。**Tailscale 是装在你每一台设备上的客户端**，它提供的是一条通道，而不是一个「住在 NAS 里的服务」。只装在 NAS 上，其他设备照样进不来。

### 误区四：六问法对每个服务都给出一样的答案

不对。**框架一样，答案可以完全不同** —— 这正是六问法的价值。Pi-hole 和 Immich 的答案差异巨大，Tailscale 甚至连「运行在哪里」这一问都答得和别的服务不一样。

### 误区五：这些服务的日志和配置只是技术数据，公开没关系

不成立。**Pi-hole 的记录暴露你的上网习惯、设备清单；Immich 的内容是私人照片；Tailscale 的凭据直接关系网络安全。** 这些都不是「无关紧要的技术参数」，而是隐私。**公开笔记时要用示例代替真实内容。**
