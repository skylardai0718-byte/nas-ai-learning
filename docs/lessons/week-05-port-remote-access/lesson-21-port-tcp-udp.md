# 第二十一课：端口、TCP 与 UDP

> 本课的一句话结论：**IP 地址把你送到正确的设备，端口再把你送到设备上正确的服务 —— 一台设备上可以同时跑很多服务，靠端口区分。**

## 1. 今天学习什么

今天要掌握 3 个概念：

1. **端口（Port）**：标识设备上的具体服务。
2. **TCP**：可靠的传输方式，保证数据完整到达。
3. **UDP**：快速的传输方式，不保证送达。

你今天要建立的核心结构是：

```text
IP 地址      →  送到哪台设备
端口（Port） →  送到设备上的哪个服务
```

以及一个常见写法：

```text
192.168.1.10:8096
     ↑          ↑
  设备地址    服务端口
```

## 2. 为什么要学

上周你知道了 IP 地址能定位一台设备。但这里有个问题：

**一台 NAS 上同时跑着很多服务** —— 文件共享、影音服务、照片服务、管理界面。数据送到了这台设备之后，**怎么知道该交给哪个服务？**

如果没有端口，一台设备就只能提供一个服务，或者系统只能靠猜。端口解决了这个问题。

不理解端口，会遇到这些问题：

- 为什么同一个 NAS 可以同时提供好几种服务？
- `192.168.1.10:8096` 里的 8096 是什么意思？
- 为什么配置服务时总要指定一个「端口号」？
- 为什么有些服务用 TCP、有些用 UDP？
- 为什么「端口被占用」是一个常见错误？

**这也是下周所有远程访问问题的前提** —— 端口转发、防火墙规则，全都围绕端口展开。

## 3. 小白解释

### 3.1 端口：公寓楼里的房间号

上周学过：IP 地址像小区的地址，能定位到哪栋楼。

但快递送到楼下还不够 —— 还得知道**送到哪一户**。

**端口就是「房间号」。**

```text
IP 地址   →  小区地址  →  定位到哪栋楼（哪台设备）
端口      →  房间号    →  定位到楼里的哪一户（哪个服务）
```

所以完整的地址要写成这样：

```text
192.168.1.10:8096
     ↓          ↓
   哪台设备    哪个服务
```

一台 NAS 可以同时开着好几扇「门」：

```text
192.168.1.10:8096   →  影音服务
192.168.1.10:2283   →  照片服务
192.168.1.10:5000   →  管理界面
192.168.1.10:445    →  文件共享
```

**同一个 IP 地址，不同的端口，对应不同的服务。**

### 3.2 为什么端口号有范围

端口号是一个 0 到 65535 之间的数字。

其中一部分被约定给了常见服务：

```text
80    →  网页（HTTP）
443   →  加密网页（HTTPS）
22    →  远程登录（SSH）
445   →  文件共享（SMB）
```

这些「约定俗成」的端口叫**知名端口**。其他服务通常用较大的数字，比如 8096、2283 这类。

**为什么要约定？** 这样你不用记数字就能访问常见服务 —— 输入网址时浏览器会自动用 80 或 443。

### 3.3 TCP 和 UDP：两种送快递的方式

数据在网络上传输，有两种基本方式：

**TCP：可靠的**

```text
特点：保证数据完整、按顺序到达
方式：有确认机制，丢了会重传
适合：网页、文件传输、任何不能出错的情况
```

**UDP：快速的**

```text
特点：不保证送达、不保证顺序
方式：发出去就不管了，图快
适合：实时音视频、游戏、直播
```

用送快递类比：

> **TCP 像挂号信** —— 要签字确认，没送到会重发。慢一点，但不会丢。
>
> **UDP 像现场喊话** —— 喊完就算，没听清也就没了。快，但不保证对方收到。

**为什么视频通话用 UDP？** 因为实时性比完整性更重要。一帧画面丢了大不了画面闪一下，但如果为了补上这一帧而卡住等待，通话体验就毁了。

## 4. 技术解释

### 4.1 端口的作用

在网络通信中，一条连接由四个要素唯一确定：

```text
源 IP、源端口、目标 IP、目标端口
```

这说明端口的作用是**在设备内部区分不同的服务或连接**。

操作系统维护一张表，把「哪个端口对应哪个程序」记录下来。当数据到达某个端口时，系统就知道该交给哪个程序处理。

**这就是为什么同一个 NAS 能同时提供多种服务** —— 每种服务监听不同的端口。

### 4.2 端口的分类

| 范围 | 名称 | 说明 |
|---|---|---|
| 0–1023 | 知名端口 | 预留给常见服务，需要特权才能监听 |
| 1024–49151 | 注册端口 | 常见应用使用 |
| 49152–65535 | 动态端口 | 临时分配给客户端连接 |

**普通服务通常用 1024 以上的端口** —— 这也是为什么自托管服务的端口看起来都是 8096、8989 这类较大的数字。

### 4.3 端口占用

如果两个程序试图监听同一个端口，第二个会失败 —— 这叫**端口被占用**。

这是配置服务时的常见错误。出现时通常有两个原因：

- 另一个服务已经在用这个端口。
- 之前的实例没有正常退出，还占着这个端口。

**解决办法**：换一个端口，或者找到并停掉占用该端口的程序。

### 4.4 TCP 的特点

- **面向连接**：通信前先建立连接（三次握手）。
- **可靠**：有确认和重传机制，保证数据完整、按序到达。
- **有流量控制**：根据对方处理能力调整发送速度。
- **代价**：建立连接和确认机制带来额外开销，速度相对较慢。

**典型用途**：网页浏览、文件传输、远程登录、数据库 —— 任何不能容忍数据出错或丢失的场景。

### 4.5 UDP 的特点

- **无连接**：直接发送，不预先建立连接。
- **不保证可靠**：不确认、不重传。
- **开销小、延迟低**。
- **需要应用层自己处理**：如果应用需要可靠性，得自己在上面实现。

**典型用途**：视频通话、直播、在线游戏、DNS 查询。

**注意 DNS 用 UDP**：因为一次查询只需要一问一答，数据量很小，为它建立连接的代价不划算。这也是为什么 DNS 查询很快。

## 5. 类比

把网络通信想象成**寄东西到一个大型办公楼**：

- **IP 地址是大楼的地址**：能定位到这栋楼，但楼里有很多家公司。
- **端口是房间号**：告诉快递员送到哪一间。301 是设计部，502 是财务部，8096 是影音服务。
- **TCP 是挂号信**：需要签收，对方没收到会重发。适合寄合同、发票这类不能丢的东西。
- **UDP 是普通平信或喊话**：投出去就不管了。适合寄广告单 —— 丢一张无所谓，重要的是快。

**关键洞察**：同一栋楼（同一个 IP）可以有不同的房间（不同的端口），各家公司互不干扰。这就是一台 NAS 能同时提供影音、照片、文件共享等多种服务的原因。

## 6. NAS 实际场景

### 6.1 一台 NAS 上的多种服务

```text
192.168.1.10:8096   →  Jellyfin 影音服务
192.168.1.10:2283   →  Immich 照片服务
192.168.1.10:5000   →  NAS 管理界面
192.168.1.10:445    →  文件共享

同一个 IP，四个不同的端口，四扇不同的门。
```

**在浏览器里访问服务时，格式就是 `设备地址:端口`。** 如果省略端口，浏览器会默认用 80 或 443。

### 6.2 三个真实判断

**场景一：为什么访问某个服务必须加端口号**

因为该服务不在默认端口上。浏览器默认去找 80 或 443，如果你的服务跑在 8096，就必须明确告诉它。

```text
✗  192.168.1.10        →  浏览器去找 80 端口，找不到
✓  192.168.1.10:8096   →  明确指向影音服务
```

**场景二：配置服务时报「端口已被占用」**

说明这个端口已经被别的程序用了。排查方向：

- 是不是这个服务重复启动了两次？
- 是不是另一个服务占用了同一个端口？
- 是不是上次的进程没退出干净？

处理方式：给新服务换一个端口，或者找到并停掉占用者。

**场景三：为什么有些服务「连不上」，有些「能连但慢」**

如果端口根本没开（服务没运行、或防火墙挡住），表现为连不上。如果端口开着但带宽或性能不足，表现为能连但慢。

**这两个症状指向不同的问题**，排查方向也不同。

### 6.3 端口号是服务的「门牌」

一个实用的理解方式：

```text
IP 地址  =  设备在网络中的地址（相对固定的）
端口     =  服务在这台设备上的门牌号（可以自己安排）
```

所以配置服务时，你经常需要指定「用哪个端口」—— 就是在给这个服务分配一个门牌号。

**如果两个服务想要同一个门牌号，就会冲突。**

## 7. 常见误区

### 误区一：端口用于定位设备

反了。**IP 地址定位设备，端口定位服务。** 这是本课最基础的一条区分，混淆之后，后面学端口转发时会完全混乱。

### 误区二：一台设备只能提供一个服务

不对。一台设备可以同时监听很多端口，每个端口对应一个服务。这正是 NAS 能同时做文件共享、影音播放、照片管理的原理。

### 误区三：UDP 比 TCP 更可靠

不是。UDP 恰恰是**不保证可靠**的那种 —— 它不确认、不重传，图的是快。需要可靠性时应该用 TCP。两者的选择取决于场景需要「完整」还是「快速」。

### 误区四：端口号是固定的，不能改

多数服务可以配置成监听任意端口。约定俗成的端口（如 80、443）只是**默认值**。你可以把服务配置到别的端口上 —— 但改完之后访问时也要相应带上新端口。

### 误区五：端口开着就说明服务正常

端口开着只能说明有程序在监听。它是否真正工作正常、能否返回正确内容，是另一回事。排查时要分开判断「端口通不通」和「服务对不对」。

## 8. 知识地图

本周开始，网络内容从「能不能通」进入「怎么安全地通」。

```text
网络

│   ├── LAN / WAN
│   └── Switch / Router
├── 地址                    （Week 4 Day 3）
│   ├── Private IP / Public IP
│   └── 服务                 （Week 4 Day 4）DHCP / DNS
└── 通信细节                ← 本周在这里
    ├── Port 端口             （IP 定位设备，端口定位服务）  ← 今天
    ├── TCP / UDP            （可靠 vs 快速）              ← 今天
    ├── NAT                  （Day 2：多设备共用一个公网地址）
    ├── Port Forwarding      （Day 2：让外部能进来）
    ├── DDNS / Firewall      （Day 3：地址会变 / 谁能进入）
    └── VPN / Tailscale      （Day 4：建立私有通道）
```

本课与其他课的连接：

```text

     ↓

     ↓

     ↓

```

今天只需要真正记住一句话：

> **IP 地址负责找到设备，端口负责找到设备上的服务** —— 一台 NAS 用不同的端口同时提供多种服务；而 TCP 和 UDP 的区别，就是「保证送到」和「尽快发出」的取舍。
