# 第二十三课：DDNS 与防火墙

> 本课的一句话结论：**DDNS 解决「地址会变，你怎么找到我」，防火墙解决「找到了，让不让你进」—— 一个管「找得到」，一个管「进得来」。**

## 1. 今天学习什么

今天要掌握 2 个概念：

1. **DDNS（动态域名解析）**：用一个固定域名指向会变化的公网地址。
2. **防火墙（Firewall）**：决定哪些连接可以通行、哪些被拒绝。

你今天要建立的核心区分：

```text
DDNS    →  解决「地址会变」的问题   →  让你「找得到」
Firewall →  解决「谁能进入」的问题   →  决定「进得来」
```

**这两个问题最容易混淆，也是本课的核心。**

## 2. 为什么要学

昨天你学了端口转发，知道它可以开一个口子让外部进来。但实际使用时会遇到两个额外的麻烦：

**麻烦一：公网地址会变。** 家用的公网地址往往不是固定的，会随时间变化。地址一变，你原来记的地址就失效了。

**麻烦二：开了口子之后，怎么控制谁能进。** 端口转发默认对所有人开放 —— 有没有办法决定放谁进来？

这两个麻烦对应今天两个概念：

```text
地址会变  →  DDNS
控制进入  →  Firewall
```

不理解它们的区别，会遇到这些问题：

- 为什么我的公网地址过一段时间就变了？
- DDNS 配好之后，是不是外面就能访问我家了？
- 「能找到」和「能进入」有什么区别？
- 防火墙会不会挡住我自己访问？
- 只做 DDNS 不做别的，安全吗？

**一个关键认知：DDNS 只是让你更容易找到目标，它不提供任何安全保护。**

## 3. 小白解释

### 3.1 DDNS：一个永久的门牌

**问题**：家里的公网地址会变。

你可能遇到过这种情况：记下了家里的公网地址，过几天发现连不上了 —— 因为运营商重新分配了一个新地址。

**DDNS 解决的就是这个问题：用一个固定不变的域名，指向那个会变的地址。**

用类比：

> 假设你经常搬家，但希望朋友能一直联系到你。
>
> **做法一**：每次搬家都给所有朋友发新地址 —— 麻烦，而且总有人不知道。
>
> **做法二**：保留一个永久的邮箱或转寄地址。朋友永远往那个地址寄信，你在后台更新实际住址。**这就是 DDNS。**

它的工作原理很简单：

```text
程序检测到公网地址变化
↓
自动更新域名解析记录
↓
域名始终指向当前地址
```

**关键点：DDNS 只解决「找到」，不解决「进入」。**

域名解析成功，只说明「你的请求找到了正确的目标地址」。至于最终能不能访问到服务，取决于端口转发、防火墙、以及服务本身。

### 3.2 防火墙：门口的守卫

**防火墙决定哪些连接可以通行。**

如果说 NAT 是「默认关着大门」，端口转发是「给某个房间常开门」，那防火墙就是**站在门口检查的人**：

```text
允许的  →  放行
不允许的 →  拒绝
```

**DDNS 和防火墙的分工：**

```text
DDNS    →  让外部「找到你家」        （找到）
Firewall →  决定「让不让进」          （进入）
```

**这就是本课最重要的区分。** 举个具体例子：

| 配置 | 结果 |
|---|---|
| 只做 DDNS | 外部能找到你家地址，但进不来（NAT 挡着） |
| DDNS + 端口转发 | 外部能找到，也能进来 |
| DDNS + 端口转发 + 防火墙限制 | 外部能找到，只有符合规则的能进来 |

**注意第一行**：只做 DDNS 而不做端口转发，外部依然访问不到 —— 因为「找到」不等于「进入」。

### 3.3 为什么很多人以为 DDNS 就够安全了

这是一个常见的误解。有人觉得：

> “我用了 DDNS，用一个别人猜不到的域名，这样就安全了。”

**这个想法的问题在于：** DDNS 域名的作用是**方便你访问**，不是**隐藏你的服务**。域名是可以被查到的，而且攻击者通常根本不通过域名 —— 他们直接扫描 IP 地址范围，看哪些端口开着。

**「用了一个奇怪的域名」属于隐蔽，不属于防护。**

## 4. 技术解释

### 4.1 DDNS 的工作机制

DDNS 需要两部分配合：

**客户端**：运行在家里的设备上（通常是路由器或 NAS），定期检测当前公网地址，发现变化就通知服务商更新。

**服务商**：维护域名解析记录，收到更新请求后修改记录。

流程：

```text
1. 客户端定期查询：「我现在的公网地址是什么？」
2. 与上次记录对比
3. 如果变了，向 DDNS 服务商发送更新请求
4. 服务商更新域名解析记录
5. 之后外部通过域名访问，解析到新地址
```

**注意**：DDNS 依赖的服务商能正常工作。如果更新失败，域名就会指向一个失效的旧地址。

### 4.2 为什么家用地址会变

住宅宽带的公网地址通常是**动态分配**的：

- 运营商从地址池中分配，不保证长期固定。
- 路由器重启、线路中断、租约到期都可能触发变化。
- 有些运营商甚至不提供独立的公网地址（这会给远程访问带来额外限制，属于进阶话题）。

**如果你确实需要一个固定的公网地址**，有些运营商提供「固定 IP」作为付费增值服务。但对大多数家用场景，DDNS 已经足够。

### 4.3 防火墙的作用

防火墙根据规则决定数据包是否放行。规则的判断依据通常包括：

- **来源地址**：来自哪里。
- **目标端口**：访问哪个服务。
- **协议**：TCP 还是 UDP。
- **连接状态**：是主动发起还是回应。

**家用路由器的默认策略通常是：**

```text
内部出去    →  允许（不用问）
外部进来    →  默认拒绝
已有连接的回应 →  允许（所以你能正常上网）
```

**这个默认策略解释了为什么你能正常上网，但外部访问不进来** —— 因为「出去」被允许，「进来」被拒绝。

### 4.4 防火墙与端口转发的关系

两者配合工作：

```text
端口转发  →  建立「外部端口 → 内部设备」的映射关系
防火墙    →  决定这个映射对应的连接是否放行
```

**实际中的表现**：如果防火墙拒绝了某个端口，即使端口转发规则存在，外部也连接不上。

有些路由器把这两个功能合并在一个界面里，有些则分开配置。理解它们的分工，在排查时就不会混淆。

### 4.5 家用的典型安全策略

```text
1. 默认不对外开放任何端口          → NAT 已经做到
2. 确实需要暴露的服务，才做端口转发
3. 配合防火墙限制来源（如果条件允许）
4. 更优选择：用 VPN，根本不暴露端口
```

**第 4 条是 Day 4 的内容，也是本周的核心建议。**

## 5. 类比

用**寄信和门禁**来理解这两个概念的配合：

**DDNS 是「随时更新的通讯录」：**

```text
你经常搬家
朋友们记不住你的新地址
→ 你给大家一个永久邮箱：me@example.com
→ 你在后台更新实际住址
→ 朋友只管往邮箱寄信                    ✓ 找得到
```

**但找到了邮箱，不等于能进你家门：**

```text
朋友按地址来到你家楼下
→ 楼下有门禁

门禁的规则（防火墙）：
  ✓ 允许的来访者 → 放行
  ✗ 其他人      → 拒绝
```

**所以完整的链条是：**

```text
DDNS      →  知道你家在哪      （找到）
NAT       →  默认大门是关的     （默认屏障）
端口转发   →  给某个房间开个口   （开洞）
防火墙     →  决定谁的口子能过   （把关）
```

**最常见的混淆是把第三步和第四步搞混**：开了口子（端口转发）不等于控制住了谁能进（防火墙）—— 端口转发默认是「开给所有人」的。

## 6. NAS 实际场景

### 6.1 四种配置的对比

```text
配置 A：只有公网地址，没有 DDNS，没有端口转发
  →  地址会变，外部也进不来

配置 B：DDNS，没有端口转发
  →  随时能找到你家地址，但进不来（NAT 挡着）
  →  「找到」不等于「进入」

配置 C：DDNS + 端口转发
  →  外部能访问，但该端口对全世界开放
  →  安全性取决于服务自身

配置 D：Tailscale / VPN
  →  不需要 DDNS，不需要端口转发
  →  只有你自己的设备能进
```

**这四行是本周内容的一个浓缩。** 注意 B 和 C 的差别 —— 它们清楚地展示了「找到」和「进入」是两件独立的事。

### 6.2 三个真实判断

**场景一：配置了 DDNS，但外部还是访问不了**

这是**正常现象**，不是配置失败。因为 DDNS 只解决「找到地址」，不解决「让数据进来」。

需要继续检查：

- 有没有配置端口转发？
- 防火墙有没有放行？
- 服务本身是否在正常运行？

**这个排查顺序很重要**：先确认「找得到」（域名解析正确），再确认「进得来」（转发和防火墙），最后确认「服务正常」。

**场景二：为什么说「换个隐蔽的域名」不安全**

因为攻击者通常不通过域名来找目标。他们扫描的是 **IP 地址范围**，检查哪些地址的哪些端口是开放的。你的域名是否好猜，对这类扫描完全没有影响。

而且域名本身是可查的 —— 通过证书信息、DNS 记录等方式都能关联出来。

**结论：隐蔽不能替代防护。** 依赖「别人不知道」的安全策略，一旦被发现就彻底失效。

**场景三：防火墙会不会挡住我自己访问 NAS**

在**内网**访问时不会 —— 因为你的请求不出门，不经过外部防火墙的入站规则。

只有从**外网**访问时才受这些规则影响。所以出现「在家能访问、外面不行」时，防火墙配置是众多可能原因之一。

### 6.3 一个判断顺序

遇到「外面访问不了」时，按这个顺序检查：

```text
1. 域名能解析吗？        →  DDNS 是否正常工作
2. 解析出的地址对吗？     →  DDNS 是否更新及时
3. 端口转发配了吗？       →  「进入」的通道是否存在
4. 防火墙放行了吗？       →  规则是否挡住了
5. 服务在运行吗？        →  最后一环
```

**第 1、2 步解决「找到」，第 3、4 步解决「进入」，第 5 步是服务本身。** 分层排查，不会乱。

## 7. 常见误区

### 误区一：配了 DDNS 就能从外面访问了

不能。DDNS 只解决「地址会变」的问题，让你能稳定地找到目标。要真正访问到服务，还需要端口转发、防火墙放行，以及服务正常运行。

### 误区二：DDNS 比端口转发更安全

两者解决的是完全不同的问题。DDNS 是**可发现性**工具，它甚至让访问变得更容易被定位。**安全性来自防火墙规则、认证机制和网络架构，不是来自 DDNS。**

### 误区三：用一个难猜的域名就安全了

这是「隐蔽式安全」的典型误区。攻击者通常直接扫描 IP 地址和端口，不依赖域名。而且域名信息本身是可以被查询到的。**隐蔽不能替代防护。**

### 误区四：防火墙会阻止我正常上网

不会。家用防火墙的默认策略是「内部出去允许，外部进来默认拒绝」。你正常的网页浏览、视频播放都是「内部主动出去」，不受影响。

### 误区五：DDNS 和防火墙是同一个功能

完全不同。DDNS 管「找到」，防火墙管「进入」。在路由器界面上它们可能在不同的设置页面里，排查时要分清。
