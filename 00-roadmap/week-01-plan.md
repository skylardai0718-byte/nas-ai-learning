## Day 1：NAS 本质上为什么是一台计算机？

**新概念：** Computer、Hardware、Operating System、Application、NAS

**总时长：** 55 分钟

### 今日目标

- 不再把 NAS 理解成“带网口的硬盘盒”。
- 分清一台计算机的三个主要层次。
- 知道 NAS、手机和笔记本的外形与用途虽不同，底层都有完整的计算机结构。

### 学习（25 分钟）

1. 对比笔记本、手机和 NAS：外形不同、用途不同，但都有硬件、操作系统和应用。
2. 用数字图书馆或餐厅类比三个层次。
3. 阅读准确解释，理解每一层负责什么。
4. 拆解一台运行 Jellyfin 的 NAS：

   ```text
   Jellyfin                     Application
        ↓
   NAS OS / Linux               Operating System
        ↓
   CPU / RAM / Disk / Network   Hardware
   ```

- 回答：操作系统和应用为什么不是同一种东西？

复述必须包含每层的职责、层与层怎样配合，以及至少一个 NAS 实例。

## Day 2：一台 NAS 的四个硬件角色

**新概念：** CPU、RAM、Storage、Network

**总时长：** 55 分钟

### 今日目标

- 用“做事、临时工作区、长期保存、对外连接”区分四类硬件。
- 不再混淆 RAM 和硬盘。
- 初步理解 NAS 性能问题不一定都由 CPU 引起。

### 学习（25 分钟）

先用书桌类比建立直觉：

- CPU：正在处理任务的人。
- RAM：摊开资料的桌面。
- Storage：长期保存资料的文件柜。
- Network：办公室与外界连接的道路。

再拆解“手机上传照片到 NAS”：Network 接收数据，CPU 处理任务，RAM 暂存正在使用的数据，Storage 长期保存文件。

最后明确边界：RAM 不是长期仓库；存储容量大不等于处理能力强；Network 影响数据能否以及多快进出 NAS。

### 复述（12 分钟）

- 用自己的类比解释四者，然后不用类比再准确解释一次。
- 回答：为什么 16GB RAM 不能替代 16TB 硬盘？
- 把四者补进计算机知识地图。

### 测试（13 分钟，不给答案）

1. 将“计算、临时放置、长期保存、传输”与四个部件匹配。
2. 判断：断电后，RAM 中的数据通常仍会长期保留。
3. 照片保存成功且重启后仍能找到，它主要保存在哪里？
4. 生成大量照片缩略图很慢，哪个部件的工作关系最直接？还可能受谁影响？
5. CPU 和 RAM 如何配合？为什么不能互相替代？

## Day 3：一次 NAS 操作是怎样流动的？

**新概念：** Data、Task、Data Flow、Bottleneck

**总时长：** 55 分钟

### 今日目标

- 从背部件名称，进步到理解部件怎样协作。
- 能画出一个简单 NAS 操作的数据流。
- 知道性能取决于完整链路，不只取决于一个部件。

### 学习（25 分钟）

先区分：上传照片是一个 **Task（任务）**，照片文件是被处理的 **Data（数据）**。

再追踪照片备份：

```text
手机发出任务
↓
Network 接收数据
↓
Application 理解用户请求
↓
Operating System 调用硬件
↓
CPU 处理 + RAM 暂存
↓
Storage 长期保存
```

然后反向追踪 Jellyfin 视频从磁盘读取、经过处理、通过网络到达电视的过程。

最后建立瓶颈直觉：数据流像一条送水管道，实际表现可能受最慢的一段限制。本周不学习测速单位和复杂性能指标。

### 复述（10 分钟）

- 闭卷画出照片上传和视频播放两张数据流图。
- 用一句话解释：为什么“NAS 很慢”不是一个足够准确的问题？

### 测试（15 分钟，不给答案）

1. 将网络接收、应用理解请求、系统调用资源、写入存储等步骤排序。
2. “上传照片”中，什么是任务，什么是数据？
3. 判断：NAS 运行慢时，一定是 CPU 不够强。
4. CPU 和硬盘都有余力，但传输一直受限，瓶颈可能在哪里？
5. 读取视频正常，但电视收不到数据，应优先检查数据流的哪一段？

### 今日产出（5 分钟）

- 两张数据流图：照片上传、视频播放。
- 把“NAS 很慢”改写成一个更容易定位的故障描述。
- 在学习日志中记录一个仍然模糊的环节。

## Day 4：NAS、移动硬盘与云存储有什么不同？

**新概念：** NAS、DAS、Cloud Storage

**总时长：** 55 分钟

### 今日目标

- 按连接方式和数据所在位置区分三者。
- 理解 NAS 的关键不只是容量大，而是通过网络提供存储。
- 能针对实际需求选择更合适的方案。

### 学习（25 分钟）

- **DAS**：通过 USB 等方式直接连接一台设备。
- **NAS**：接入网络，由网络中的设备访问。
- **Cloud Storage**：数据保存在服务商管理的远程系统中，通常通过互联网访问。

只比较四个维度：连接方式、多设备共享、硬件由谁管理、对互联网的依赖。

用三个场景练习选择：给一台电脑扩容、全家共享照片、出门后跨地区访问文件。

### 复述（12 分钟）

- 用 2 分钟向普通用户解释三者的区别。
- 回答：为什么“NAS 就是一块能联网的硬盘”只说对了一部分？
- 给“单电脑扩容”和“全家照片共享”分别选方案并说明理由。

### 测试（13 分钟，不给答案）

1. 只给一台笔记本增加离线容量，哪种方案最直接？
2. 判断：移动硬盘通过 USB 连接电脑时，可以视为一种 DAS。
3. 判断：使用云存储意味着用户自己维护存储服务器硬件。
4. 三位家庭成员要从不同设备访问同一照片库，应优先考虑哪类方案？
5. NAS 比外置硬盘多出的“计算机能力”是什么？

## Day 5：NAS、Server、Self-hosting 与 Homelab

**新概念：** Server、Service、Self-hosting、Homelab

**总时长：** 55 分钟

### 今日目标

- 理解 Server 首先是一种角色，不只是一类昂贵硬件。
- 知道 NAS 可以同时提供多个 Service。
- 分清 Self-hosting 是一种运行与管理方式，Homelab 是学习和实践环境。

### 学习（20 分钟）

- 当一台计算机持续向其他设备提供资源或功能时，它就在扮演 Server 角色。
- 文件共享、Jellyfin 媒体服务和 Immich 照片服务都是 Service。
- 在自己控制的设备上运行和维护服务，是 Self-hosting。
- 用于学习、实验和运行个人服务的小型环境，是 Homelab；一台 NAS 或迷你电脑就可以起步。

```text
Physical Computer / NAS
↓ 运行
Operating System
↓ 承载
Services
↓ 提供给
Other Devices / Users

自己管理这些服务 = Self-hosting
用于学习和实验的整体环境 = Homelab
```

### 复述（12 分钟）

做一段 2–3 分钟口头讲解，回答：

- NAS 为什么是计算机？
- NAS 什么时候扮演 Server？
- Jellyfin 属于什么？
- Self-hosting 描述的是什么？
- Homelab 为什么不等于“昂贵机房”？

### 周测（13 分钟，不给答案）

1. 判断：Server 只指专门生产的大型服务器硬件。
2. 在“NAS 上运行 Jellyfin”中，指出设备、服务器角色和服务。
3. 判断：应用运行在第三方云端，也属于用户自己的 Self-hosting。
4. 判断：搭建 Homelab 必须购买机架和企业级设备。
5. 一台旧电脑持续向手机提供照片服务，它是否在扮演 Server？
6. 用不超过 150 字说明 NAS、Server、Service、Self-hosting 和 Homelab 的关系。
